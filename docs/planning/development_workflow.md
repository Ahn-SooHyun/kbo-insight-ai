## 1. 전체 흐름과 단계 경계

```text
설계·개발 기반
      ↓
자동 수집·표준화·입력/정답·시간 분할
      ↓
핵심 모델의 기준 비교·개선·보정
      ↓
시즌/포스트시즌·보조 기능 연결
      ↓
설정 확정·최종 평가·설명 종합
      ↓
재실행·운영 안내·최종 인수
```

여섯 단계는 아래 12개 세부 작업으로 수행한다. 실제 착수는 배정 범위와 선행 증거를 따르며, 계획의 존재가 실행·승인을 뜻하지 않는다.

<a id="dependencies"></a>

### 1.1 작업 의존성

| 작업                        | 시작에 필요한 선행 결과                    | 넘기는 곳           |
| --------------------------- | ------------------------------------------ | ------------------- |
| [1 기준 설계](#task-1)      | 확정 범위·기존 자료·실제 대상 확인         | 2, 3 이후 계약 기준 |
| [2 개발 기반](#task-2)      | 1의 기준과 저장/설정 책임                  | 3~12의 실행 기반    |
| [3 소규모 확인](#task-3)    | 1·2, 출처 후보와 이용 조건                 | 4·5                 |
| [4 전체 확보](#task-4)      | 3의 자동 경로·대상 범위                    | 5                   |
| [5 표준화·품질](#task-5)    | 4의 원본·수집 이력                         | 6                   |
| [6 입력·정답·분할](#task-6) | 5의 품질·완료·조건부 근거                  | 7·9                 |
| [7 M1](#task-7)             | 6의 경기 자료·분할·정답                    | 8·9·10              |
| [8 시즌 전망](#task-8)      | 검증된 7, 일정·현재 성적·시즌 규칙         | 10·11               |
| [9 M2·M4·M3·M5](#task-9)    | 6의 해당 자료, 7부터 시작하는 기본 순서    | 10·11               |
| [10 보조·통합](#task-10)    | 필요한 핵심 모델·8의 시즌 전망·조건부 판정 | 11                  |
| [11 최종 검증](#task-11)    | 7~10의 대상 기능·선택 완료·고정 자산       | 12                  |
| [12 재실행·문서](#task-12)  | 적용된 기반·결과·11의 증거                 | 최종 사용자 인수    |

**부분 통합:** 개별 보조 기능은 필요한 모델이 준비된 범위에서 확인한다. 작업 10 전체 완료는 합의된 대상 기능의 연결을 모두 대조해야 한다. M1 후 시즌 전망의 조기 연결은 다음 예외 규칙을 따른다.

### 1.2 개발 순서의 예외와 반복

- M1이 검증되고 시즌 규칙·일정 입력이 확보되면 다른 모델 전체 완성을 기다리지 않고 시뮬레이션을 연결할 수 있다.
- 확률 보정·설명·오류 분석은 각 모델 개발 중 반복한다. 종합 검증 단계까지 미루지 않는다.
- 새 라인업·보조 입력으로 M1을 개선하면 같은 분할·지표로 다시 비교하고 관련 시뮬레이션·보고서를 갱신한다.
- 최종 Test는 이 반복 개선에 사용하지 않는다. [평가 계약](../standards/project_contract.md#evaluation)을 먼저 고정한다.

### 1.3 공통 기준의 관리 위치

| 기준                     | 상세 원문                                                       | 이 문서의 역할                    |
| ------------------------ | --------------------------------------------------------------- | --------------------------------- |
| 범위·시점·정답·누수 방지 | [예측·평가 계약](../standards/project_contract.md#information)  | 각 작업에서 확인할 입력·증거 연결 |
| 지표·기준 모델·Test      | [평가 기준](../standards/project_contract.md#evaluation)        | 개발·선택·최종 평가 순서 관리     |
| 원본·버전·경로·Secret    | [재현성 기준](../standards/project_contract.md#reproducibility) | 구현과 인수 책임 연결             |

상세 정의를 작업별로 복제하지 않는다. 규칙 변경 시 계약을 먼저 갱신하고 이 문서의 인수 조건·README 요약을 함께 대조한다.

<a id="status"></a>

### 1.4 현재 확인 범위

이 표는 이 문서 개정에 인수된 증거의 범위다. 실제 저장소 전체의 진행률이나 작업 승인 상태를 추정한 표가 아니다.

| 대상                  | 확인 수준             | 완료로 인정할 다음 증거             |
| --------------------- | --------------------- | ----------------------------------- |
| 문서 3개의 기준·연결  | 문서 개정본 제공      | 실제 적용 파일·기존 변경·연결 대조  |
| 환경·패키징·기본 실행 | 실행 증거 미인수      | 작업 2의 설치·import·설정·경로 결과 |
| 수집·가공·정답·분할   | 실제 자료 검증 미인수 | 작업 3~6의 원본·품질·완료·분할      |
| 학습·보정·예측        | 실행·성능 근거 미인수 | 작업 7·9의 동일 조건 비교           |
| 시즌·보조·최종 평가   | 계산·평가 근거 미인수 | 작업 8·10·11의 결과·한계            |
| 사용자 실행 안내      | 검증된 명령 미인수    | 작업 12의 재실행과 README 안내      |

새 근거를 인수하면 대상·확인일·버전·실행 결과를 함께 기록한다. 문서 작성이나 파일 존재만으로 실행 상태를 바꾸지 않는다.

## 2. 설계·개발 기반 준비

<a id="task-1"></a>

### 세부 작업 1 — 예측·평가 기준 고정

**목적:** 수집 담당과 모델 담당이 같은 기능·시점·정답을 사용하게 한다.

| 구분         | 내용                                                                                                                              |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 입력         | 확정 기능 범위·기존 문서·사용 가능한 자료·실제 적용 위치                                                                          |
| 작업         | 동등 문서를 확인하고 [예측·평가 계약](../standards/project_contract.md)에 표본·입출력·기간·누수 방지·지표·기준 모델·미확정을 정리 |
| 산출물       | 단일 상세 계약, 문서 연결, 미확정 목록, 기준 대조 결과                                                                            |
| 완료 증거    | 기능별 시점·입력·출력·정답을 설명할 수 있고 미확정마다 책임·시점·확인 방법·사용 제한이 있음                                       |
| 실패 시 처리 | 실제 적용 위치·원본 가용성 미확인은 분리 기록. 원본 필드·기간·성능을 임의 확정하지 않음                                           |

상세 대조 항목은 [계약 검증표](../standards/project_contract.md#checks)를 사용한다.

<a id="task-2"></a>

### 세부 작업 2 — 최소 개발 기반

**목적:** 사업 기능을 선행 구현하지 않고 실제 설치·기본 실행·설정·경로를 검증한다.

| 구분         | 내용                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------- |
| 입력         | 실제 저장소·OS·설치 도구·기존 구조·계약의 저장/설정 책임                                  |
| 작업         | Python·환경/패키지 관리·최소 의존성을 근거로 선정·고정, 최소 패키징·진입점·설정·로그 구성 |
| 산출물       | 재현 가능한 환경 정의, 기본 확인 진입점, 경로·설정 안내, 의미 있는 최소 검증              |
| 완료 증거    | 실제 설치·import·기본 실행·설정 오류·경로 처리 결과와 실행 위치가 기록됨                  |
| 실패 시 처리 | 실행할 수 없는 기반을 완료 처리하지 않음. 실패 명령·환경·오류·보완·재검증 결과 기록       |

**확인할 경계**

- 프로젝트 기준 경로와 원본·중간·처리 자료·모델·결과·캐시의 책임을 구분한다. 정확한 물리 경로는 이 단계에서 정한다.
- 공백·한글 경로, 실행 위치, 대소문자 차이로 자료 위치가 달라지지 않게 확인한다.
- 도움말·기본 확인·import는 수집·학습·모델 로딩·대량 파일 생성을 일으키지 않는다.
- 실제 Secret은 추적·출력하지 않는다. 환경 파일 허용 범위는 계약의 [저장·설정 경계](../standards/project_contract.md#reproducibility)를 따른다.
- DB·Docker·CI/CD·GPU·서비스를 선제 도입하거나 미구현 수집/학습 명령을 성공처럼 반환하지 않는다.

## 3. 자동 수집·데이터 구축

<a id="task-3"></a>

### 세부 작업 3 — 소규모 확인과 조건부 판정

**목적:** 자료가 있다는 주장과 자동 처리 가능한 근거를 구분한다.

| 구분         | 내용                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------- |
| 입력         | 계약의 [확정 대기 목록](../standards/project_contract.md#decisions), 출처 후보·이용 조건 |
| 작업         | 소량 원본으로 필드·타입·식별자·순서·라인업·엔트리·교체·일정·경기 상태 연결 확인          |
| 산출물       | 원본 표본, 자동 확보 근거, 필드 의미 대응, 조건부 세부 항목의 잠정 판정                  |
| 완료 증거    | 실제 자동 확보 경로와 핵심 이벤트 대응을 설명할 수 있음                                  |
| 실패 시 처리 | 확보 실패·식별 불가·의미 불명을 구분. 수동 입력으로 통과시키지 않음                      |

**소규모에서 확인할 사례**

| 사례             | 확인할 질문                                               |
| ---------------- | --------------------------------------------------------- |
| 타석 중 교체     | 시작 참가자와 최종 결과 귀속을 구분할 수 있는가           |
| 주루로 이닝 종료 | 타석·투구와 별도 사건의 순서·아웃 변화를 연결할 수 있는가 |
| 무투구 타석      | 실제 투구 없이 끝난 결과를 투구 표본에서 분리할 수 있는가 |
| 라인업·일정      | 사건 날짜뿐 아니라 공개/수집 시각 근거가 있는가           |
| 좌표             | 단위·축·원점·결측·유도값의 의미를 확인할 수 있는가        |

대타·대주자·수비 교체, 도루·도루실패·견제사, 관측 번트 세부 항목은 각각 판정한다. 이 단계의 확인은 전체 자료 품질 통과가 아니며 작업 5에서 재검증한다.

<a id="task-4"></a>

### 세부 작업 4 — 전체 확보와 원본 보존

**목적:** 포함·누락·정정 상태를 설명할 수 있는 원본을 확보한다.

| 구분         | 내용                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------- |
| 입력         | 확인된 자동 경로·대상 범위·요청 조건·잠정 식별 규칙                                            |
| 작업         | 선정 기간의 경기·타석·투구·일정·라인업·엔트리·포스트시즌 자료 확보, 중복 방지·재개·제한 재시도 |
| 산출물       | 원본 버전, 수집 이력, 기간/시즌별 포함·누락·실패 목록                                          |
| 완료 증거    | 같은 원본을 식별·재독할 수 있고 대상 목록과 실제 수집 현황을 대조할 수 있음                    |
| 실패 시 처리 | 빈 응답·접근 실패·미편성·미완료·누락을 분리. 원본을 덮어써 실패 흔적을 지우지 않음             |

현재부터 확보하는 라인업·일정은 시각별 원본을 보존한다. 과거 자료의 현재 응답은 당시 공개 상태의 근거가 아니다. 시즌 종료 여부와 전체 자료 확보 여부를 별도 확인한다.

<a id="task-5"></a>

### 세부 작업 5 — 표준화·품질·집계 대조

**목적:** 원본에서 사용 자료로 가는 변환을 추적하고 중복·누락·잘못된 집계를 막는다.

| 구분         | 내용                                                                            |
| ------------ | ------------------------------------------------------------------------------- |
| 입력         | 원본·수집 이력·이벤트 의미·대상 경기/선수 목록                                  |
| 작업         | 경기·타석·투구·선수 경기 기록·교체·등록·일정 정리, 식별자·순서 연결, 품질 검사  |
| 산출물       | 표준 자료, 항목 설명, 품질 보고, 수정/제외 이력, 조건부 최종 자료 판정          |
| 완료 증거    | 원본·공식 집계와 결과를 대조할 수 있고 제외 사유·영향 범위가 남음               |
| 실패 시 처리 | 손상·불완전·불가능 값은 명시적으로 격리/제외/보완 변환. 원본을 직접 고치지 않음 |

**필수 품질 점검**

- 필드 타입·Null·중복·범위·날짜·식별자·이벤트 순서
- 투구마다 반복되는 타석 결과의 중복 집계 방지
- 실제 투구와 무투구 결과, 타석 전/후와 투구 전/후 상태 구분
- 경기 종료 상태·최종 점수·타자 기록·투수 사용량의 집계 일관성
- 정정·재수집이 중간/처리 결과에 반영되는 경로
- 조건부 항목별 전체 누락·오분류와 포함/제한/제외 근거

품질선은 자료와 사용 목적에 근거해 정한다. 소규모에서 확인한 사례만으로 전체 품질을 주장하지 않는다.

<a id="task-6"></a>

### 세부 작업 6 — 입력·정답·시간 분할

**목적:** 각 행의 입력과 정답이 당시 시점에서 재현되는 학습 자료를 만든다.

| 구분         | 내용                                                                                    |
| ------------ | --------------------------------------------------------------------------------------- |
| 입력         | 품질 확인 자료·계약·기간/시즌 완료·누락/정정 현황                                       |
| 작업         | 과거 통계·최근 기록·불펜 사용량·휴식·전력 등 입력 구성, 모델별 정답·시간 분할 목록 생성 |
| 산출물       | 입력/정답 자료, 변수 의미·이용 시점, 분할 목록, 누수·정답 완료 검사                     |
| 완료 증거    | 표본의 부모 원본·변환·입력 시각·정답·분할을 재구성할 수 있음                            |
| 실패 시 처리 | 경계·누락·공개 시점 불명 표본을 임의 정상 처리하지 않음. 평가 제한과 제외 이유 기록     |

**인수 전 대조:** [정보 채택](../standards/project_contract.md#input-gate), [M3 정답 완료·겹치는 구간](../standards/project_contract.md#m3-overlap), [경기 묶음·학습 전처리·Test](../standards/project_contract.md#split), [다른 예측기의 당시 생성 가능성](../standards/project_contract.md#stacking)을 검사하고 표본/경기 목록·제외 근거를 남긴다.

모델 선택을 위한 EDA·변수 탐색은 학습 범위에서 수행한다. 정확한 분할 날짜는 이 작업의 자료 근거로 확정하며 성능에 맞춰 바꾸지 않는다.

## 4. 핵심 예측 모델 개발

### 공통 개발 절차

```text
계약·가용성 확인 → 기준 모델 → 변수 비교 → 알고리즘 비교
              → 설정 최적화 → 시간 순서 검증·보정·오류 분석
```

문제별 점수의 우열을 비교하지 않는다. 각 문제 내부에서 같은 분할·표본·지표로 비교한다. 실험 후보와 최종 주 예측기, 전처리·보정의 학습 요소를 별도 기록한다.

<a id="task-7"></a>

### 세부 작업 7 — M1 경기 결과·득점

| 구분         | 내용                                                                                            |
| ------------ | ----------------------------------------------------------------------------------------------- |
| 입력         | 경기 전 입력·공식 결과/득점·시간 분할·시즌 규칙                                                 |
| 작업         | 공통 팀 관점 득점 기본안과 기준 모델 비교, 분포·승무패·예상 스코어 연결, 보정·오류 분석         |
| 산출물       | 입력/전처리/모델/설정 자산, 시점별 경기 예측, 검증 비교·일관성 검사                             |
| 완료 증거    | 정해진 입력으로 재예측 가능, 확률 합·비음수·분포/승무패/스코어 규칙 대조, 개선·비개선 모두 기록 |
| 실패 시 처리 | 분포·결합 가정의 실패를 별도 보고. 모델 추가로 개수를 숨기거나 Test로 선택하지 않음             |

## 9. 증거·실패·변경 관리

### 9.1 상태를 구분하는 말

| 상태          | 뜻                                               |
| ------------- | ------------------------------------------------ |
| 설계          | 기준과 방법을 정했으나 적용·실행은 별도          |
| 적용          | 실제 파일·설정에 반영됨. 동작 성공을 뜻하지 않음 |
| 실행          | 특정 환경에서 수행함. 결과 검증을 뜻하지 않음    |
| 검증          | 기준·입력·실제 결과를 대조하고 근거를 남김       |
| 제한 / 미확인 | 범위가 좁거나 직접 확인할 수 없음                |

단계 완료는 파일 존재나 성공 메시지 하나로 판단하지 않는다. 요구사항·실제 적용·필요 실행·오류/한계·후속 인수가 모두 설명돼야 한다.

### 9.2 최소 증거 묶음

| 증거      | 기록할 내용                                      |
| --------- | ------------------------------------------------ |
| 기준      | 코드/문서·데이터·설정·분할 버전과 실제 작업 위치 |
| 실행      | 실행 식별자·실행 시각·환경·명령/설정·성공/실패   |
| 자료      | 출처·포함 기간·대상 목록·누락·정정·제외          |
| 결과      | 산출물 위치·요약·비교 대상·평가 지표·오류        |
| 확인 수준 | 직접 확인·전달받은 결과·미실행·미확인 구분       |

### 9.3 실패와 회귀 확인

실패하면 원인·영향 대상·사용 제한·보완 방법·재검증 결과를 남긴다. 단계의 공통 대응은 다음과 같다.

| 발견한 문제              | 즉시 제한                                      | 다시 확인할 근거              |
| ------------------------ | ---------------------------------------------- | ----------------------------- |
| 접근·원본·필드 의미 불명 | 해당 자료를 정상 입력으로 채택하지 않음        | 원본·조건·변경 이력·의미 대조 |
| 누수·정답·분할 오류      | 영향 평가 결과를 유효한 성능으로 유지하지 않음 | 경계·관측 완료·표본/경기 목록 |
| 모델 수·출력 가정 불일치 | 이름·파일 포장으로 숨기지 않음                 | 실제 학습 요소·대안·평가 영향 |
| 실행·경로·Secret 문제    | 성공 처리·민감 출력·임의 경로 생성을 막음      | 환경·설정·로그·오류 사례      |

원본 정정·분류 변경은 처리 자료와 정답·분할·모델·예측·평가의 영향 범위와 재생성 여부를 추적한다. 문서만 바뀌면 링크·기준 일치·누락을 대조하고 무관한 Unit Test를 만들지 않는다.

## 10. 단계 인수 체크리스트

- [ ] 입력·출력·시점·정답·기간과 상세 계약이 연결돼 있다.
- [ ] 실제 적용 위치·자산 버전·실행 식별자를 확인했다.
- [ ] 요구된 정상/오류 사례를 실제 결과로 대조했다.
- [ ] 공개 시점·M3 관측 완료·같은 경기 묶음·학습 전처리 경계를 확인했다.
- [ ] 누락·정정·제외·평가 불가·미실행을 숨기지 않았다.
- [ ] 모델 수·미검증 가정·조건부 범위 변경을 기록했다.
- [ ] README·개발 흐름·계약의 정의와 링크가 일치한다.
- [ ] 다음 담당이 사용할 자료·제약·확정 책임을 설명할 수 있다.

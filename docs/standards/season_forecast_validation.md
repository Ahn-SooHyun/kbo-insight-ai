# 시즌 전망·보조 분석 종합 검증

KBO Insight AI · 기술 계약 및 실행 안내 · [Issue #35](https://github.com/Ahn-SooHyun/kbo-insight-ai/issues/35)

저장소 적용 경로: `docs/standards/season_forecast_validation.md`

## 범위와 실행 경계

기준 `main`은 `11f996b6ac04c0edac706d4b16599e49cc6ebdc5`이다. 고정 표준 DB, 모델 자료 DB, M1, 기존 정규시즌·포스트시즌·보조 분석과 고정 최종 평가 결과를 변경하지 않는다. 검증 모듈은 고정 자산과 기존 운영 CLI를 사용하며 학습·선정·보정 또는 새 예측기를 추가하지 않는다. 이 문서는 구현 및 실행 계약의 제안본이며 실제 통과·적용·수용을 뜻하지 않는다.

## 사전 고정 및 실행

`prepare`는 신규 검증 디렉터리에 `plan.json`을 작성하고 SHA-256을 출력한다. 계획에는 기준 HEAD, 실제 Git 상태, Python 버전, 고정 자산 및 기존 산출물, 관련 코드·테스트·설정·본 문서의 지문과 실행 조합이 포함된다. `run`과 `verify`에는 출력된 계획 경로와 SHA-256을 전달한다. 입력 파일의 변동이나 지문 불일치는 차단한다.

정규시즌 대표 기준은 2025-09-01 KST 자정, Seed 42, 1,000회이며 개발 진단을 포함한다. 동일 조건 재실행, Seed 42/2,000회 및 Seed 43/1,000회를 추가 실행한다. 각각의 포스트시즌 실행은 해당 정규시즌 부모 실행 ID를 인수한다. 별도의 2025-11-01 종료 재생은 Seed 42/1,000회이며 원천 판본 가정을 명시한다. 보조 분석은 동일 대표 부모를 인수한 시즌/대표 경기, 2025년 선발 개발 평가, 최초 지원일과 종료 이후 경계일을 실행한다. 새 결과만 생성한다. 검증 전용 테스트와 전체 회귀도 실행 증거에 포함한다.

`run`은 개별 성공 기록과 산출물 지문을 보존한다. 다시 실행할 경우 검증 가능한 기존 성공 기록은 재사용한다. 실패 기록은 별도 파일에 보존하고 성공한 작업을 덮어쓰지 않는다. 원천 자료 및 이전 결과를 삭제하거나 수정하지 않는다.

## 독립 검산과 판정 기준

- 정규시즌: 표준 DB 경기 식별자·날짜·홈/원정·점수 및 기준일 절단을 대조한다. 반복별 팀 기록과 순위·진출·시드를 검사하고 승수·순위·1위·진출 분포, 분모 및 미결정 사유를 재집계한다. 정규시즌 반복 출력은 팀별 집계이므로 완료 경기의 반복별 개별 점수 행까지 저장되지는 않는다. 실제 완료 경기의 시나리오 연결과 반복 집계의 하한·합계 검증을 구별한다.
- 포스트시즌: 부모·자식 반복의 식별자, 확정 시드, 진출 상태, 순위, 1위 상태 및 미결정 사유를 전수 대조한다. 시리즈 연결과 실제 기록의 접두 구간을 검사하고 기존 규칙으로 차전·홈·종료 상태를 다시 검증한다. 팀별 참가·승리 사건과 라운드 공동 분모, 대진 조건부 분모를 독립 재집계한다. 규칙 재생은 기존 규칙의 재사용이며 완전히 별개 규칙 구현이 아니다.
- 재현: 동일 Seed·입력·반복 수에서 계산 출력은 정확히 같아야 한다. 정규시즌과 포스트시즌의 2,000회 실행에서 앞 1,000개 반복 행도 일치해야 한다. 실행 ID·시각 등 비계산 메타데이터는 명시한 범위에서만 제외한다.
- 변동: 동일 입력의 Seed 변화와 반복 수 변화는 별도로 기록한다. 사건별 유효 분모가 30 이상일 때 확률 변화가 `max(0.02, 5 * sqrt(0.25/n1 + 0.25/n2))`를 초과하면 조사 대상으로 표시한다. 기대 승수·순위는 각각 가능한 범위(144, 9)를 곱한 동일한 보수적 척도와 0.5의 최소 변화 기준을 사용한다. 이 기준은 사전 선언한 탐색적 경고이며 공식 신뢰구간 또는 합격 성능 기준이 아니다. 중첩 반복과 미결정 분모의 의존성을 고려한다.
- 선발: 실제 정답은 `starter_actual`의 경기×팀 키에서 확인한다. 전체·정답 식별·후보 제공·공통 분모를 구분하고 두 규칙의 Top-1/Top-3을 저장 표본으로 독립 계산한다. 전체 이력과 기준일 이전 행만 남긴 자료에서 기존 후보 규칙을 재실행해 미래 입력 영향 여부를 비교한다. 이는 별도 선발 모델 학습이나 독립 순위 알고리즘 구현이 아니다.
- 팀·일정: 실제 완료 경기 행에서 시즌/최근 28일·홈/원정·상대별 기록을 재계산한다. 일정의 팀별 경기 키, 유효 확률, 미편성 및 누락 수를 검사한다. 난이도는 `P(loss)+0.5*P(tie)`이며 두 팀 값의 합은 1이다. 팀 평균은 유효 전망 경기의 동일 가중 평균이다. 분모 0은 null이다. 자료에 없는 누락 상황은 기존·신규 합성 테스트와 구별한다.

## 실행

프로젝트 루트에서 사용자 실행 명령:

```powershell
& {
    Set-Location 'D:/Programming/kbo-insight-ai'
    $py = 'D:/Programming/kbo-insight-ai/.venv/Scripts/python.exe'
    $raw = & $py -X utf8 -B -m src.validation.season_forecast prepare
    if ($LASTEXITCODE -ne 0) { throw '검증 계획 생성 실패' }
    $plan = ($raw -join "`n") | ConvertFrom-Json
    $plan | ConvertTo-Json -Depth 5
    & $py -X utf8 -B -m src.validation.season_forecast run --manifest $plan.manifest --manifest-sha256 $plan.sha256
    if ($LASTEXITCODE -ne 0) { throw '검증 실행 실패' }
    & $py -X utf8 -B -m src.validation.season_forecast verify --manifest $plan.manifest --manifest-sha256 $plan.sha256
    if ($LASTEXITCODE -ne 0) { throw '독립 검산 실패' }
    git diff --check HEAD
    if ($LASTEXITCODE -ne 0) { throw 'Git 형식 검사 실패' }
    git status --short --branch
}
```

실패 후에는 같은 계획 경로 및 지문으로 `run`을 재호출한다. 코드나 입력을 변경해야 하는 경우 기존 계획과 결과를 보존하고 신규 계획을 작성한다. 종료 코드 0과 결과의 모든 검산 항목 통과를 확인한다. Git 변경은 사용자가 수행한다.

## 산출물과 후속 인계

`results/season_forecast_validation/<run_id>/plan.json`, `jobs/*.json`, `verification-<id>.json` 및 각 기존 CLI가 생성한 독립 결과 디렉터리를 보존한다. 검증 결과에 포함된 경로와 파일 지문을 통해 정규시즌·포스트시즌 `iterations.jsonl`, `summary.json`, `scenario.json`, `manifest.json`과 보조 분석 `evaluation.json`, `season.json`, `game.json`에 연결한다. 반복 연결 키는 `iteration_id`, 선발·일정은 `game_id` 및 `team_id`, 대진은 라운드와 순서 있는 상위/하위 시드 구단 ID다. 미결정·가정·미지원은 실패 또는 실제 0과 구별한다.

실제 완료 여부·검산 수치·테스트 수·종료 코드·적용 HEAD·하위 판정은 사용자 실행 증거 확보 후 수용 요청 보고서에 기록한다. 이 문서는 실제 수행되지 않은 검증을 통과로 기록하지 않는다.

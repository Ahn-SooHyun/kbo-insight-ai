## 1. 목적·지원 범위

### 1.1 문제 정의

시즌 중 특정 날짜 자정까지의 성적이 주어졌을 때 이후 예정 경기의 결과에 따라 정규시즌 최종 승수·순위가 어떻게 달라지는지를 계산한다. 팀별 최종 승수·순위·1위·진출 사건은 같은 경기 결과들의 함수이므로 각각 독립된 분류기 또는 회귀기로 학습하지 않는다. 같은 모의 시즌 안에서 양 팀의 경기 결과를 동시에 반영하고, 모든 팀의 성적에 동일한 리그 규칙을 적용한다. 이로써 리그 전체 승수와 패수의 합, 구단별 경기 수, 진출 인원, 상위 시드가 서로 모순되지 않는 공동 결과를 생성한다.

| 정의 항목 | 계약                                                                                                                                                |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 입력 시점 | KST 날짜 자정. 예측일 당일 및 이후의 실제 점수·승무패는 입력하지 않는다.                                                                            |
| 지원 시즌 | 2025년 정규시즌만; 기준 날짜 2025-03-22~2025-12-31                                                                                                  |
| 입력      | 표준 완료 경기, M1 자료 교차 대조, 잔여 경기 식별 정보, 저장된 M1 자산, 규칙, Seed, 반복 횟수                                                       |
| 출력      | 팀별 최종 승수 분포·기대 승수·순위별 확률·기대 순위·정규시즌 1위 및 진출 확률; 공동 분모와 반복별 진출 구단·시드                                    |
| 정답      | 실제 완료 시즌의 정규시즌 공식 승수·순위·1위·진출 상태. 구현은 완료 근거를 확인한 표준 경기로 재계산한다.                                           |
| 모델 수   | 신규 주 예측기 0개. 인수한 M1 한 개를 재사용한다. 전체 기존 6개 주 예측기의 집계 변경 없음. M3의 PR #26 병합 및 Issue #21 종료는 원격에서 확인했다. |
| 실행 유형 | 과거 개발 가정 시나리오; 입력한 외부 일정 스냅샷도 공개 진위를 독립 인증하지 않음                                                                   |
| 제외      | 한국시리즈 및 시리즈 승리 계산, 1·5위 별도 결정전의 결과 예측, 2026 최종 Test, 신규 선수/라인업 입력, 별도 우승 모델 학습                           |

### 1.2 용어와 조건부 의미

- **정규시즌 1위:** 정규시즌 종료 순위가 1인 팀. 한국시리즈 우승과 다르다.
- **포스트시즌 진출:** 정규시즌 규칙에서 상위 5개 팀으로 확정되는 사건이다. 진출을 확정할 수 있는 것과 정확한 시드를 확정할 수 있는 것은 다르다.
- **확정:** 적용한 규칙과 보수적인 잔여 경기 범위 내에서 가능한 모든 결과가 해당 판정을 바꾸지 않는 경우. 예측 확률이 100%인 것과 다르다.
- **미결정:** 자료 부족, 무정의 승률 또는 별도 결정전 미실시 등으로 판정 불가능한 값. `null`로 유지한다. 실제 확률 0 또는 탈락(`false`)과 같지 않다.
- **개발 진단:** 이미 학습·선정한 M1을 2025년 사후 일정 가정에서 사용하는 실험. 당시 배치된 모델의 실시간 운용을 재현했다고 주장하지 않는다.

### 1.3 규칙 근거

규칙의 원문 식별자는 소스에 저장된 [2025 KBO 리그 규정](https://6ptotvmi5753.edge.naverncp.com/KBO_FILE/ebook/pdf/2025_%EB%A6%AC%EA%B7%9C%EC%A0%95.pdf) 및 [2025-03-07 KBO 공지](https://www.koreabaseball.com/MediaNews/Notice/View.aspx?bdSe=11396)다. 이번 문서에서는 원격 `rules.py`에 구현된 판정과 인수된 검증 결과를 설명한다. 공식 PDF의 모든 조문을 이번 문서 작성에서 독립적으로 재확인한 것은 아니다. 새 시즌 적용 시 규정 원문을 다시 대조해야 한다.

`data.py:verify_assets`는 기존 M1 `source`와 `load_model`을 호출하고 표준 및 모델 DB의 SHA-256을 매니페스트와 비교한다. 모델 데이터 실행 ID·자료 지문·계약 지문이 저장 모델의 계보와 같아야 한다. 저장 모델의 분할 키는 `train`, `validation`만 허용하며 Validation 마지막 날짜가 2026-01-01 이후이면 거부한다. 검증용 원본 DB는 SQLite URI `mode=ro`, `PRAGMA query_only=ON`으로 연결한다. 이는 원본 변경을 막는 저장 경계이지 데이터 사용 허가의 대체물이 아니다.

자료 이용은 승인된 비영리 대학 과제용 로컬 처리 및 내부 평가로 제한한다. 원본·로컬 자산·예측 결과를 별도 근거 없이 공개 저장소로 재배포하지 않는다.

### 2.3 정보 경계 및 일정 증거

완료 경기 조회와 잔여 일정 조회를 분리한다. `read_completed`는 `eligible_games`와 `m1_index`·`m1_inputs`·`m1_targets`의 날짜가 기준일 미만인 정규시즌 경기만 읽으며 경기 ID, 표준 source key, 표본 ID, 날짜, 홈·원정, 득점, 결과, 경기 집합을 교차 검사한다. M1 자료에 이미 존재하는 누적 통계 컬럼은 여기서 재사용하지 않는다.

잔여 일정 조회 `read_archive_schedule`는 기준일 이후 `eligible_games`에서 경기 ID, source key, 날짜, 차수, 홈·원정 구단만 읽는다. 미래 실제 점수와 승무패 컬럼은 조회하지 않는다. 그러나 **실제 완료 경기를 바탕으로 한 사후 일정 자체에는 미래 일정 확정 정보가 들어 있을 수 있다.** 따라서 점수 누수 차단과 엄격한 as-of 정보 가용성은 같은 주장이 아니다. 사후 상태 집계 `archive_status_counts`는 메타데이터에만 남는다.

| 일정 모드                           | 의미                                                         | 제한                                           |
| ----------------------------------- | ------------------------------------------------------------ | ---------------------------------------------- |
| `retrospective_schedule_assumption` | 실제 완료 경기 식별 정보로 잔여 일정 가정                    | 당시 공개 일정이 아님; 재편성 개별 연결 미검증 |
| `provided_snapshot_unverified`      | 외부 JSON 일정의 스키마·공개 주장·시간대·행·재편성 연결 검증 | 공개 출처 진위를 독립 인증하지 않음            |

외부 스냅샷은 `regular-season-schedule-v1`, `season`, 시간대가 포함된 `published_at`(기준 시각 이하), `source_url`(HTTPS 문자열), `version`, `fixtures`를 포함한다. 일정 행의 허용 필드는 `game_id`, `date`, `home_team_id`, `away_team_id`, `game_number`, `status` 및 선택 `rescheduled_from`이다. 완료 점수·승무패 등 추가 필드는 거부한다. `scheduled`만 모의 경기로 사용하고 `postponed`/`cancelled`는 별도 경기로 합산하지 않는다. 재편성 연결은 선행 상태, 중복, 날짜, 상대 구단 집합을 확인한다. 단순 URL 및 공개 시각 문자열이 신뢰 가능한 공개 시점 증명을 의미하지 않는다.

2025년 날짜 경계 이전 완료 결과가 다음 날짜 자정까지 알려졌다고 가정한다. 시간 단위 실제 공개 이력, 경기 종료·정정 시각 및 모델의 기준일 이전 이용 가능성이 입증되지 않았다. `formal_backtest_supported=false`를 출력하며 진단은 `formal_backtest=false`, `selection_use=prohibited`, `final_test_used=false`로 기록한다.

### 2.4 자료 품질과 탐색적 해석

경기 ID의 날짜·구단 코드·차수를 표준 정규식과 대조한다. 중복 ID, 동일 날짜에 상충하는 구단 일정, 경기 차수, 구단 쌍별 초과 경기 수 등을 `validate_schedule`로 확인한다. 리그 전체 경기 수는 $\binom{10}{2}\times16=720$이고 각 팀은 $9\times16=144$다. 누락된 구단 쌍과 경기 수를 `missing_pairs`, `missing_games`로 기록한다. 일정 불완전성을 임의 상대·임의 결과로 채우지 않는다.

9월 1일 기준으로 시즌 후반부의 결과만 모의하는 실험이다. 초반부나 시즌 중반부에 같은 정확도 또는 변동성을 보장하지 않는다. 별도의 새 EDA Notebook·분포 시각화·정식 기간별 검증은 이번 Issue에서 수행하지 않았다. M1의 2025년 평균 예측 무승부율 2.07%와 관측 무승부율 3.06%는 인수된 모델 한계이며 시뮬레이션 메타데이터에 기록된다.

### 4.1 정답과 완료 조건

정답은 2025년 실제 완료 정규시즌을 구성하는 720개의 검증된 공식 경기 결과로부터 동일 규칙으로 집계한다. `read_diagnostic_truth`는 표준 `season_complete=1` 근거가 전체 720경기에 존재하는지 확인하고 모든 경기·정답을 모델 자료와 대조한다. 후보와 기준 계산이 모두 끝난 뒤에만 정답을 읽는다. 실제 정답을 기준 계산, 모델 선택 또는 하이퍼파라미터 탐색으로 연결하지 않는다. 정규시즌 1위 및 진출은 공식 순위 사건의 정답이고 한국시리즈 우승 정답이 아니다.

### 4.3 팀별 확률 및 공동 분모

`regular-season-summary-v1`은 `season`, `requested_iterations`, `teams`, `league`를 제공한다. 팀별 `final_wins`는 범주 0~144, `rank`는 1~10, `regular_season_first`와 `postseason_qualification`은 0/1 범주의 분포다. 네 지표마다 별도의 분모와 미결정 사유를 갖는다.

| 지표 공통 필드       | 의미                                                               |
| -------------------- | ------------------------------------------------------------------ |
| `status`             | 유효 분모 존재 시 `supported`, 아니면 `unsupported`                |
| `requested`          | 전체 요청 반복 수 $N$                                              |
| `valid`              | 해당 지표가 확정된 반복 수 $n$                                     |
| `unresolved`         | 미결정 반복 수 $N-n$                                               |
| `unresolved_reasons` | 미결정 사유별 개수                                                 |
| `counts`             | 범주별 확정 횟수 $c_x$                                             |
| `probabilities`      | $n>0$일 때 $c_x/n$, 아니면 범주별 null                             |
| `expected`           | 유효 반복 조건부 평균; 이진 지표는 사건 확률; 유효 분모 0이면 null |

$$\widehat P(X=x\mid A)=\frac{c_x}{n},\qquad \widehat E[X\mid A]=\frac{\sum_x x c_x}{n},\qquad A=\{X\text{ is resolved}\}.$$

이진 지표의 `expected`를 읽으면 확정된 반복을 조건으로 하는 확률이다. $c_1/N$은 전체 반복 중 사건이 확인된 비율이며, 미결정 상태를 어떻게 판정할지 모르는 경우 실제 전체 사건 확률과 다를 수 있다. 다음 보수적 식은 문서의 해석 보조이며 현재 `summary.json`이 별도 구간을 출력하는 것은 아니다.

$$\frac{c_1}{N}\le P_{\text{empirical completion}}\le\frac{c_1+(N-n)}{N}.$$

이는 미결정 결과를 모두 0 또는 1로 놓았을 때의 반복 표본 내 극단 경계다. 통계적 신뢰구간, 확률 보정, 실제 성능 보장은 아니다. 조건부 분모가 팀마다 다르면 팀별 1위 확률을 단순 합산하여 정확히 1이 되는 것을 기대할 수 없다. 리그 공통 분모 `first_joint_valid` 및 `qualification_joint_valid`를 사용하면 공동 확정 반복에서 각각 합 1 및 합 5를 검사할 수 있다.

## 5. 모델·학습·선정

### 5.1 신규 학습 없이 기존 M1을 재사용하는 이유

이 기능은 경기 단위 지도학습 모델의 출력으로 시즌 단위 사건의 분포를 계산한다. 독립 순위 회귀나 우승 이진 분류기를 추가하면 경기 결과와 순위의 논리적 일관성, 시즌 간 독립 정답의 희소성, 프로젝트 모델 수 관리 등의 문제가 생긴다. 따라서 동일 경기 예측기를 재사용하고 규칙·난수·통계 집계를 결합한다.

| 항목      | 운영 계산                                                | 개발 진단 기준                                                 |
| --------- | -------------------------------------------------------- | -------------------------------------------------------------- |
| 방식      | `existing_m1_dynamic_daily_history_joint_score_sampling` | `venue_only_using_existing_m1_tie_weight`                      |
| 예측 자산 | 기존 저장 M1                                             | 같은 저장 자산의 홈/원정 경험 득점 분포 및 무승부 가중치       |
| 경기 이력 | 날짜 이전 시즌 및 최근 28일 프로필                       | 프로필 차이 사용하지 않음                                      |
| 학습·튜닝 | 없음                                                     | 없음                                                           |
| 적용 규칙 | 동일 시즌·일정·초기 성적                                 | 동일                                                           |
| 난수      | 동일 Seed와 반복 수                                      | 동일 Seed와 반복 수; 분포별 대응은 완전히 같다고 가정하지 않음 |
| 역할      | 운영 가정 시나리오 계산                                  | 개발 비교용; 별도 주 예측기 아님                               |

인수 M1의 `cap=39`, `league_mean=4.8801627461706785`, `tie_weight=0.16978105721277892`는 사전 점검 전달값이다. 운영 코드에서는 이 값을 다시 하드코딩하지 않고 자산을 읽는다. M1의 훈련 원리·평활·비교 실험은 [경기 결과·득점 문서](game_outcome_score.md#method)를 따른다. 별도 Grid Search, Random Search 또는 최종 Test 기반 모델 재선정은 이 Issue에서 하지 않는다.

### 5.2 결합 득점 분포

M1의 `home_base_pmf`와 `away_base_pmf`를 각각 $p_H(h)$, $p_A(a)$라 하고 무승부 셀과 비무승부 셀의 가중치를 $w_=,w_{\ne}$, 정규화 상수를 $Z$라 한다. `JointSampler`는 저장 모델의 추론 결과가 정의하는 다음 결합 질량을 재구성한다.

$$q(h,a)=\frac{p_H(h)p_A(a)w(h,a)}{Z},\quad w(h,a)=\begin{cases}w_=&h=a\\w_{\ne}&h\ne a.\end{cases}$$

$$P(H)=\sum_{h>a}q(h,a),\qquad P(T)=\sum_{h=a}q(h,a),\qquad P(A)=\sum_{h<a}q(h,a).$$

승·무·패 범주별 질량을 원래 M1 `result_probabilities`와 대조한다. 음수·비유한 값, 빈 조건부 분포, 정규화 오류, 불일치를 거부한다. 기본 주변분포의 단순 독립 표본 추출로 대체하면 무승부 가중치가 적용된 최종 공동 분포를 훼손할 수 있다. 동률 상대 다득점 규칙까지 계산해야 하므로 단순 승무패 범주만 뽑는 대신 같은 공동 분포의 득점 쌍을 사용한다.

### 5.3 몬테카를로 표본 추출과 날짜별 상태 갱신

1. 범주 질량으로 누적분포를 만든 뒤 $U_1\sim U[0,1)$을 사용하여 승·무·패를 표본 추출한다.
2. 선택 범주 $C$에서 조건부 득점분포 $q(h,a)/P(C)$를 구성하고 $U_2\sim U[0,1)$으로 득점 쌍을 추출한다.
3. $P(C)P(h,a\mid C)=q(h,a)$이므로 이 두 단계는 원래 결합 분포의 표본 추출과 일치한다.
4. 같은 날짜의 모든 경기 예측을 먼저 생성하고 모의 결과를 일괄 반영한다. 날짜가 지나면 프로필을 다시 계산한다.
5. 각 반복의 최종 상태에 같은 규칙을 적용하고 팀별·공동 결과를 저장한다.

`cumulative`는 양수 가중치의 누적 질량을 만들고 마지막을 1.0으로 고정한다. `bisect_right`로 범주·점수 셀을 찾는다. 0질량 셀은 표본 추출에서 제외한다. 동일 프로필의 `JointSampler`는 `M1Sampler.cache`에서 재사용하되 경기 결과 자체를 캐시하지 않는다. 동일 프로필은 동일 분포를 갖지만 각 경기 표본은 새로운 난수로 생성한다. Python `random.Random(seed)`를 실행당 한 번 초기화하고 반복마다 초기 시즌 상태를 복사한다.

이는 반복별 경로의 확률 계산으로, 모든 경기 조합을 전수 열거하지 않는다. 날짜별 상태 갱신으로 미래 경기의 분포는 이전 모의 경기 결과에 의존한다. 같은 반복의 경기/팀 결과를 독립으로 간주할 수 없다. 반복을 늘리면 몬테카를로 근사 오차를 줄일 수 있지만, 일정·리그 규칙·M1 분포의 편향과 미결정 비율을 자동으로 해결하지 못한다.

### 5.4 승률·동률 및 확정 성적

2025년 팀 ID는 KIA 2001, KT 2002, LG 2003, NC 2004, SSG 2005, 두산 2006, 롯데 2007, 삼성 2008, 키움 2009, 한화 2010이다. `PREVIOUS_RANK_2025`는 공식 근거로 기록한 전년도 최종 구단 순위(순서 KIA, 삼성, LG, 두산, KT, SSG, 롯데, 한화, NC, 키움)를 사용한다.

정규시즌 승률은 $r_i=W_i/(W_i+L_i)$이다. 무승부는 경기 수에는 포함되나 승률 분모에서 제외한다. `Fraction`을 사용하여 동률을 부동소수점 오차로 잘못 판정하는 것을 방지한다. 승률 분모가 0이면 순위를 임의 확정하지 않는다.

| 상황                                  | 구현 판정                                                          |
| ------------------------------------- | ------------------------------------------------------------------ |
| 유일 승률                             | 내림차순 순위                                                      |
| 정확히 두 팀의 1위 또는 5위 경계 동률 | 별도 결정전 결과가 없으므로 해당 순위 범위 미결정                  |
| 5위 이내에서 시작하는 기타 동률 집단  | 집단 내부 상대전적 다승, 상대 다득점, 전년도 확정 순위 순서로 판정 |
| 전년도 순위 근거가 필요한데 없음      | 미결정 사유 저장                                                   |
| 6위 이하에서 시작하는 동률 집단       | 공동 순위 처리                                                     |
| 미완료 일정 / 무정의 승률             | 보수적 순위 가능 범위에서 확정 가능한 사건만 확정                  |

위 표는 `rules.py:resolve_tied_group`, `resolve_standings`, `bounded_standings`의 실제 구현 설명이다. 정확히 두 팀 동률의 별도 결정전은 미래 결과를 새로 예측하지 않는다. 다팀 동률의 세부 규정 변경, 실제 별도 결정전 처리, 후속 시즌은 별도 근거가 필요하다.

아직 $m$경기가 남은 팀의 보수적인 승률 하한과 상한은 다음과 같다.

$$\ell=\frac W{W+L+m},\qquad u=\frac{W+m}{W+L+m}.$$

분모가 0이면 $[0,1]$로 둔다. 다른 팀 $j$의 $\ell_j>u_i$이면 반드시 위, $u_j<\ell_i$이면 반드시 아래다. 가능한 최선 순위는 $1+\#\{j:\ell_j>u_i\}$, 최악 순위는 $10-\#\{j:u_j<\ell_i\}$다. 최악 순위가 1이면 1위 확정, 최악이 5 이하이면 진출 확정, 최선이 5 초과이면 탈락 확정이다. 부등호는 동률 가능성을 배제하지 않기 위해 엄격 비교한다. 구단 간 상호 의존을 모두 열거하지 않은 외부 경계라서 확정을 놓칠 수 있으나 섣불리 확정하지 않는 방향으로 설계했다. `verify_fixed`는 시작 시 확정된 상태가 반복 결과에서 바뀌지 않는지 검사한다.

### 5.5 복잡도·자원·선정 한계

팀 수를 $K$, 경기 수를 $G$, 잔여를 $R$, 반복 수를 $N$, 프로필 조합 수를 $C$라 두면 실행은 초기 완료 이력 구축과 대략 $N\times R$회의 경기 표본 추출을 수행한다. 결합 분포 생성은 프로필별 점수 격자 크기에 의존하며 재사용으로 비용을 줄인다. 순위 계산은 팀 수와 상대전적 처리에 의존한다. 구현은 전체 반복 결과를 메모리에 유지한 뒤 저장하므로 메모리 사용량은 반복 수와 팀 수에 따라 증가한다. 이론적 차수 설명은 실제 메모리·CPU 벤치마크가 아니다. 검증된 실행 환경은 CPU 기반 Python 표준 라이브러리 사용이며 GPU 가속, 대규모 병렬 처리, 메모리 피크 측정은 수행하지 않았다.

## 7. 평가 지표·실제 결과

### 7.1 지표 정의 및 분모

팀 수를 $K$라 한다. 해당 지표의 예측 및 정답이 모두 존재하는 팀 집합 $V$에 대해서만 계산한다.

| 지표                   | 산식                                                                   | 단위·방향                |
| ---------------------- | ---------------------------------------------------------------------- | ------------------------ |
| 승수 MAE               | $\frac1{\lvert V\rvert}\sum_{i\in V}\lvert\hat W_i-W_i\rvert$          | 승, 낮을수록 좋음        |
| 순위 MAE               | $\frac1{\lvert V\rvert}\sum_{i\in V}\lvert\hat r_i-r_i\rvert$          | 순위 차이, 낮을수록 좋음 |
| 1위·진출 Brier         | $\frac1{\lvert V\rvert}\sum_{i\in V}(p_i-y_i)^2$                       | 무차원, 낮을수록 좋음    |
| 1위·진출 이진 Log loss | $-\frac1{\lvert V\rvert}\sum_{i\in V}[y_i\log p_i+(1-y_i)\log(1-p_i)]$ | 자연로그, 낮을수록 좋음  |

실제 코드는 각 팀별 지표의 `expected`를 사용한다. Log loss에서 로그의 0을 방지하기 위해 `1e-15` 하한을 사용한다. Brier는 팀별 이진 Brier 평균이지 10클래스 합산 Brier가 아니다. 같은 시즌 팀들의 순위와 진출은 서로 의존하므로 10개 팀을 10개의 독립 시즌으로 간주하지 않는다. 비교 표의 팀 평가 행은 후보와 기준 모두 10개였지만 확률 자체는 각 방식·팀의 유효 반복 조건부로 계산된다.

| 동일                 | 진출 확률(퍼센트포인트) |    1.723265 |    0.596607 |    10 |

동일 Seed 실행의 요약·반복별 결과·SHA-256은 완전 일치했다. 2,000회 실행의 처음 1,000행은 동일 Seed의 1,000회 실행과 동일했다. 1,000↔2,000 비교는 서로 독립된 반복 표본의 비교가 아니다. 관측된 차이를 계산 안정성의 진단으로만 보고하며 1,000회가 모든 기준일에서 충분하다는 보편적 임계값을 정하지 않는다. 베르누이 사건 확률의 독립 유효 반복에서 근사 표준오차 $\sqrt{p(1-p)/n}$를 참고할 수 있으나 조건부 분모·미결정·모델 오류는 포함하지 않는다. 신뢰구간 산출은 현재 구현에 추가하지 않았다.

### 8.2 실행·산출물의 계보

```text
검증된 표준 DB + 모델 자료 DB + 저장 M1 자산
              |
       완료 경기(기준일 이전) + 잔여 일정 식별 정보
              |
       날짜별 모의 경기 -> 규칙 -> 반복별 공동 결과
              |
  scenario.json | iterations.jsonl | summary.json
              |                 |
  별도 개발 진단(선택)       후속 포스트시즌 인계
              |
       manifest.json (마지막 저장)
```

매니페스트에 `run_id`, `version`, `created_utc`, `season`, `as_of_kst`, `seed`, `iterations`, Python/SQLite 버전, 소스 파일별 SHA-256, 스키마, 메타데이터, 계산 방법, 난수 생성기, 경기 처리 순서, 동일 날짜 정책, 캐시 프로필 수, 진단 여부와 최종 Test 사용 여부를 기록한다. `files`에는 생성 파일의 경로와 SHA-256이 있다. 원본 모델의 생성 시각·Train/Validation 구간·자료 지문도 `metadata.provenance`에 보존한다. 실행 UUID가 달라질 수 있으므로 전체 매니페스트 바이트가 동일해야 재현 성공이라고 판단하지 않는다. 비교의 핵심은 같은 입력·설정에 대한 요약과 반복별 결과 및 해당 파일 지문이다.

| 재현 대상                                                | 실제 사용자 확인                                                     |
| -------------------------------------------------------- | -------------------------------------------------------------------- |
| 일반/진단 실행의 후보 `summary.json`, `iterations.jsonl` | 동일 Seed에서 완전 일치                                              |
| 반복별 파일 SHA-256                                      | 동일 Seed 일치                                                       |
| 더 많은 반복                                             | 기존 반복 prefix 동일                                                |
| 이전 실행 `98a7738466ad46a3a3d3f43d751fe0d5`             | 수정 후 A와 요약·반복·진단·기준 반복·반복 파일 해시 일치             |
| 파일 무결성                                              | 각 실행의 매니페스트 파일 및 소스 SHA-256 재검산 통과                |
| 종료 시즌                                                | 실제 팀별 승수 고정, 캐시 프로필 0, 10개 반복의 팀 상태 및 시드 일치 |

### 8.3 환경과 오류 처리

기존 Python 프로젝트 설정, 표준 라이브러리(SQLite, `random`, `fractions`, `bisect`, `json`, `hashlib` 기반 파일 지문 경계)를 사용한다. 새 외부 의존성이나 GPU가 필요하지 않다. 실행 실패는 로그로 진단하고 stdout 완료 JSON과 구분한다. CLI의 종료 코드는 성공 0, 입력/실행 오류 2, 사용자 중단 3이며 다른 모듈의 수집/저장 종료 코드와 혼용하지 않는다. 구체 예외는 `OSError`, `SourceError`, `ValueError`, `TypeError`, `KeyError`, `AttributeError`, `OverflowError`, `sqlite3.DatabaseError`를 처리한다. 잘못된 CLI 인자는 argparse가 거부할 수 있다. 원본 DB에는 쓰지 않으며 신규 실행 결과 저장 실패 시 매니페스트의 완료 상태 및 해시를 확인한다.

### 9.3 후속 포스트시즌 인계

[Issue #28](https://github.com/Ahn-SooHyun/kbo-insight-ai/issues/28)의 입력은 하나의 정규시즌 실행의 `manifest.json`, `scenario.json`, `iterations.jsonl`, `summary.json` 및 원본 M1 계보다. 실제 후속 구현의 계약 확정과 사용자 실행은 별도 작업이다.

- 해당 실행의 상태, 스키마, 소스·자료·자산 식별자, 파일 경로·해시 및 반복 수를 대조한다.
- 같은 `run_id`/`iteration_id`의 팀 상태와 시드를 함께 사용한다. 팀별 진출 확률을 서로 독립적인 베르누이 표본으로 뽑아 시드를 다시 조합하지 않는다.
- `postseason_seeds`가 null인 94개 행을 조용히 버리지 않는다. 지원 여부·미결정 이유·유효 및 전체 분모를 후속 확률 계산에서 명시한다.
- 특정 대진에서의 조건부 한국시리즈 승리 확률과 현재 기준일의 전체 우승 전망을 구분한다. 이번 정규시즌 1위 확률을 한국시리즈 우승 확률로 표기하지 않는다.
- 같은 실행에서 정확한 시드가 확정된 906회는 후속 대진 계산 후보이며, 나머지 94회를 어떻게 처리할지는 포스트시즌 규칙 및 별도 결정전 지원의 확인에 달려 있다. 이 문서가 해당 기능의 구현·실행·검증 완료를 선언하지 않는다.

## 10. 실행 명령

### 10.1 전제와 읽기 전용 기준 확인

확인된 Windows PowerShell 저장소는 `D:/Programming/kbo-insight-ai`이다. 다른 환경은 실제 확인한 절대 경로와 해당 Python 실행 파일을 사용한다. 원본 수집이나 M1 재학습을 요구하지 않는다. 아래 실행은 새 결과 디렉터리를 생성하지만 기존 자료 또는 결과를 삭제·덮어쓰지 않는다. 실행 중 오류가 나면 중단하고 종료 코드·로그·파일 상태를 기록한다.

```powershell
Set-Location -LiteralPath 'D:/Programming/kbo-insight-ai'
$ErrorActionPreference = 'Stop'
$root = (Get-Location).Path
```

```powershell
function Invoke-Season {
    param([int]$Count, [int]$Seed, [string]$AsOf='2025-09-01', [switch]$Diagnostic)
    $arguments = $common + @('--as-of',$AsOf,'--iterations',"$Count",'--seed',"$Seed")

    $lines = & $python @arguments
    if ($LASTEXITCODE -ne 0) { throw '시뮬레이션 실행 실패' }
    $result = ($lines -join "`n") | ConvertFrom-Json

    return $result
```

```powershell

def inspect(directory, expected_count, expected_seed, completed, remaining, cutoff):
    root = Path(directory)
    def read(name):
        return json.loads((root / name).read_text(encoding="utf-8"))
    manifest = read("manifest.json")
    scenario = read("scenario.json")
    summary = read("summary.json")

    assert manifest["seed"] == expected_seed
    assert manifest["as_of_kst"] == cutoff + "T00:00:00+09:00"
    assert manifest["final_test_used"] is False
    assert manifest["formal_backtest_supported"] is False
    for name, info in manifest["files"].items():
        path = Path(info["path"])
        assert path.parent == root and path.is_file(), name
        assert sha256_file(path) == info["sha256"], name
    source = Path.cwd() / "src/simulation/regular_season"
    for name, digest in manifest["source_sha256"].items():
```

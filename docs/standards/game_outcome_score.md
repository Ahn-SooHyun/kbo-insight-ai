## 입력과 지원 범위

M1은 정규시즌 경기 시작 전에 해당 날짜보다 이른 같은 시즌 정규시즌 종료 경기 이력을 받아 공식 종료 득점을 예측한다. 경기 날짜는 KST 기준이다. 최근 창은 직전 28일이며 경기일 당일의 더블헤더 두 경기 모두 이력에서 제외한다. 과거 일정의 당시 공개 시각은 복원되지 않았다. 운영 호출자는 경기 시작 전 확인된 대진과 당시 이용 가능한 완료·공개 기록으로 JSON을 만들고 실행 시각과 입력의 출처를 함께 보관한다.

입력 JSON은 `competition` 값 `regular`와 홈·원정 각각 아래 6개 열을 받는다. 접두사는 `home_`, `away_`다. DB에서 내보낸 `example_input.json`이 실제 스키마의 예제다.

| 팀별 열                                  | 의미                                                |
| ---------------------------------------- | --------------------------------------------------- |
| `season_games`, `season_rf`, `season_ra` | 같은 시즌 이전 정규시즌의 경기 수, 득점 합, 실점 합 |
| `recent_games`, `recent_rf`, `recent_ra` | 직전 28일의 경기 수, 득점 합, 실점 합               |

정수는 0 이상이다. 경기 수가 0이면 득점·실점 합에 0 또는 `null`을 허용한다. 경기 수가 양수이면 두 합 모두 필요하다. 최근 집계는 시즌의 부분집합이다. 시즌 첫 경기와 신생·이력 부족 팀은 경기 수에 따라 Train 전체 득점 평균으로 완화한다. 새 팀 ID에 대한 별도 인코딩은 필요 없다. 입력 필드가 빠졌거나 허용 목록 밖의 필드가 있으면 오류를 반환한다. 경기 ID, 날짜, 팀 ID, 분할, 출처, 정답, 실제 선발·라인업은 모델 입력으로 들어가지 않는다.

## 자료와 학습

| 분할       | 사용 범위                          | 인수 DB에서 확인한 정규시즌 | 같은 분할에서 제외하는 포스트시즌 |
| ---------- | ---------------------------------- | --------------------------: | --------------------------------: |
| Train      | 2025-01-01 이전                    |                      14,624 |                               163 |
| Validation | 2025-01-01 이상 및 2026-01-01 미만 |                         720 |                                16 |
| 최종 Test  | 2026-01-01 이상 및 2026-11-26 미만 |                   후속 검증 |                         후속 검증 |

개발 실행은 완료 매니페스트와 정규화한 입력 계약 해시를 확인하고 세 M1 테이블을 경기별로 연결한다. 실제 실행은 포함 기간과 분할별 제외를 평가 보고서에 기록한다. 상위 표준화에서 제외된 원본 사례는 해당 인수 자료의 품질 보고서에서 확인한다. DB 해시는 인수 매니페스트에 기재된 값을 보존한다.

기준 득점은 Train 홈·원정별 평균과 경험 분포를 쓴다. 승무패 기준은 Train의 홈승·무승부·원정승 빈도다. 기준 경험 분포 지지 밖에서 CRPS는 관측 득점까지의 CDF 오차를 합산한다.

공용 득점 예측기는 관점 팀의 득점률과 상대 팀의 실점률을 시즌·최근 창에서 각각 계산한다. 각 비율에 Train 전체 평균과 같은 성적을 낸 가상 경기 수 24(시즌), 12(최근)를 합친다. 네 비율의 평균과 Train 리그 평균의 차이를 0.5점 단위로 구간화하고 범위를 −4부터 4까지로 제한한다. 같은 홈·원정 조건의 Train 분포 150건 상당을 프로필 분포에 더한다. 학습 표본에 없던 프로필은 해당 홈·원정 분포를 사용한다. 이 설정은 Validation 비교 전에 고정한다. 후보 한 개를 등록하고 실제 우열과 상관없이 같은 지표를 공개한다. Validation으로 튜닝하거나 다시 학습하지 않는다.

## 예측 결과와 결합

- `home_pmf`, `away_pmf`의 배열 인덱스는 0부터 시작하는 공식 종료 득점이다. 두 배열의 합은 각각 1이다. `home_expected_runs`, `away_expected_runs`는 각 PMF의 확률 가중 평균이다.
- `representative_score`는 팀별 기대득점을 소수점 절반에서 올림한다. 이 스코어의 승패와 확률이 가장 높은 승무패 범주는 다를 수 있다.
- `result_probabilities`의 `home`, `tie`, `away`는 각각 결합 분포의 홈 득점 초과, 동점, 원정 득점 초과 영역 합이다. 정답도 같은 대소 관계로 공식 기록의 결과와 대조한다.
- `joint`에는 결합 이전 홈·원정 PMF와 동점·비동점 가중치, 정규화 분모가 있다. 득점 조합 `(h, a)`의 결합 확률은 `home_base_pmf[h] × away_base_pmf[a] × 해당 가중치 ÷ normalizer`다. Train에서 가볍게 평활화한 무승부 빈도에 평균 동점확률을 맞춘다. Validation은 독립 결합 평균 동점확률, 조정 후 동점확률, 실제 무승부 건수, 예측 결합 공분산과 잔차 공분산을 남긴다. 양 팀 득점의 의존성은 동점 가중치 한 개로 근사한다.
- 경험 분포에 기하분포 `P(k)=0.5^(k+1)`를 0.001 비율로 섞는다. 정수 범위는 0부터 `max(39, Train 최대 득점)`까지이며 Train 최대 득점 512 초과는 오류다. 범위 밖 기하 꼬리는 버리고 정규화한다. `tail`은 결합 꼬리 질량 상한과 팀별 기대득점 오차 상한을 제공한다. 각 팀이 버리는 기하 혼합 질량은 `0.001 × 0.5^(상한+1)`이다. 결합 질량 상한은 양 팀 질량의 합에 큰 셀 가중치와 작은 셀 가중치의 비를 곱한다. 확률 합 허용 오차는 `1e-12`다.
- 공식 종료 득점에는 자료에 포함된 연장과 공식 무승부가 반영된다. 9이닝 종료 득점 및 경기 중 스코어를 따로 추정하는 기능은 범위 밖이다. 여러 시즌의 정규시즌 규칙을 하나의 동점 가중치로 근사하므로 특정 시즌의 무승부 규칙 변경, 단축·중단·서스펜디드 경기, 포스트시즌에는 별도 적용 검증이 필요하다.

정규시즌 1위와 한국시리즈 우승 전망을 계산하는 후속 시뮬레이션은 일정·팀 이력의 기준 시점을 정하고 정규시즌의 점수 쌍을 재현해야 한다. 점수 쌍을 뽑을 때 `joint` 셀을 사용한다. 결과만 필요한 계산에는 `result_probabilities`를 그대로 쓴다. 한국시리즈 전망에는 별도로 검증한 포스트시즌 점수 모형 적용 범위와 대회 규칙이 필요하다.

## 기록과 재실행

`evaluation.json`의 득점 지표는 홈·원정과 두 팀 행을 합친 표본에서 계산한다. 그 통합 RMSE는 전체 팀 행 제곱오차의 평균에 제곱근을 적용한다. 분포 지표는 비음수 정수 전체에 대한 이산 CRPS다. 승무패 Log loss는 경기별 실제 범주의 확률을 최소 `1e-15`로 제한한 뒤 음의 자연로그를 평균한다. Brier score는 경기별 3개 범주의 확률 제곱오차 합을 평균한다. 보정 표의 왼쪽 경계는 포함하며 마지막 구간만 1을 포함한다. 빈 구간은 건수 0과 `null`을 남긴다. `candidate_minus_baseline`의 음수는 해당 오류 지표가 감소했다는 뜻이다.

실행은 Python 3.12의 표준 라이브러리만 쓴다. 기존 저장 경로 설정으로 모델과 결과를 별도 생성한다. 기본 위치는 `models/m1/<실행 ID>/model.json` 및 `results/m1/<실행 ID>/` 아래의 `evaluation.json`, `example_input.json`, `example_prediction.json`이다. 예측 계약 버전은 `m1-final-score-v1`이다. 모델에는 입력 열 순서, 학습 방법, 출처와 버전, 모듈 해시, 런타임, 설정 시드, 분할별 표본, 재현 인자가 기록된다. 학습 계산은 결정적이며 실행 ID는 저장 폴더 충돌을 방지한다. 저장 자산은 읽어 다시 예측해 확인한 뒤 게시한다. JSON 또는 스키마·무결성 오류는 종료 코드 2로 보고한다. 완료된 예제 입력·출력에는 해당 경기의 정답이 들어가지 않는다.

```powershell
Set-Location -LiteralPath 'D:/Programming/kbo-insight-ai'
$kboPython = 'D:/Programming/kbo-insight-ai/.venv/Scripts/python.exe'
& $kboPython -X utf8 -B -m src.models.game_outcome train --run-id 259b38decaac4ed68dd5a596cfbe4849
```


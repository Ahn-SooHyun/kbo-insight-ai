## 1. 목적·지원 범위

### 1.1 문제 정의

공식 종료 득점의 공동 분포를 통해 승무패와 대표 스코어를 일관되게 계산하는 경기 단위 예측 문제다. 두 개의 독립 승패·득점 모델을 운영하지 않는다.

M1은 정규시즌 경기 시작 전에 해당 날짜보다 이른 같은 시즌 정규시즌 종료 경기 이력을 받아 공식 종료 득점을 예측한다. 경기 날짜는 KST 기준이다. 최근 창은 직전 28일이며 경기일 당일의 더블헤더 두 경기 모두 이력에서 제외한다. 과거 일정의 당시 공개 시각은 복원되지 않았다. 운영 호출자는 경기 시작 전 확인된 대진과 당시 이용 가능한 완료·공개 기록으로 JSON을 만들고 실행 시각과 입력의 출처를 함께 보관한다.

### 1.2 운영 상태

Issue #17의 구현 및 검증은 기존 수용·병합 이력에 근거한다. 이 문서는 정규시즌 기본 모델만 설명하며 포스트시즌 성능·최종 Test를 확정하지 않는다.

## 3. 입력·전처리

### 3.1 입력 스키마

입력 JSON은 `competition` 값 `regular`와 홈·원정 각각 아래 6개 열을 받는다. 접두사는 `home_`, `away_`다. DB에서 내보낸 `example_input.json`이 실제 스키마의 예제다.

| 팀별 열                                  | 의미                                                |
| ---------------------------------------- | --------------------------------------------------- |
| `season_games`, `season_rf`, `season_ra` | 같은 시즌 이전 정규시즌의 경기 수, 득점 합, 실점 합 |
| `recent_games`, `recent_rf`, `recent_ra` | 직전 28일의 경기 수, 득점 합, 실점 합               |

정수는 0 이상이다. 경기 수가 0이면 득점·실점 합에 0 또는 `null`을 허용한다. 경기 수가 양수이면 두 합 모두 필요하다. 최근 집계는 시즌의 부분집합이다. 시즌 첫 경기와 신생·이력 부족 팀은 경기 수에 따라 Train 전체 득점 평균으로 완화한다. 새 팀 ID에 대한 별도 인코딩은 필요 없다. 입력 필드가 빠졌거나 허용 목록 밖의 필드가 있으면 오류를 반환한다. 경기 ID, 날짜, 팀 ID, 분할, 출처, 정답, 실제 선발·라인업은 모델 입력으로 들어가지 않는다.

### 3.2 파생 변수

팀·상대 관점의 득실점률, 시즌 및 최근 창을 사용한다. 구체적 수축 산식은 5절과 일치한다. 선수·투구·라인업 자료는 현재 기본 모델에서 사용하지 않는다.

## 4. 정답·출력 계약

### 4.1 정답 의미

공식 종료 홈 득점과 원정 득점, 그 대소 관계로 결정하는 홈승/무승부/원정승이 정답이다.

### 4.2 출력 및 불변 조건

- `home_pmf`, `away_pmf`의 배열 인덱스는 0부터 시작하는 공식 종료 득점이다. 두 배열의 합은 각각 1이다. `home_expected_runs`, `away_expected_runs`는 각 PMF의 확률 가중 평균이다.
- `representative_score`는 팀별 기대득점을 소수점 절반에서 올림한다. 이 스코어의 승패와 확률이 가장 높은 승무패 범주는 다를 수 있다.
- `result_probabilities`의 `home`, `tie`, `away`는 각각 결합 분포의 홈 득점 초과, 동점, 원정 득점 초과 영역 합이다. 정답도 같은 대소 관계로 공식 기록의 결과와 대조한다.
- `joint`에는 결합 이전 홈·원정 PMF와 동점·비동점 가중치, 정규화 분모가 있다. 득점 조합 `(h, a)`의 결합 확률은 `home_base_pmf[h] × away_base_pmf[a] × 해당 가중치 ÷ normalizer`다. Train에서 가볍게 평활화한 무승부 빈도에 평균 동점확률을 맞춘다. Validation은 독립 결합 평균 동점확률, 조정 후 동점확률, 실제 무승부 건수, 예측 결합 공분산과 잔차 공분산을 남긴다. 양 팀 득점의 의존성은 동점 가중치 한 개로 근사한다.
- 경험 분포에 기하분포 `P(k)=0.5^(k+1)`를 0.001 비율로 섞는다. 정수 범위는 0부터 `max(39, Train 최대 득점)`까지이며 Train 최대 득점 512 초과는 오류다. 범위 밖 기하 꼬리는 버리고 정규화한다. `tail`은 결합 꼬리 질량 상한과 팀별 기대득점 오차 상한을 제공한다. 각 팀이 버리는 기하 혼합 질량은 `0.001 × 0.5^(상한+1)`이다. 결합 질량 상한은 양 팀 질량의 합에 큰 셀 가중치와 작은 셀 가중치의 비를 곱한다. 확률 합 허용 오차는 `1e-12`다.
- 공식 종료 득점에는 자료에 포함된 연장과 공식 무승부가 반영된다. 9이닝 종료 득점 및 경기 중 스코어를 따로 추정하는 기능은 범위 밖이다. 여러 시즌의 정규시즌 규칙을 하나의 동점 가중치로 근사하므로 특정 시즌의 무승부 규칙 변경, 단축·중단·서스펜디드 경기, 포스트시즌에는 별도 적용 검증이 필요하다.

## 5. 모델·학습·선정

### 5.1 기준과 운영 후보

기준 득점은 Train 홈·원정별 평균과 경험 분포를 쓴다. 승무패 기준은 Train의 홈승·무승부·원정승 빈도다. 기준 경험 분포 지지 밖에서 CRPS는 관측 득점까지의 CDF 오차를 합산한다.

공용 득점 예측기는 관점 팀의 득점률과 상대 팀의 실점률을 시즌·최근 창에서 각각 계산한다. 각 비율에 Train 전체 평균과 같은 성적을 낸 가상 경기 수 24(시즌), 12(최근)를 합친다. 네 비율의 평균과 Train 리그 평균의 차이를 0.5점 단위로 구간화하고 범위를 −4부터 4까지로 제한한다. 같은 홈·원정 조건의 Train 분포 150건 상당을 프로필 분포에 더한다. 학습 표본에 없던 프로필은 해당 홈·원정 분포를 사용한다. 이 설정은 Validation 비교 전에 고정한다. 후보 한 개를 등록하고 실제 우열과 상관없이 같은 지표를 공개한다. Validation으로 튜닝하거나 다시 학습하지 않는다.

### 5.2 실제 수학적 구조

Train 경기 수를 $N$, 양 팀 공식 종료 득점의 전체 평균을 $\mu$라고 한다. 팀의 과거 경기 수 $g$, 해당 득점 또는 실점의 합 $r$, 의사 경기 수 $\alpha$에 대해

$$
\widetilde{r}(g,r;\alpha)=\frac{r+\alpha\mu}{g+\alpha},\qquad \alpha\in\{24,12\}.
$$

팀 득점률과 상대 실점률의 시즌 및 최근 28일 값 네 개를 평균한 $v$로 구간 $z=\operatorname{clip}(\lfloor(v-\mu)/0.5+0.5\rfloor,-4,4)$를 결정한다. 같은 홈·원정 조건의 득점 빈도 $c_k$, 해당 프로필 득점 빈도 $n_k$로부터 $q_k=(n_k+150c_k/\sum_j c_j)/(\sum_j n_j+150)$를 얻는다. 미출현 프로필은 홈·원정 빈도 자체로 후퇴한다. 이후 0.001의 기하분포 혼합을 적용하고 유한 지지에서 정규화한다.

독립 결합의 동점 질량을 $d=\sum_k p_H(k)p_A(k)$라 하면, 동점 가중치 $w$를 적용한 동점 확률은 $wd/[wd+(1-w)(1-d)]$다. `fit_tie_weight`는 Train에서 실제 무승부의 평활화 빈도 $(n_{tie}+0.5)/(N+1)$와 평균 동점확률을 맞추기 위해 [0,1]에서 48회 이분 탐색을 수행한다. 홈·원정은 같은 공용 모델을 재사용하므로 독립 운영 예측기 수는 1개다.

### 5.3 비교 후보 및 설정

포아송 후보의 $\eta=\beta^Tx$, $\lambda=\exp(\eta)$이며, Train 팀 행에 대해 상수항을 제외한 목적함수는 $N_t^{-1}\sum_i(\exp(\eta_i)-y_i\eta_i)+0.01\|\beta\|_2^2/2$다. 6개 계수(절편, 홈 여부, 네 가지 득실점률)를 학습하며, 정규화에는 절편도 포함된다. 4개 비율은 Train 평균을 중심으로 나누고 ±2로 제한한다. `poisson.py`는 Newton 방향, 최대 25회 반복, 각 단계 최대 25회 선 탐색, 기울기 최대 절댓값 허용 오차 1e-7을 사용한다. 추론 득점률은 0.05~40, 지지 상한은 최소 128로 제한하고 포아송 꼬리 오차 상한을 기록한다. 단순 선형 회귀와 달리 음수 득점 평균을 내지 않는다. 설정은 실제 소스의 상수이며 최적값 또는 전수 탐색 결과를 의미하지 않는다.

### 5.4 시즌별 백테스트 및 모델 결정

2023·2024·2025 정규시즌을 각각 검증 시즌으로 두고 매번 그 시즌보다 이른 경기만 학습에 쓴다. 검증 경기는 시즌별 720경기다. 기본 실행은 홈·원정별 경험 분포에 동점 보정을 적용한 `venue_only`와 주 예측 방식인 `profile_histogram`을 비교한다. 이 백테스트의 기준과 단일 Validation의 득점·결과 빈도 기준은 산식이 다르다.

`--include-poisson`을 지정하면 홈 여부와 기존 시즌·최근 득실점 변수를 쓰는 L2 정규화 포아송 회귀를 비교에 추가한다. 학습·동점 보정은 각 검증 시즌 이전의 경기만 사용한다. 포아송 분포는 지지 범위 밖 질량과 기대득점 오차의 상한을 기록한다. 백테스트는 후보별 지표와 학습·검증 구간을 `results/m1_backtest/<실행 ID>/evaluation.json`에 저장한다. 모델 자산은 `train` 명령에서 생성한다.

운영 예측 방식은 `profile_histogram`이다. 단일 Validation에서는 고정 구간별 경험 분포를 비교했고, 시즌별 백테스트의 포아송 회귀는 선택 비교 후보로 평가했다. 확률 분포의 품질을 후속 시뮬레이션에서 재사용해야 하므로 MAE 하나만으로 운영 모델을 변경하지 않는다.

| 실제값과 예측값 차이·손실 최소화               | 직접 적용 및 비교 실험 | 득점의 MAE·RMSE를 기록하고, `poisson.py` 비교 후보에서 평균 음의 로그우도와 L2 벌점을 최소화한다. 주 예측기는 구간별 경험 분포이며 포아송 회귀는 실험 후보로만 사용한다. |
| 일반화·과적합 통제 원리                        | 문제에 맞게 변형       | 희소한 팀 이력과 프로필의 확률 분포를 Train 기준으로 완화한다. 검증 이전에 고정한 설정을 그대로 비교한다.                                                                |

| 확장 원리                                     | 적용과 이유                                                                                  | 검증 및 제한                                                                                                       |
| --------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |

## 7. 평가 지표·실제 결과

### 7.1 지표 정의와 평가 분모

`evaluation.json`의 득점 지표는 홈·원정과 두 팀 행을 합친 표본에서 계산한다. 그 통합 RMSE는 전체 팀 행 제곱오차의 평균에 제곱근을 적용한다. 분포 지표는 비음수 정수 전체에 대한 이산 CRPS다. 승무패 Log loss는 경기별 실제 범주의 확률을 최소 `1e-15`로 제한한 뒤 음의 자연로그를 평균한다. Brier score는 경기별 3개 범주의 확률 제곱오차 합을 평균한다. 보정 표의 왼쪽 경계는 포함하며 마지막 구간만 1을 포함한다. 빈 구간은 건수 0과 `null`을 남긴다. `candidate_minus_baseline`의 음수는 해당 오류 지표가 감소했다는 뜻이다.

- MAE = 평균 `|y - E[Y]|`, RMSE = 전체 팀 행의 제곱오차 평균의 제곱근. 단일 Validation 720경기는 통합 득점 평가에서 1,440개 팀 행이다.
- 이산 CRPS = 비음수 정수 $k$에 대한 $(F(k)-\mathbf{1}\{y\le k\})^2$의 합. 실제 득점이 모델 지지 범위 밖이어도 그 관측값까지 평가한다.
- Log loss = 경기별 $-\log(\max(p_{y},10^{-15}))$의 평균. Brier = 3개 승무패 확률과 원-핫 정답의 제곱오차 합을 경기별 평균한다. 모두 낮을수록 좋다.
- 보정 표는 확률 구간의 표본 수·평균 예측 확률·실제 발생 비율을 함께 확인하는 진단이다. 평균 무승부 오차와 개별 경기의 분포 품질은 구분한다.

### 7.2 확인된 개발 결과

인수 데이터의 DB SHA-256이 매니페스트와 일치했다. 학습에는 정규시즌 14,624경기(2001-04-05~2024-10-01), 단일 Validation에는 720경기(2025-03-22~2025-10-04)를 사용했다. 같은 분할에서 포스트시즌은 각각 163경기와 16경기를 제외했다. 2026년 최종 Test는 후속 종합 검증에 인계한다.

| 통합 득점 RMSE         | 3.38287 |   3.34147 |

## 8. 구현·산출물·재현성

### 8.1 구현 책임

| 위치                                         | 책임                                                |
| -------------------------------------------- | --------------------------------------------------- |
| `src/models/game_outcome/model.py`           | 입력 검증, 공용 득점 예측기 학습, 결합 분포 및 예측 |
| `src/models/game_outcome/__main__.py`        | 정규시즌 표본 연결, 학습·평가 명령, 자산 저장·로딩  |
| `src/models/game_outcome/backtest.py`        | 시즌별 학습 창, 공통 표본 비교, 평가 결과 저장      |
| `src/models/game_outcome/poisson.py`         | 비교용 포아송 회귀와 득점 분포                      |

학습 자산과 평가 결과는 프로젝트 설정의 `models_dir`, `results_dir`에 저장한다. 기본값은 저장소 루트의 `models/`와 `results/`다.

### 8.2 자산과 재현

실행은 Python 3.12의 표준 라이브러리만 쓴다. 기존 저장 경로 설정으로 모델과 결과를 별도 생성한다. 기본 위치는 `models/m1/<실행 ID>/model.json` 및 `results/m1/<실행 ID>/` 아래의 `evaluation.json`, `example_input.json`, `example_prediction.json`이다. 예측 계약 버전은 `m1-final-score-v1`이다. 모델에는 입력 열 순서, 학습 방법, 출처와 버전, 모듈 해시, 런타임, 설정 시드, 분할별 표본, 재현 인자가 기록된다. 학습 계산은 결정적이며 실행 ID는 저장 폴더 충돌을 방지한다. 저장 자산은 읽어 다시 예측해 확인한 뒤 게시한다. JSON 또는 스키마·무결성 오류는 종료 코드 2로 보고한다. 완료된 예제 입력·출력에는 해당 경기의 정답이 들어가지 않는다.

학습·백테스트·평가·추론의 실행 ID를 혼동하지 않는다. 기존 자산은 덮어쓰지 않는다.

## 9. 검증·한계·후속 연결

### 9.1 검증 및 실패 처리

- Issue #17의 기존 검증에서 전체 143개 테스트 통과, 실제 Train/Validation 학습 및 저장 자산의 독립 프로세스 예측 동일성을 확인했다. 시즌별 백테스트와 포아송 후보 포함 백테스트의 결과를 대조했다. 현재 전체 189개 테스트 기록은 M2까지 추가된 별도 로컬 실행 기록으로, M1 단독 당시 개수와 구분한다.
- 입력 허용 목록, 정수 및 최근/시즌 부분집합 제약, 확률 합·비음수, 학습과 평가의 시간 경계, 저장 모델 무결성 검사에 실패하면 값을 임의 보정해 결과를 발행하지 않는다. `model.py`, `__main__.py`, `tests/models/test_game_outcome.py` 및 `test_game_outcome_backtest.py`의 계약을 따른다.
- 원본의 과거 공개 시각이 완전히 복원되지 않았으므로 당시 실제 발표된 라인업·선발의 완전한 재현을 주장하지 않는다. 공식 종료 득점과 9이닝 종료 득점을 혼동하지 않는다.

### 9.2 해석·적용 제한 및 후속 연결

정규시즌 1위와 한국시리즈 우승 전망을 계산하는 후속 시뮬레이션은 일정·팀 이력의 기준 시점을 정하고 정규시즌의 점수 쌍을 재현해야 한다. 점수 쌍을 뽑을 때 `joint` 셀을 사용한다. 결과만 필요한 계산에는 `result_probabilities`를 그대로 쓴다. 한국시리즈 전망에는 별도로 검증한 포스트시즌 점수 모형 적용 범위와 대회 규칙이 필요하다.

- 무승부 관측 비율 3.06% 대비 예측 평균 2.07%는 약 0.99%p 과소 추정이다. 개선 지표에도 특정 범주 보정과 양 팀 득점 의존성의 한계가 있다.
- 2026년 최종 Test와 포스트시즌의 일반화 성능, 전체 시즌 시뮬레이션의 순위·우승 정확도는 후속 검증에 인계한다. 테스트 결과를 보고 현재 후보를 다시 선택하지 않는다.

## 10. 실행 명령

아래 PowerShell 블록 전체를 붙여 넣는다. 전체 테스트와 실데이터 학습·평가를 실행하고, 새 프로세스에서 계산한 예측을 저장 JSON과 비교한다. 이후 기본 백테스트와 포아송 후보 포함 백테스트를 순서대로 실행한다. 어느 단계에서든 오류가 발생하면 블록이 중단된다.

```powershell
& {
    Set-Location -LiteralPath 'D:/Programming/kbo-insight-ai' -ErrorAction Stop
    $m1Python = 'D:/Programming/kbo-insight-ai/.venv/Scripts/python.exe'
    $m1DataRun = '259b38decaac4ed68dd5a596cfbe4849'

    & $m1Python -X utf8 -B -m unittest discover -s tests
    if ($LASTEXITCODE -ne 0) { throw '전체 테스트 실패' }

    $m1Train = & $m1Python -X utf8 -B -m src.models.game_outcome train --run-id $m1DataRun
    if ($LASTEXITCODE -ne 0) { throw 'M1 학습·평가 실패' }
    $m1Report = ($m1Train -join [Environment]::NewLine) | ConvertFrom-Json -ErrorAction Stop
    $m1Train

    $m1Prediction = & $m1Python -X utf8 -B -m src.models.game_outcome predict --asset $m1Report.paths.model --input $m1Report.paths.input
    if ($LASTEXITCODE -ne 0) { throw 'M1 저장 모델 예측 실패' }

    $m1Prediction | & $m1Python -X utf8 -B -c 'import json, sys; from pathlib import Path; expected = json.loads(Path(sys.argv[1]).read_bytes()); sys.exit(0 if json.load(sys.stdin) == expected else 1)' $m1Report.paths.prediction
    if ($LASTEXITCODE -ne 0) { throw 'M1 저장 예측과 재실행 예측 불일치' }
    Write-Output 'M1 저장 모델 예측 재현 성공'

    & $m1Python -X utf8 -B -m src.models.game_outcome.backtest --run-id $m1DataRun
    if ($LASTEXITCODE -ne 0) { throw 'M1 기본 백테스트 실패' }

    & $m1Python -X utf8 -B -m src.models.game_outcome.backtest --run-id $m1DataRun --include-poisson
    if ($LASTEXITCODE -ne 0) { throw 'M1 포아송 후보 포함 백테스트 실패' }
}
```

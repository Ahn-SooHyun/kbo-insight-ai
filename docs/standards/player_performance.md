## 1. 목적·지원 범위

선수의 출전량과 누적 기록을 함께 예측하는 지도학습 다중 출력 회귀 문제다. 타자와 투수의 기록 정의가 다르므로 역할별 주 예측기 하나씩, 총 두 개를 목표로 한다. 공동 회귀 트리는 여러 기간·기록의 분기 구조와 잎 벡터를 공유한다. 과거 기록 예측기는 Train 평균 등 기준 통계를 이용해 모든 기간·기록을 계산한다. 잔차 트리의 고정 축소 계수나 기준 통계는 별도 학습된 독립 회귀기의 앙상블이 아니다. 비교 후보는 운영 예측기로 중복 저장하지 않는다. 두 역할의 구현·선정·수용 완료 시 기존 주 예측기 네 개와 합쳐 총 여섯 개다.

예측 모집단은 기준 월요일 이전에 같은 시즌의 관측 기록이 있는 선수·역할이다. 정규시즌 경기만 대상이며 포스트시즌, 공식 등록 명단 전체, 미래 이적, 비공개 부상 및 감독 의도는 추정하지 않는다. 정규시즌 종료 후 기준 시점은 지원 대상 밖이다. 시즌 전망은 현재까지 확인된 누적과 잔여 예측을 합산한다. 자료 사용은 승인된 비영리 대학 과제의 로컬 평가에 한정하며 원본·모델·결과를 공개 재배포하지 않는다.

## 3. 입력·전처리

기준은 월요일 00:00 KST이며 당일 기록을 모두 제외한다. `sample_id`, `player_id`, `role`, `season`, `sample_date`, `last_observed_date`로 대상과 시점을 검증한다. `days_since_observed`는 날짜 차이와 일치해야 한다. `known_team_id`, `prior_rejected`, 역할별 `season_*`, `recent28_*`를 검증한다. `season_active=true`는 호출자가 기준 시점의 정규시즌 진행 상태를 확인했다는 입력 계약이다. 독립 추론은 호출자가 제공한 기록·증거의 진위를 외부 원천에서 인증하지 않는다.

트리 입력은 고정 달력 기준 3월 1일 이후 경과일(최소 1일), 마지막 관측 경과일, 제외 이력 수, 팀 식별 불명 표지, 시즌 및 최근 28일 기록의 달력 일수당 관측량이다. 시즌 기록 환산 분모는 경과일과 28일 중 큰 값이다. 실제 개막일이나 경기 수를 뜻하지 않는다. 미관측 수치는 비음수 특징과 구별되는 -1 표지로 나타낸다. 선수 ID·실제 팀 ID 자체, 미래 팀, 실제 미래 출전량, 미래 시즌 종료일, 정답·사후 품질 정보는 트리 특징으로 쓰지 않는다.

입력은 최근 기록이 시즌 누적을 초과하는지, 날짜·식별자·기록 구성 및 허용 필드를 검사한다. 현재 누적은 `current_counts`, `current_scope`, `current_as_of`로 별도 제공할 수 있다. `current_scope=caller_verified`는 호출자가 동일 선수·역할·기간·기록 정의의 누적을 확인한 경우에만 사용하며 `current_as_of`는 기준 월요일(종료 제외 경계)과 같아야 한다. 별도 누적 없이 시즌 관측 Count 전체가 있으면 `observed_pbp`로만 제공한다. 기록 누락 시 최종 전망은 unavailable이다.

사전 확인된 정규시즌 종료 경계가 있는 별도 시나리오는 `known_end_exclusive`, `known_end_as_of`, `known_end_source`를 함께 제공한다. 증거 날짜는 기준 월요일 이전, 종료 제외 경계는 기준일 이후여야 한다. 실제 역사적 종료 정답을 이 필드에 넣어 개발 성능을 높이지 않는다. 별도 시나리오의 구간은 보정하지 않았으므로 null과 사유를 반환한다.

## 4. 정답·출력 계약

| 역할 | 기간별 Count                                                          | 공동 출력 차원 |
| ---- | --------------------------------------------------------------------- | -------------: |
| 타자 | games, pa, ab, hits, home_runs, walks, hbp, strikeouts                |             24 |
| 투수 | games, bf, outs, pitches, ab, hits, home_runs, walks, hbp, strikeouts |             30 |

기간은 `[t,t+7일)`, `[t,t+28일)`, `t`부터 정규시즌 공식 종료일까지다. 종료일은 DB에서 종료 제외 경계로 표현한다. 고정 기간에 시즌 종료 이후 날짜가 있어도 포스트시즌 기록을 포함하지 않는다.

`usable`, `status`, `window_start`, `window_end`, `observed_through_exclusive`, `ready_date`, 기록별 NULL을 확인한다. `valid_observed` 및 `zero_observed`인 정답 중 논리적 시점과 분할 경계를 충족한 기록만 사용한다. 실제 0과 부분 관측·미관측을 구분한다. `observed_*`는 완전 정답의 대체값이 아니다. 같은 선수·역할의 기간별 유효 정답을 연결하며 시즌 종료로 포함 범위가 동일한 정답은 같은 Count이어야 한다.

출력은 비음수 실수 기대 Count이다. 정수 반올림을 강제하지 않는다. PA/BF, AB, BB, HBP, H, HR, SO의 구성 관계와 7일 ≤ 28일 ≤ 잔여 정규시즌 Count를 검사한다. 아웃과 투구 수는 주루 사건·무투구 타석 때문에 단순 BF 상하한을 가정하지 않는다. 사전 종료일이 없는 경우 실제 사후 종료일을 특징이나 후처리에 전달하지 않으며, 실제 종료로 포함 범위가 동일해진 관측 표본의 예측 차이는 평가 진단에 남긴다.

사전 종료일을 제공한 시나리오에서는 실제 알려진 기간과 학습 종료 통계의 환산 일수를 비교해 트리 출력을 단축할 수 있다. 보정되지 않은 별도 시나리오이며, 종료 제외 경계가 7일 이내이면 세 기간의 Count가 동일하고, 28일 이내이면 28일과 잔여 Count가 동일하도록 한다. 공식 종료가 확인되지 않은 경우 예상 종료 통계를 사실로 해석하거나 실제 종료일 일치까지 보장하지 않는다.

`hit_rate=hits/ab`, `strikeout_rate=strikeouts/pa`(타자) 또는 `/bf`(투수)로 계산한다. 분모가 0이면 null과 `zero_denominator`를 반환한다. 투구 이닝은 `outs/3`의 실수이며 야구식 .1/.2 아웃 표기가 아니다. ERA, SLG, OPS 등 정의·구성 기록이 불충분한 통계는 지원하지 않는다. 시즌 전망은 현재 누적과 잔여 Count를 먼저 합산한 뒤 비율을 재계산한다. 관측 PBP 누적을 사용하면 공식 최종 기록이 아닌 잠정 관측 기준 전망으로 표시한다.

## 5. 모델·학습·선정

### 5.1 기준 모델과 과거 기록 개선 후보

Train의 유효 7일 Count에서 달력 일수당 역할 평균을 계산한다. 개인 시즌 기록의 일수당 집계와 최근 28일 기록의 일수당 집계를 장기·단기 기록률로 사용한다. 시즌 기록이 없으면 Train 평균, 최근 기록이 없으면 장기 기록률로 후퇴한다. 기존 기준 `history_baseline`의 단기 가중치는 0.7, 장기 0.3이다. 기존 기준의 사전 입력과 개발 평가 계산은 유지한다.

추가 후보 `history_balanced_50`(단기 0.5)과 `history_recent_90`(단기 0.9)은 관측 거절 이력이 있고 채택된 경기 수가 0인 경우 Train 평균 또는 장기 기록률로 후퇴한다. 역사적 채택 경기 수가 0이라는 사실을 공식 미출전·미관측 정답 0으로 바꾸지 않는다. 두 후보는 과거 기록 기반 통계 예측기이며 트리를 학습한 머신러닝 후보로 분류하지 않는다.

잔여 기간 환산은 학습 시즌의 확인된 종료 제외 경계와 3월 1일 기준 사이의 평균 경과일을 사용하고 최소 7일을 유지한다. 7일·28일은 예상 잔여 기간과 해당 기간 중 작은 값이다. 사전 확인 종료일이 있으면 이 정보를 별도 시나리오에서만 사용한다. 실제 미래 일정·시즌 종료를 아는 것이 아니다.

### 5.2 공동 회귀 트리와 후보 사전

공동 출력마다 Train 평균 Count와 1 중 큰 값 `s_j`를 정규화 척도로 사용한다. 잔차 후보는 `r_ij=(y_ij-b_ij)/s_j`를 학습하며, 직접 후보는 `y_ij/s_j`를 학습한다. 기록별 유효 정답 마스크는 해당 출력의 학습·분기 손실에만 적용한다. 미관측 출력을 0으로 채우지 않는다.

하나의 트리가 모든 출력의 분기를 공유한다. 각 출력의 전체 Train 관측 수 역수를 분기 손실 가중치로 적용한다. 양쪽 자식 노드에서 지원되는 기록의 제곱오차 감소를 합산해 공통 분기를 선정한다. 분기 후보는 Train 특징 분위수 20·40·60·80%, 최소 리프 40행, 출력별 최소 자식 지원 8, 최소 이득 1e-12, 상위 노드 수축 상수 10으로 고정한다. 지원 부족 출력은 상위 노드 값으로 후퇴한다.

| 계열             | 후보                                                                                                            | 개수 |
| ---------------- | --------------------------------------------------------------------------------------------------------------- | ---: |
| 과거 기록        | `history_baseline`, `history_balanced_50`, `history_recent_90`                                                  |    3 |
| 잔차 트리 깊이 2 | `joint_residual_tree_depth_2_shrink_25`, `joint_residual_tree_depth_2_shrink_50`, `joint_residual_tree_depth_2` |    3 |
| 잔차 트리 깊이 4 | `joint_residual_tree_depth_4_shrink_25`, `joint_residual_tree_depth_4_shrink_50`, `joint_residual_tree_depth_4` |    3 |
| 직접 트리        | `joint_direct_tree_depth_2`, `joint_direct_tree_depth_4`                                                        |    2 |

잔차 후보는 기준 Count에 `alpha*s_j*r_hat`을 더하며 alpha는 0.25, 0.50, 1.00이다. 동일 깊이 잔차 후보의 트리 학습 결과를 재사용한다. 직접 후보는 `s_j*y_hat_normalized`를 사용한다. 이후 비음수·구성 관계를 보존하는 기간별 증가량 후처리를 적용한다. 하나의 트리와 고정 변환으로 구성되며 복수의 독립 회귀기를 보팅하거나 결합하지 않는다.

### 5.3 시간순 개발과 예측 구간

2024-01-01 이전에 정답이 완료된 2023 표본으로 선행 후보를 학습한다. 2024년 기준 표본 중 2025-01-01까지 관측이 완료된 유효 기록에서 절대 잔차를 계산한다. 기록별 90% 목표 구간 반경은 정렬 잔차의 `min(n,ceil((n+1)*0.90))`번째 값이다. 최소 20행, 서로 다른 선수 5명, 기준 주 3개를 충족하지 못하면 지원 부족으로 null을 반환한다. 구간은 `[max(0,point-radius),point+radius]`로 표시한다. 시즌 전망 구간은 현재 누적을 더하며 현재 누적 자체의 측정 불확실성은 반영하지 않는다.

최종 후보는 2023~2024 Train 전체로 재적합하고 2024년 시간순 잔차 반경을 전이한다. 2025 Validation에서 모든 후보를 같은 기록별 마스크와 동일 척도로 비교한다. 2025년은 v1 실험에서 이미 관찰한 개발 구간이며 추가 후보 선택에도 사용하므로 독립 평가가 아니다. 90%는 목표 포함 수준이며, 동일 선수·기간 중첩 및 전체 Train 재적합 때문에 실제 모델의 90% 포함을 보장하지 않는다.

### 5.4 운영 선정 규칙

기준 모델 대비 정규화 macro MAE가 1e-12보다 크게 감소하고 정규화 macro RMSE가 1e-12 허용 오차 내에서 악화하지 않는 후보를 채택 가능 대상으로 한다. 채택 가능 후보 중 MAE, RMSE, 고정 후보 순서로 선정한다. 통과 후보가 없으면 `history_baseline`을 유지한다. `baseline_retained`, `improved_joint_tree`, `improved_history_predictor` 상태를 구분한다. 기준 유지 또는 과거 기록 후보의 선정은 학습형 트리의 우월성을 입증하지 않는다. 학습형 후보가 선정되지 않을 경우 하위 검토에서 운영 방식과 과제 모델 요건을 확인한다. 기준 대비 악화한 후보·기록도 삭제하지 않는다.

## 7. 평가 지표·실제 결과

### 7.1 지표 및 공통 표본

기간·기록별 MAE, RMSE, 평균 편향, 실제 평균, 유효 행·선수·기준 주 수를 계산한다. 정규화 macro MAE/RMSE는 Train 평균 기반 척도의 기록별 정규화 오차를 산술 평균한다. 모든 Count 후보의 유효 정답 마스크·출력 수·척도를 대조한다. 시즌·기준 주·사전 알려진 팀별 정규화 오차와 관측 위험을 별도로 남긴다. 기록 셀 수·행 수·선수 수를 서로 독립인 관측 수로 해석하지 않는다.

구간 지표는 목표 포함 수준, 실제 포함 건수/유효 구간 건수, 평균 폭, 구간 미지원 건수다. 2024년 구간 적합 표본의 포함률은 적합 자체의 진단이고 2025년 포함률과 다르다. 주변 Count 구간만 제공하며 기록 간 동시 포함이나 비율 구간은 지원하지 않는다.

비율은 실제 분모 양수·정답 유효 행과 후보별 예측 분모 양수 행을 구분한다. 7일은 Count에서 재계산한 진단값이다. 28일·잔여는 저장 비율과 해당 분모를 대조한다. `common_ratio_comparison.all_candidates_common`은 모든 후보의 예측 분모가 양수인 공통 행, `baseline_pairwise_common`은 기준과 개별 후보 모두의 분모가 양수인 공통 행이다. 정답 유효 수, 후보별 예측 분모 0 수, 공통 행·분모 합 및 공통 표본 오차를 제공한다. 공통 행이 없으면 오차는 null이다. 후보 자체의 유효 행 평가도 함께 남긴다.

`selected_output_audit`은 모든 Validation 입력의 기간별 Count·분모·구간·시즌 전망을 검사한다. 시즌 평가의 정답은 관측 PBP 현재 누적과 유효 잔여 정답의 합으로 만든 잠정 기록이며 공식 최종 성적이 아니다. 사전 종료일 1·7·14·28·35일 합성 시나리오는 실제 미래 종료 정답을 입력하지 않는 별도 계약 검증이다. 실제 종료로 동일해진 기간의 예측 차이는 `actual_end_equality_diagnostic`에 보고한다.

Python 3.12와 기존 설정을 사용한다. 신규 외부 실행 의존성·GPU가 필요하지 않다. 난수 없는 결정적 트리이며 프로젝트 Seed를 기록한다. 후보의 선행 학습과 전체 Train 재적합 시간을 기록한다. 선정된 자산은 역할별 별도 실행 ID로 저장한다. 기존 자산을 덮어쓰지 않는다.

`models/m3/<실행ID>/model.json`은 선정된 예측기 하나, 기준 통계, 선택된 트리(해당 시), 입력·출력 사전, 구간 반경, 설정, 자료·코드 지문, 런타임을 포함한다. `results/m3/<실행ID>/`에는 `evaluation.json`, `example_input.json`, `example_prediction.json`, `scenario_input.json`, `scenario_prediction.json`, `manifest.json`을 저장한다. 마지막 두 시나리오 자료는 실제 종료일 대신 합성 14일 종료 경계를 사용한 독립 재현용 예시다. 완료 매니페스트는 모든 파일과 내부 재현이 완료된 뒤 작성한다.

저장 JSON의 구조·지문, 파일 SHA-256, 버전·런타임, 현재 코드·설정 지문, 후보·트리 분기·출력 지지 수와 구간 분위수 순위를 검사한다. v1 전체 운영 자산은 새 스키마로 재학습해야 하며 내부 트리 표현의 회귀 호환 검사와 구별한다. `predict`는 모델 DB나 표준 DB 없이 저장 자산과 사전 입력만 이용한다. 동일 프로세스 저장 전후 비교와 새 프로세스 결과 지문 비교는 별도 검증이다. 원본 데이터·대용량 모델·결과는 Git 추적에서 제외한다. 다른 OS의 실제 실행은 미확인이다.

<a id="limitations"></a>

## 9. 검증·한계·후속 연결

- 월요일 입력 경계·역할·정답 완료·마스크·0/Null·비율 분모·기간 및 Count 구성 관계는 합성 테스트와 실자료 검사를 구분해 검증한다.
- 자료 품질 제한과 공식 선수 등록·이적·건강 상태 및 전체 공식 누적의 불완전성을 유지한다. 2025년 투구 순번 누락과 28일·잔여 희소성에 따라 평가 표본에 선택 편향이 있을 수 있다.
- 2025년 Validation은 v1의 결과가 이미 공개됐고 v2 후보 선정에도 사용한다. 추가 개발 비교 결과를 독립 일반화 성능으로 주장하지 않는다. 2026 Test는 후속 종합 검증으로 인계한다.
- 기준 대비 선정 조건은 개발 구간의 두 macro 지표에 대한 규칙이다. 모든 기록·기간·비율·구간 지표의 개선이나 최종 Test 개선을 보장하지 않는다. 기준 유지 또는 과거 기록 후보 선정 시 트리의 우월성을 입증하지 못한 사실과 운영 모델 요건을 하위 검토에 제출한다.
- 과거 종료 평균은 실제 미래 종료일이 아니다. 확인된 종료 시나리오의 점 예측은 고정 기간 조정일 뿐 실자료 보정이 확인되지 않았다. 실제 종료일을 알 수 없는 경우 동일한 실제 기간의 예측 차이는 진단하며 사후 종료일을 입력해 해결하지 않는다.
- 기대 Count 및 주변 구간은 개별 경기 경로나 인과 효과를 제공하지 않는다. 현재 누적의 자체 불확실성, 공동 확률 분포 및 비율 구간을 지원하지 않는다.
- README 및 공통 예측·평가 계약, 개발 흐름의 실제 운영 상태·모델 수·선정 결과는 새 사용자 실행 및 하위 검토 근거를 확보한 뒤 동기화한다. 기존 M1·M2·M4·M5 및 데이터 생성기 구현을 변경하지 않는다.

<a id="commands"></a>

## 10. 실행 명령

Windows PowerShell에서 신규·교체 코드를 적용한 뒤 실행한다. 각 학습 명령의 stdout은 JSON, stderr는 운영 로그다. 모든 검증 종료 코드가 0이어야 한다. 아래 명령은 Git 변경이나 자료 재수집을 하지 않는다.

```powershell
Set-Location -LiteralPath 'D:/Programming/kbo-insight-ai'
$kboPython = 'D:/Programming/kbo-insight-ai/.venv/Scripts/python.exe'
$dataRun = '259b38decaac4ed68dd5a596cfbe4849'

& $kboPython -X utf8 -B -m unittest `
    tests.models.test_player_performance `
    tests.models.test_player_performance_development
if ($LASTEXITCODE -ne 0) { throw 'M3 tests failed' }

& $kboPython -X utf8 -B -m unittest discover -s tests
if ($LASTEXITCODE -ne 0) { throw 'Regression tests failed' }

foreach ($role in @('hitter', 'pitcher')) {
    $lines = & $kboPython -X utf8 -B -m src.models.player_performance train `
        --project-root (Get-Location).Path --data-run $dataRun --role $role
    if ($LASTEXITCODE -ne 0) { throw "M3 training failed: $role" }
    $summary = ($lines -join "`n") | ConvertFrom-Json
    $summary | ConvertTo-Json -Depth 10

    & $kboPython -X utf8 -B -m src.models.player_performance inspect --asset $summary.asset
    if ($LASTEXITCODE -ne 0) { throw 'Asset inspection failed' }

    foreach ($case in @('normal', 'scenario')) {
        if ($case -eq 'normal') {
            $inputPath = $summary.input
            $expectedPath = $summary.expected
        } else {
            $inputPath = $summary.scenario_input
            $expectedPath = $summary.scenario_expected
        }
        $actual = Join-Path (Split-Path -Parent $summary.evaluation) `
            ("reloaded-$case-" + [guid]::NewGuid().ToString('N') + '.json')
        $prediction = & $kboPython -X utf8 -B -m src.models.player_performance predict `
            --asset $summary.asset --input $inputPath --output $actual
        if ($LASTEXITCODE -ne 0) { throw "Inference failed: $case" }
        & $kboPython -X utf8 -B -m src.models.player_performance compare `
            --expected $expectedPath --actual $actual
        if ($LASTEXITCODE -ne 0) { throw "Comparison failed: $case" }
    }
}
```

정상 성공 조건은 두 역할 각각 11개 후보 평가·운영 예측기 1개·최종 Test 미사용·자산 검사·일반 및 종료 시나리오의 별도 프로세스 전체 JSON 지문 일치다. 최초 388개 테스트에 신규 28개를 더한 예상 전체 테스트 수는 416개이며 실제 발견 수로 확정한다. 성능 및 구간 지표, 마스크, 공통 분모, 실제 종료 진단과 기준 유지 여부는 성공 코드와 별도로 확인한다. 오류가 발생하면 전체 로그, 실행 ID, 실제 평가 파일 및 테스트 종료 코드를 보존한다. 기존 원본·표준·모델 자료를 변경하지 않는다.

## 1. 문서 읽는 법

### 1.1 무엇을 정하는가

이 문서는 서로 다른 개발자가 같은 예측 문제를 다르게 해석하지 않도록 기준을 정한다. 상세 예측·평가 정의는 여기서 관리하고 개발 순서·산출물·인수 증거는 개발 흐름에서 관리한다.

원본 필드명·정밀 전체 스키마·모든 Feature·최종 알고리즘·환경 도구/버전·실제 기간·성능 목표는 자료 확인 전에 발명하지 않는다. 미래 단계의 설명은 작업 착수나 검증 완료를 뜻하지 않는다.

### 1.2 표현의 의미

| 표현               | 뜻                                                               |
| ------------------ | ---------------------------------------------------------------- |
| 확정 원칙          | 구현과 평가가 지켜야 할 경계                                     |
| 기본안 / 검증 대상 | 먼저 검토할 설계이며 데이터·성능으로 타당성을 확인해야 함        |
| 미확정             | 원본·조건·근거를 더 확인해야 함. 담당·시점·방법·사용 제한을 기록 |
| 정답               | 평가 대상 구간이 끝나고 포함·누락·정정 상태를 확인한 실제 값     |
| 예측 / 가정        | 미래 값의 추정 / 직접 확인되지 않은 조건. 실제 확정값과 구분     |
| 평가 불가          | 정답·표본·자료 정의 등 평가 조건이 충족되지 않은 상태            |

## 2. 기능 범위

### 2.1 전체 구현 대상

| 기능              | 산출물                                                                              |
| ----------------- | ----------------------------------------------------------------------------------- |
| M1 경기 결과·득점 | 승무패 확률, 양 팀 득점 분포·예상 득점·예상 스코어                                  |

**판정 절차:** 소규모 원본·자동 식별 확인 → 전체 포함 범위·누락·오분류 검사 → 포함/범위 제한/제외와 이유 기록.

단일 표본의 성공을 전체 품질로 확대하지 않는다. 일부 항목의 실패로 자동 확보 가능한 다른 항목까지 일괄 제외하지 않는다. 관측 번트 결과를 감독의 숨은 지시나 전체 번트 시도로 확대하지 않는다. 자료 확인 전 구현 가능/불가능·수치 품질선을 선결하지 않는다.

| -------------- | ---------------------------------------------------------------------------- |

## 3. 공통 정보 경계

<a id="input-gate"></a>

### 3.1 입력 채택 조건

| 검사           | 채택 기준                                                   |
| -------------- | ----------------------------------------------------------- |
| 사건 시각      | 예측하려는 사건 이후 정보가 아님                            |
| 이용 가능 시각 | 기준 시점에 사용할 수 있었다는 근거가 있음                  |
| 집계 절단      | 최근·누적·Rolling·Expanding에 기준 시점 이후 기록이 없음    |
| 출처·정정      | 원본 버전과 당시 이용 가능 근거를 설명할 수 있음            |
| 교차 예측      | 다른 예측기의 값도 당시 생성 가능한 학습·입력으로 만든 값임 |

일반적인 과거 기록은 기준 시점 전에 완료·공개된 정보만 사용한다. 바로 그 경계에서 확정된 경기 상태·참가자처럼 입력에 필요한 값은 이벤트 순서로 선후를 입증해야 한다. 같은 시각으로 기록됐다는 이유만으로 미래 결과를 포함하지 않는다.

공개 근거 없는 실제 라인업은 사후 정답·평가에는 사용할 수 있어도 당시 경기 전 입력으로 쓰지 않는다. 과거 일정의 현재 응답은 과거 공개 상태의 증거가 아니다.

<a id="corrections"></a>

### 3.2 정정 자료와 재현 범위

사후 정정·현재 제공되는 과거 자료가 당시 버전과 다를 수 있다. 당시 입력 스냅샷이 없으면 정정된 자료를 실제 과거 실행 상태와 동일하다고 주장하지 않는다. 현재 확인 가능한 자료 기반의 소급 분석과 당시 공개 상태 재현을 구분해 한계를 기록한다.

정정된 자료는 정답의 최신 공식 버전으로 사용할 수 있으나 입력 재현의 시점 조건과 혼합하지 않는다. 정정 영향은 데이터·정답·예측·평가 버전에 연결한다.

### 3.3 결과에 붙일 맥락

대상, 예측 기준 시점, 기간, 정보 절단 기준, 입력 범위/버전, 모델·설정·실행 식별자, 확정/예측/가정/미확정 상태를 연결한다. 이는 의미 계약이며 실제 필드명·파일 형식은 후속 구현에서 정한다.

## 4. M1~M5 예측 계약

### 한눈에 보는 차이

| 모델 | 논리적 표본          | 입력을 끊는 경계       | 정답 종료           |
| ---- | -------------------- | ---------------------- | ------------------- |
| M1   | 경기 예측 1건        | 경기 시작 전 실행 시점 | 해당 경기 공식 종료 |
| M2   | 타석 예측 1건        | 타석 시작 전           | 해당 타석 확정 결과 |
| M3   | 선수·역할·월요일 1건 | 월요일 00:00 KST       | 기간별 관측 완료    |
| M4   | 타석 경계 상태 1건   | 해당 경계까지          | 경기 / 반이닝 종료  |
| M5   | 실제 투구 예측 1건   | 해당 공 투구 전        | 해당 공 결과        |

원본의 투구 행에 타석 결과가 반복돼도 타석 표본을 중복 생성하지 않는다. 모델별로 정보 단위와 정답 귀속을 따로 정의한다.

<a id="m1"></a>

### 4.1 M1 — 경기 결과·득점

| 계약 항목      | 정의                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 한 행의 의미   | 한 경기의 예측 1건. 공통 득점 예측기의 팀 관점 내부 호출을 경기 수로 중복 세지 않음                                       |
| 입력 의미      | 당시 이용 가능한 팀·상대 과거 기록, 전력·최근 경기력·불펜 사용량·휴식, 시점 근거가 있는 라인업/등록 정보 또는 당시 예상값 |
| 출력           | 승무패 확률, 홈/원정 득점 분포·예상 득점·예상 스코어                                                                      |
| 예측 시점      | 경기 시작 전 기록된 실행 시점                                                                                             |
| 과거 정보 범위 | 기준 시점 전에 완료·공개된 자료. 현재 경기 결과·실제 사용 선수·경기 후 집계 제외                                          |
| 정답           | 공식 종료 경기의 결과와 양 팀 최종 득점                                                                                   |
| 예측 기간      | 해당 경기 공식 종료까지                                                                                                   |
| 미확정         | 실행 시각, 무효/중단/서스펜디드 처리, 분포·양 팀 결합·꼬리·시즌 규칙 연결                                                 |

**기본안:** 공통 팀 관점 득점 예측기 1개를 홈·원정에 재사용한다. 분포 가정과 양 팀 득점 의존성을 아직 검증한 것으로 취급하지 않는다.

**출력 연결 검증**

1. 확률은 유효 범위에 있고 전체 합이 정의에 맞는다.
2. 득점은 비음수이며 분포·기대득점·스코어 요약 규칙이 일치한다.
3. 최종 점수와 공식 결과가 직접 대응하는 경기에서는 결합 득점 분포의 홈 우세/동점/원정 우세 영역 합으로 승무패를 대조한다.
4. 연장·무승부·시즌 규칙과 분포의 경기 종료 의미가 맞는다. 독립 득점 가정이나 꼬리 절단을 사용하면 그 근거·영향을 기록한다.
5. 예상 스코어가 평균의 반올림인지 최빈 조합인지 명시한다. 요약 점수의 승패를 확률 예측과 동일시하지 않는다.

분류와 득점을 별도 독립 예측기로 학습하면 실제 모델 수에 포함한다. 일관성 실패를 숫자만 맞춰 숨기지 않고 가정·평가를 다시 검토한다.

| 입력 의미      | 시작 시점의 타자·투수·주자·아웃·점수·상황과 이전 기록                   |

**교체 경계:** 시작 참가자와 최종 결과 귀속 참가자를 분리한다. 타석 도중 사후 확정된 타자·투수를 시작 입력에 넣지 않는다. 시작 참가자 식별 불가 표본은 임의로 최종 참가자로 대체하지 않고 제한·제외 근거를 남긴다.

결과 분류는 공식 기록·원본 가용성에 맞춰 고정하고 학습·검증·Test에서 같은 매핑을 쓴다. 단타·장타·볼넷·사구·삼진·기타 아웃 등의 후보를 최종 범주로 확정하기 전에 희귀·중복·특수 결과를 점검한다.

기간·관측 완료·비율 계산의 상세 기준은 [M3 정답 계약](#m3-labels)을 따른다.

### 4.4 M4 — 경기 상황 가치

| 계약 항목      | 정의                                                                  |
| -------------- | --------------------------------------------------------------------- |
| 한 행의 의미   | 타석 경계 상태 1건. 같은 타석의 직전/직후 상태 연결                   |
| 입력 의미      | 해당 경계까지의 이닝·공수·점수·주자·아웃과 이전 기록                  |
| 출력           | 고정 팀 관점의 승리 확률·현재 반이닝 잔여 기대득점, 전후 변화         |
| 예측 시점      | 타석 직전과 종료 직후 각각                                            |
| 과거 정보 범위 | 경계에서 관측된 상태까지. 미래 결과·경기 후 집계 제외                 |
| 정답           | 공식 경기 결과, 해당 상태 이후 현재 반이닝 종료까지 실제 득점         |
| 예측 기간      | 승리 확률은 경기 종료, 기대득점은 현재 반이닝 종료까지                |
| 미확정         | 팀 관점·무승부 의미·종료 상태, 기대득점 표·희소 처리·상황 중요도 산식 |

**승리 확률과 기대득점:** 주 예측기는 승리 확률 1개가 기본안이다. 기대득점은 학습 구간의 과거 상황별 통계로 제공한다. 무승부 확률과 승리 지분을 혼동하지 않게 정의하고, 정답·지표를 그 정의에 맞춘다.

**WPA:** 같은 팀 관점의 `타석 후 승리 확률 − 타석 전 승리 확률`이다. 실제 사건의 WPA는 사건 후 상태가 관측된 뒤 계산한다. 사건 전 입력으로 넣거나 독립적인 실제 정답처럼 취급하지 않는다.

**기대득점 변화:** 실제 발생 득점을 포함한 득점 가치인지 잔여 기대득점의 단순 차이인지 구분해 산식을 기록한다. 타석 직후 이닝이 끝났다면 이전 반이닝의 잔여 득점 종료 상태로 처리하고 다음 반이닝 상태와 섞지 않는다.

**상황 중요도:** 가능한 결과·확률·가치 변화·참조 평균을 사용하는 계산 정의를 확정한다. 실제 발생 결과의 WPA와 동일시하지 않는다. 산식·참조 통계·확률 버전과 검증 사례를 보존한다.

경기·반이닝 종료, 끝내기·무승부 등 경계 사례는 시즌 규칙에 맞게 검사한다. 정확한 종료 상태 처리·산식은 원본과 규칙 확인 후 학습·사용 전에 고정한다.

## 5. M3 기간·관측 완료·기록 일관성

<a id="m3-period"></a>

### 5.1 기간 경계

기준 월요일을 t로 두고 KST 기준으로 해석한다.

| 기간      | 포함 범위                         | 주의점                                         |
| --------- | --------------------------------- | ---------------------------------------------- |
| 7일       | [t, t+7일)                        | 시작 월요일 포함, 다음 월요일 제외             |
| 28일      | [t, t+28일)                       | 시작 포함, 28일 뒤 경계 제외                   |
| 잔여 시즌 | t부터 해당 정규시즌 공식 종료까지 | 포스트시즌 혼합 금지, 종료·전체 포함 근거 필요 |

월요일 당일 기록은 정답에는 들어갈 수 있지만 입력에서는 모두 제외한다. 실제 실행이 늦어도 논리 기준을 늦추지 않는다. 시즌이 고정 기간 안에서 끝나면 정규시즌 기록만 집계하고 남은 날짜가 있다는 이유로 미래 포스트시즌 기록을 넣지 않는다.

기준 시점에 해당 정규시즌이 이미 끝났다면 잔여 시즌 미래 예측 대상으로 취급하지 않는다. 종료된 시즌의 확정 기록과 미래 예측을 분리하고, 대상 밖 상태를 누락·예측 실패·정답 0과 혼동하지 않는다.

연기·서스펜디드·자정 경계 경기의 기록 귀속일과 실제 이용 가능 시각은 별개다. 데이터 구축 단계에서 공식 집계와 원본 순서를 대조해 귀속 규칙을 고정한다.

### 5.2 출전량·Count·파생 비율

| 항목      | 기준                                                                       |
| --------- | -------------------------------------------------------------------------- |
| 출전량    | 타석·타수·상대 타자·아웃 등 가용한 노출량을 정의하고 기록과 함께 예측·평가 |
| Count     | 비음수와 구성/상위 기록 관계를 검사. 원본 확인 전 전체 목록 확정 금지      |
| 이닝      | 단순 소수로 산술하지 않고 아웃 수 등 일관된 표현으로 계산                  |
| 비율      | 같은 기간의 예측 분자·분모로 계산. 분모 0은 null과 사유로 표시             |
| 시즌 전망 | 실제 누적 Count + 잔여 예측 Count를 먼저 계산한 뒤 비율 산출               |

예를 들어 타율은 안타/타수다. 출루율·장타율·OPS 등은 필요한 구성 기록과 공식 계산 정의를 확보한 경우에만 제공한다. 실제 비율과 미래 비율을 단순 평균하지 않는다. 분모가 다른 비율의 비교에서는 분모 규모·평가 가능 범위를 함께 보고한다.

<a id="m3-state"></a>

### 5.3 정답 상태 의사결정

| 상태                                     | 정답 처리                | 학습·평가                   |
| ---------------------------------------- | ------------------------ | --------------------------- |
| 미래 구간 미종료                         | 미관측                   | 확정 정답으로 사용 금지     |
| 구간 종료, 원본 누락·정정 미확인         | 미확정                   | 0 대체 금지, 제한·제외      |
| 구간 전체 확보·집계 완전, 실제 기록 없음 | 실제 Count 0 가능        | 모집단·정의 충족 시 사용    |
| 시즌 종료·전체 포함·정정 확인            | 잔여 시즌 정답 확정 가능 | 관측 완료 시점 검사 후 사용 |
| 시즌 진행 중 또는 종료/완전성 근거 부족  | 잔여 정답 미확정         | 확정 사용 금지              |

선수 행이 없다는 사실만으로 출전하지 않았다고 단정하지 않는다. 대상 목록·경기 기록·수집 완전성을 대조한다. 불완전한 28일을 관측된 날짜만 합쳐 완전한 28일 정답처럼 만들지 않는다.

<a id="m3-overlap"></a>

### 5.4 학습 시각·겹치는 구간

학습 실행 시점까지 전체 정답 구간이 관측·이용 가능해진 표본만 학습한다. 기준 월요일이 과거라는 것만으로 충분하지 않다.

Backtesting에서의 학습 시점은 실제 재실행한 오늘이 아니라 해당 과거 평가 구간의 **논리적 학습 기준 시각**이다. 정답 관측 완료도 그 시각으로 검사한다. 실제 프로그램 실행 시각은 실행 이력으로 별도 남긴다.

분할 경계에서는 학습 표본의 정답 구간 종료·관측 완료를 검사한다. 검증·Test 미래 구간에 걸치는 학습 표본을 제거한다. 그 뒤의 재학습에서도 실행 당시 관측 완료된 정답만 추가한다.

공동 출력 일부가 미관측이면 임의 0을 넣지 않는다. 부분 정답 마스크를 알고리즘이 안전하게 지원하는지 검증하고, 지원하지 않으면 요구 정답이 모두 관측된 표본만 학습한다. 어떤 기간·기록이 학습·평가됐는지 기록한다.

평가 내부의 겹치는 미래 구간은 서로 독립이라고 과장하지 않는다. 기준 주·기간·시즌별 결과, 중첩 관계와 해석 한계를 보고한다.

### 5.5 일관성 검사

- 비음수, 하위 Count ≤ 관련 상위 Count·출전량
- 동일 모집단·정의에서 7일 Count ≤ 28일 Count
- 잔여 시즌과 고정 기간의 포함 관계는 실제 시즌 경계에 따라 검사
- 파생 비율의 분자·분모·구성 기록 간 대응
- 누적 실제 기록과 잔여 예측의 중복·누락 방지

Count의 기대값은 소수일 수 있으며 무조건 정수로 반올림하지 않는다. Count 단조 관계를 타율 등 비율에 그대로 강제하지 않는다. 제약·후처리를 사용하면 규칙·버전·평가 영향을 남긴다.

## 6. 평가 원칙

### 6.1 무엇을 비교하는가

같은 문제 안에서 같은 시점·기간·표본·분할·지표로 기준 모델과 후보를 비교한다. 다른 모델군의 점수를 직접 우열로 해석하지 않는다. 표본이 달라지면 공통 표본 비교와 각 방식의 적용 범위를 함께 제시한다.

기준 모델도 학습 범위에서만 추정하고 동일한 정보 제한을 적용한다. 기준 모델의 선택·집계 창·조건화·희소 후퇴·평활화·수치 처리는 최종 Test 전 고정한다.

주 지표·보조 지표·후보 선택 규칙은 후보 비교 전에 정한다. 세부 지표를 확정할 원본 근거가 부족하면 그 비교를 보류한다. 여러 지표의 결과가 엇갈리면 미리 정한 선택 기준과 장단점을 함께 보고하고 유리한 지표만 남기지 않는다.

<a id="metrics-probability"></a>

### 6.2 분류·확률 출력

| 대상         | 주요 지표·이유                                                                  | 기준 모델                                           |
| ------------ | ------------------------------------------------------------------------------- | --------------------------------------------------- |
| M1 승무패    | 다중분류 Log loss: 실제 결과 확률 평가. Brier score·신뢰도 도표: 확률 오차·보정 | 학습 구간 결과 빈도, 근거 있는 홈/원정 조건화       |
| M2 타석      | Log loss·Brier score: 확률 품질. Macro F1·범주별 결과: 희귀 범주 확인           | 학습 타석 결과 빈도, 필요 시 과거 입력으로만 조건화 |
| M4 승리 확률 | 정답 정의에 맞는 Log loss·Brier score·신뢰도 도표                               | 학습 상황별 결과 빈도와 희소 상황 후퇴 규칙         |
| M5 구종·결과 | 공동 Log loss와 주변 Log loss·Brier score·범주별 결과                           | 학습 공동/주변 빈도, 현재 공의 정답 구종 사용 금지  |

Accuracy는 확률 보정을 설명하지 못하므로 보조로 사용한다. 범주별 표본·지원 범위와 희귀 결과를 함께 보고한다. M4는 무승부를 어떻게 정의했는지에 따라 정답·지표를 맞춘다.

**계산 정의:** Log loss는 실제 범주에 부여한 확률의 음의 로그를 평균한다. 다중분류 Brier score는 예측 확률과 정답 원핫 값의 제곱 오차를 범주에 대해 합한 뒤 표본 평균하는 정의를 사용하고, 다른 정규화가 있으면 명시한다. 공동 확률과 주변 확률은 각각 다른 평가 대상이다.

확률 0·미출현 범주·공동 조합·수치 절단·평활화는 사전 규칙을 고정한다. Test 결과를 보고 점수 계산 방식을 유리하게 바꾸지 않는다.

<a id="metrics-numeric"></a>

### 6.3 수치·Count·분포 출력

| 대상            | 주요 지표·이유                              | 기준 모델                                              |
| --------------- | ------------------------------------------- | ------------------------------------------------------ |
| M1 득점 점 예측 | MAE: 일반 오차, RMSE: 큰 오차 민감도        | 학습 득점 평균/중앙값 등 지표에 맞는 고정 기준         |
| M1 득점 분포    | Log score 또는 이산 CRPS: 분포 품질         | 학습 경험 분포, 결합 평가는 결합 출력 정의 후 사용     |
| M3 출전량·Count | 기록·기간별 MAE·RMSE: 서로 다른 규모를 분리 | 과거 노출량 추세와 단위 노출량당 기록의 지속/평균 기준 |
| M3 파생 비율    | 유효 분모 표본 MAE와 분모 규모·평가 범위    | 기준 Count에서 동일 분자/분모 계산                     |
| M4 기대득점     | 반이닝 잔여 실제 득점 대비 MAE·RMSE         | 학습 상황별 평균과 전체 평균                           |

MAE는 절대 오차 평균, RMSE는 제곱 오차 평균의 제곱근이다. 기록 단위·기간·표본 수와 함께 보고한다. 규모가 큰 Count의 오차가 다른 기록을 가리지 않도록 임의 합산 점수만 제시하지 않는다.

M1의 주 분포 지표는 출력이 확률질량함수인지 누적분포인지, 꼬리 처리와 결합 정의가 무엇인지 확인한 뒤 모델 비교 전에 고정한다. 지표를 모두 계산하더라도 사후에 유리한 것만 골라 승자를 정하지 않는다.

M3 기준 모델은 미래 실제 출전량을 입력으로 쓰지 않는다. 미래 출전량을 가정하거나 예측하면 그 방식·범위를 명시한다. 예측 구간을 제공할 경우 관측 포함률과 폭을 함께 평가하며 지원되지 않는 구간을 발명하지 않는다.

<a id="metrics-location"></a>

### 6.4 위치 출력

| 검사      | 기준                                                      |
| --------- | --------------------------------------------------------- |
| 좌표 의미 | 단위·축·원점·방향·정규화/스트라이크존 변환·유도 근거 확정 |
| 유효 표본 | 실제 투구·유효 좌표 마스크와 제외 사유 명시               |
| 주요 지표 | 축별 MAE와 2차원 거리 오차, 단위 명시                     |
| 기준 모델 | 학습 구간 평균/중앙 위치, 같은 표본·좌표계로 비교         |
| 분포 출력 | 위치 분포를 제공한다면 적절한 분포 점수를 별도 확정       |

좌표 누락을 원점으로 채워 오차를 계산하지 않는다. 거리 오차의 평균/중앙값 등 집계 정의를 고정하고 유효 좌표 비율·제외 사유를 보고한다. 실제 현재 구종으로 조건화한 위치 성능을 무조건 투구 전 성능으로 표현하지 않는다.

### 6.5 보조 기능

라인업은 명단 적중, 타순·수비 위치 일치, 선발투수 식별 등 출력별로 평가한다. 후보 목록은 후보집합·제공 개수·순위 지표·정답 시점을 고정한다. 과거 사용 빈도·최근 패턴을 기준으로 비교한다.

선수의 실제 내부 가용성이나 교체 이유를 정답으로 만들지 않는다. 조건부 항목은 허용된 관측 이벤트·범위에서만 평가한다. 정답 정의가 확보되지 않은 부분은 평가 불가로 표시한다.

<a id="split"></a>

### 6.6 시간 분할과 Backtesting

1. **자료 근거 확인:** 수집 범위·시즌 완료·정답 포함·누락·정정을 확인한다.
2. **분할 고정:** 학습 → 검증 → 최종 Test 날짜와 경기 목록을 데이터 구축 단계에서 확정한다.
3. **경기 묶음:** 같은 경기의 타석·투구를 학습·평가 양쪽에 나누지 않는다.
4. **정답 완료:** M3는 정답 구간 관측 완료가 학습 시점 이전인지 검사한다.
5. **학습 처리 분리:** 결측 대체·Encoder·스케일링·변수 선택은 각 학습 구간에서만 맞춘다.
6. **과거 시점 반복:** 당시 입력·완료 정답만 사용해 학습·예측한다. 창·재학습·갱신 규칙을 보존한다.
7. **보정 분리:** 시간 순서상 분리된 검증 또는 과거 시점별 예측을 사용한다.
8. **Test 잠금:** 모델·변수·설정·보정 선택에 최종 Test를 사용하지 않는다.

정확한 날짜·표본 수·성능 목표는 이 문서에서 만들지 않는다. 시간 경계를 성능에 맞춰 이동하지 않는다. 최종 Test를 재조정에 사용했다면 그 자료는 독립 최종 평가로 남길 수 없으며 한계·새 평가 계획을 분리한다.

<a id="stacking"></a>

### 6.7 다른 예측기의 출력·설명·오류 분석

예상 라인업 등 다른 모델의 값을 입력으로 쓰면 각 과거 시점에서 학습·생성 가능한 예측만 사용한다. 전체 자료를 학습한 모델의 과거 적합값은 금지한다. 상위 예측기의 학습 범위·입력·생성 시점·버전을 연결한다.

보정·설명·오류 분석은 모델 개발 중 반복한다. 전체 설명과 개별 설명을 구분한다. SHAP은 모델의 예측 기여도이며 인과관계·실제 몸 상태·감독 의도의 증거가 아니다. 최종 Test의 실패 사례를 설명하되 그 결과로 선택을 다시 하면 평가 지위가 달라진다.

## 7. 시즌·포스트시즌 전망 계약

### 7.1 출력별 의미

| 출력               | 정답·평가 단위                            |
| ------------------ | ----------------------------------------- |
| 최종 승수·순위     | 완료된 정규시즌의 팀별 공식 승수·순위     |
| 정규시즌 우승      | 정규시즌 최종 1위 팀                      |
| 포스트시즌 진출    | 해당 시즌 공식 진출 결과                  |
| 시리즈별 승리·진출 | 완료된 시리즈·단계의 공식 결과            |
| 한국시리즈 우승    | 포스트시즌을 거친 한국시리즈 최종 우승 팀 |

시즌 전망은 M1·일정·현재 성적·시즌 규칙을 연결해 계산하며 별도 우승 전용 모델을 기본 추가하지 않는다. 확정 경기·진출·탈락은 고정하고 미확정 부분만 계산한다.

<a id="season-inputs"></a>

### 7.2 일정·규칙·조건부 확률

당시 알려진 일정, 미편성/변경 상태, 홈·원정, 동률·대진·차전·승리 조건·무승부 규칙을 확인한다. 시즌별 공식 근거와 적용 버전을 보존한다.

특정 대진 성립을 전제로 한 확률과 현재 시점의 전체 진출·우승 확률을 구분한다. 미래 일정이 미확정이면 가정을 표시한다. 과거 일정 스냅샷이 없으면 가정 시나리오와 실제 당시 정보 기반 Backtesting을 구분한다.

<a id="season-evaluation"></a>

### 7.3 평가와 계산 안정성

| 구분        | 확인 방법                                                                             |
| ----------- | ------------------------------------------------------------------------------------- |
| 규칙 정확성 | 작은 가상 시즌·이미 종료된 상황·확정 진출/탈락의 순위·대진·우승 대조                  |
| 계산 안정성 | 반복 횟수·Seed·반복 간 변동과 실행 설정 기록                                          |
| 예측 정확도 | 승수/순위 MAE, 진출/우승/시리즈 Brier score·Log loss, 기준 경기 예측과 동일 규칙 비교 |
| 평가 범위   | 정규시즌/포스트시즌, 예측 기준 시점, 완료된 시즌/시리즈를 분리                        |

같은 시즌의 반복 전망을 독립 시즌 수로 세지 않는다. 평가 가능한 시즌 범위와 의존성을 보고한다. 반복 변동이 작다는 것은 결과 계산이 안정적이라는 뜻이며 실제 정답에 가깝다는 뜻은 아니다.

## 8. 모델 수와 검증되지 않은 설계

### 8.1 기본 구성

| 기능군   | 최종 주 예측기 목표 | 기본 구조                                                |
| -------- | ------------------- | -------------------------------------------------------- |
| M1       | 1                   | 공통 팀 관점 득점 예측기, 분포에서 경기 출력 계산        |
| M2       | 1                   | 공통 타석 결과 분류기                                    |
| M3       | 2                   | 타자·투수 각 1개, 기록·기간 공동 출력                    |
| M4       | 1                   | 승리 확률 예측기, 기대득점은 통계·WPA/상황 중요도는 계산 |
| M5       | 2                   | 구종/결과 공동 1개, 위치 1개                             |

### 8.2 집계 규칙

- 팀·선수·기간·기록별 개별 예측기를 늘리지 않는다.
- 한 파일에 여러 독립 예측기를 묶어도 실제 독립 개수로 센다.
- 출력별 독립 예측기를 만드는 래퍼도 실제 독립 개수를 센다.
- 실험 후보·기준 모델과 최종 운영용 주 예측기를 구분한다.
- 전처리·보정의 학습 요소와 통계표·제약·시뮬레이션 설정은 별도 기록한다.

### 8.3 반드시 검증할 가정

| 가정               | 확인할 것                              | 실패 시                            |
| ------------------ | -------------------------------------- | ---------------------------------- |
| M1 분포·양 팀 결합 | 분포 적합·확률/득점 일관성·꼬리·무승부 | 대안·실제 모델 수·영향을 보고      |
| M3 공동 출력       | 기록/기간/노출량 일관성·부분 정답·분모 | 제약·제외·대안과 평가 영향 기록    |
| M5 공동 구종/결과  | 공동/주변 확률·희소 조합·당시 입력     | 공동 설계 한계·대안·개수 영향 보고 |

추가 모델은 근거·필요성·대안·관리 비용·실제 개수와 함께 설계 변경으로 다룬다. 파일 포장·출력 이름 변경으로 개수나 범위를 숨기지 않는다.

## 10. 재현성·저장·설정 계약

### 10.1 자료의 단계

```text
raw ── 변환/수정/제외 이력 ──> interim ── 검증/입력 구성 ──> processed
 │                                  │                          │
 └──────────── 부모 자료·버전·실행 식별자로 연결 ─────────────────┘
```

위 이름은 자료 경계의 의미다. 실제 물리 경로·파일 형식은 개발 기반에서 정한다. 원본은 수정·덮어쓰지 않는다. 재수집·공식 정정은 별도 버전으로 보존한다.

### 10.2 남길 이력

| 이력      | 필수 의미                                              |
| --------- | ------------------------------------------------------ |
| 수집      | 출처·수집 시각·기간·요청 조건·파일·버전·포함/누락·실패 |
| 변환      | 부모 원본·처리 단계·변환 설정·수정/제외 이유·영향 범위 |
| 분할      | 시간 경계·경기 목록·정답 완료 검사·누수 제한           |
| 학습      | 데이터·변수·정답·전처리·설정·Seed·모델·보정 자산       |
| 예측·평가 | 대상·시점·기간·사용 자산·예측/정답·지표·집계·제외      |

버전은 사용한 자산의 상태를, 실행 식별자는 수행 1건을 식별한다. 같은 설정의 반복 실행도 별도 수행으로 추적할 수 있어야 한다. 실제 명명법·스키마는 후속 구현에서 정한다.

### 10.3 저장 경계와 책임

| 대상                | 경계·책임                                                  |
| ------------------- | ---------------------------------------------------------- |
| 원본·중간·처리 자료 | 원본 보존, 변환/제외 추적, 품질 확인 상태 분리             |
| 모델·전처리·보정    | 학습 자산·입력 정의·분할·설정 연결                         |
| 예측·평가·보고      | 재생성 가능한 결과와 사용 버전·실행 연결                   |
| 소스·테스트·문서    | 동작·기준·검증의 변경 관리                                 |
| 캐시                | 재생성 가능한 임시 자산. 유일한 원본·재현 근거로 사용 금지 |
| 기준 경로·설정      | 임의 실행 위치로 출력 위치가 달라지지 않게 해석 책임 명시  |
| 로그                | 레벨·실행 맥락·오류를 남기되 비밀값 제외                   |

개발 기반 담당은 실제 경로·설정·저장·로그 경계를 구현한다. 데이터 구축은 수집·변환 이력을, 모델/통합 이후는 학습·예측·평가 연결을 채운다. 이것은 다음 개발 작업의 인수 계약이며 환경 구현을 선행하지 않는다.

### 10.4 Secret과 Git 추적

실제 Secret·환경 파일·대용량 데이터·모델·캐시의 추적 경계를 실제 구조에 맞춰 정한다. 필요한 경우 비밀값 없는 `.env.example`만 추적하고 `.env`·`.env.production`은 추적하지 않는다. 다른 `.env` 변형을 늘리지 않는다.

요청 조건을 남길 때도 Token·Key·Password 등 비밀값은 제거한다. 코드·Notebook·문서·설정·테스트·로그에 비밀값을 넣지 않는다. 데이터·코드의 사용/재배포 조건은 출처별 확인 근거와 함께 관리한다.

## 12. 결과 해석과 판단 사례

### 12.1 결과를 열면 먼저 볼 것

1. **대상과 시점:** 어느 경기·선수·타석·투구를 언제 예측했는가
2. **기간과 범위:** 한 경기인지, 향후 기간인지, 정규시즌/포스트시즌 중 무엇인가
3. **정보 상태:** 실제 확정값·예측·가정·미확정이 구분되는가
4. **근거와 버전:** 어떤 데이터·모델·설정·실행으로 생성됐는가
5. **평가 가능 범위:** 정답 완료·제외·누락·분모·좌표 조건이 충족됐는가

#### 종류별 확인 지점

| 결과      | 먼저 확인                      | 함께 읽어야 할 것                         |
| --------- | ------------------------------ | ----------------------------------------- |
| 경기 예측 | 경기 전 기준 시점·승무패 확률  | 득점 분포·예상 득점·스코어 요약 규칙      |
| 타석 예측 | 시작 참가자·상태·결과 분류     | 타석 중 교체·중단·무투구 처리             |
| 선수 전망 | 기준 월요일·7일/28일/잔여 기간 | 출전량·Count·비율 분모·정답 관측 상태     |
| 상황 가치 | 타석 경계·팀 관점              | 승리 확률·기대득점과 사후 WPA 계산의 차이 |
| 투구 예측 | 공 직전 정보·실제 투구 여부    | 공동/주변 확률·좌표계·유효 표본·제외      |
| 시즌 전망 | 기준 시점·해당 시즌 규칙       | 두 우승·확정 상태·일정 가정·조건부 대진   |
| 평가 보고 | 문제·기간·분할·기준 모델       | 지표 단위·표본/제외·보정·실패·재현 식별   |

#### 상태 표시

| 상태      | 뜻                                              |
| --------- | ----------------------------------------------- |
| 확정      | 그 시점에 근거가 확인된 실제 기록·상태          |
| 예측      | 모델·규칙·통계의 미래 추정. 실제 결과 보장 아님 |
| 가정      | 미발표 일정 등 직접 확인되지 않은 조건          |
| 미확정    | 자료·공개 시점·관측 완료 근거가 부족한 상태     |
| 평가 불가 | 정답·표본·분모·좌표 등 평가 조건 미충족         |

미확정이나 평가 불가는 실제 0·작은 오차·좋은 성능과 다르다. 산출물의 추적 항목은 [재현성 계약](#reproducibility), 평가 보고 구성은 [평가 기록](#evaluation-record)을 따른다.

### 12.2 해석·처리 사례

<details>
<summary><strong>결과 해석 4개 — 스코어·선수 기록·WPA·두 우승</strong></summary>

#### 승리 확률의 우세 팀과 예상 스코어가 다르게 보이는 경우

예상 스코어는 분포의 요약이다. 평균의 반올림과 가장 가능성 높은 점수 조합은 다를 수 있다. 요약 규칙을 확인하고, 분포에서 계산한 승무패와 제공 확률이 일치하는지 [M1 계약](#m1)으로 대조한다. 단순히 화면 숫자만 맞추지 않는다.

#### 선수가 출전하지 않은 것처럼 보이는데 기록이 비어 있는 경우

완전한 자료에서 실제 출전이 없는지, 아직 미래인지, 수집 누락인지 먼저 구분한다. 0으로 채우기 전에 [M3 정답 상태](#m3-state)를 확인한다. 비율의 분모가 0이면 비율 0으로 읽지 않는다.

#### 타석 뒤 WPA가 큰 경우

실제 사건 이후 승리 확률 변화의 계산값이다. 사건 전부터 같은 WPA를 알고 있었다는 뜻이 아니며, 선수의 인과적 공헌을 확정한 값으로 단정하지 않는다. [M4 정의](#m4)를 확인한다.

#### 정규시즌 우승과 한국시리즈 우승 전망이 다른 경우

정규시즌 순위와 포스트시즌 최종 우승은 다른 사건이다. 대진·시리즈 규칙·조건부 진출을 확인한다. 반복 계산의 안정성과 정답 대비 정확도도 [별도로 평가](#season-evaluation)한다.

</details>

<details>
<summary><strong>판단 절차 6개 — 부분 정답·과거 라인업·교체·좌표·Test·시뮬레이션</strong></summary>

#### 사례 A — 월요일에 일부 정답만 준비된 선수

**상황:** 기준 주의 7일 정답은 완료됐지만 28일·잔여 시즌 정답은 아직 관측되지 않았다.

1. 월요일 당일 기록이 과거 입력에 없는지 [기간 경계](#m3-period)를 확인한다.
2. 기간마다 [정답 상태](#m3-state)를 분리한다. 7일 완료가 다른 기간의 완료를 뜻하지 않는다.
3. [부분 정답 처리](#m3-overlap)에 따라 마스크 지원을 검증하거나 요구 정답이 모두 완료된 표본만 학습한다.
4. 누락·제외·학습에 사용한 기간을 평가 기록에 남긴다.

**잘못된 처리:** 미관측 기간을 0으로 채우거나 관측된 날짜만 합쳐 완전한 기간처럼 표시하는 것.

#### 사례 B — 지금 조회한 과거 선발 명단

**상황:** 과거 경기의 실제 선발 명단은 조회되지만 발표 시각 기록은 없다.

1. [입력 채택 조건](#input-gate)에서 사건 날짜와 이용 가능 시각을 구분한다.
2. [D04](#d04)의 공개 근거가 없으면 당시 경기 전 입력으로 채택하지 않는다.
3. 사후 라인업 정답·평가와 경기 전 입력 사용을 분리하고 재현 한계를 표시한다.

**잘못된 처리:** 현재 응답에 있으므로 당시에도 알 수 있었다고 주장하는 것.

#### 사례 C — 타석 중 투수가 바뀐 경기

**상황:** 최종 결과 행에는 교체 후 투수가 기록돼 있다.

1. [M2 계약](#m2)에 따라 타석 시작 상태와 결과 귀속을 별도로 확인한다.
2. [D08](#d08)의 시작 참가자 식별·분류 매핑을 확인한다.
3. 시작 상태를 복원할 근거가 부족하면 제한·제외를 기록한다.

**잘못된 처리:** 최종 투수를 시작 입력에 그대로 넣는 것.

#### 사례 D — 위치 오차가 작은 투구 모델

**상황:** 위치 평가에는 좌표가 있는 공만 포함됐고 실제 현재 구종으로 조건화했다.

1. [M5 계약](#m5)에서 투구 전 정보 범위를 대조한다.
2. 실제 현재 구종을 사용한 분석은 별도 조건부 문제로 구분한다.
3. [좌표 평가](#metrics-location)에 따라 유효 표본·제외 사유·좌표계·동일 기준 모델을 확인한다.

**잘못된 처리:** 조건부 위치 성능을 원래 투구 전 전체 성능으로 보고하거나 좌표 누락을 원점으로 채우는 것.

#### 사례 E — 최종 Test를 본 뒤 설정 수정

**상황:** Test 결과가 나빠 모델이나 보정 설정을 바꾸고 싶다.

1. [분할·선택 경계](#split)에 따라 해당 자료가 선택에 노출됐음을 기록한다.
2. 기존 평가의 독립성을 그대로 주장하지 않는다.
3. 변경·영향 범위·새 평가 계획을 구분하고 결과의 상태를 갱신한다.

**잘못된 처리:** 같은 자료로 재선정한 결과를 독립 최종 성능으로 유지하는 것.

#### 사례 F — 반복 계산이 안정적인 우승 전망

**상황:** 반복 시뮬레이션의 결과 변동은 작지만 실제 완료 시즌 평가가 없다.

1. [시즌 입력](#season-inputs)의 규칙·일정·확정 상태·가정을 확인한다.
2. [시즌 평가](#season-evaluation)에 따라 계산 안정성과 실제 예측 정확도를 분리한다.
3. 완료된 시즌/시리즈·기준 시점·기준 모델이 확보되기 전 정확도 통과를 주장하지 않는다.

**잘못된 처리:** 반복 변동이 작다는 이유만으로 실제 우승을 잘 예측한다고 결론 내리는 것.

</details>

### 12.3 미확정 항목의 처리

1. [확정 대기 목록](#decisions)에서 관련 항목·책임·시점을 찾는다.
2. 원본·공개 시점·완료·규칙 등 필요한 증거를 확인한다.
3. 확인 전 사용 제한을 적용한다. 비슷해 보이는 값을 임의로 채우지 않는다.
4. 결정 이유·검증 범위·변경 버전과 영향을 기록한다.
5. 정답·분할·모델·평가가 영향을 받으면 [재현성 계약](#reproducibility)에 따라 연결 자산을 갱신한다.

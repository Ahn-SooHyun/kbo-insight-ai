## 1. 문서 읽는 법

### 1.1 무엇을 정하는가

이 문서는 서로 다른 개발자가 같은 예측 문제를 다르게 해석하지 않도록 기준을 정한다. 상세 예측·평가 정의는 여기서 관리하고 개발 순서·산출물·인수 증거는 개발 흐름에서 관리한다.

원본 필드명·정밀 전체 스키마·모든 Feature·최종 알고리즘·환경 도구/버전·실제 기간·성능 목표는 자료 확인 전에 발명하지 않는다. 미래 단계의 설명은 작업 착수나 검증 완료를 뜻하지 않는다. 이 문서는 공통 규범이며, 실제 구현의 더 좁은 지원 범위·수치·모델 스키마·학습 지문은 실행 문서에서 관리한다. 2026-11-28 기준 M1·M2 개발 검증 및 병합을 확인했다. M2는 [PR #23](https://github.com/Ahn-SooHyun/kbo-insight-ai/pull/23) 병합(`307c729`) 및 Issue #18 종료를 확인했다. M4의 [PR #24](https://github.com/Ahn-SooHyun/kbo-insight-ai/pull/24) 병합(`f40ed33`) 및 [Issue #19](https://github.com/Ahn-SooHyun/kbo-insight-ai/issues/19) 종료를 확인했다. M5는 [Issue #20](https://github.com/Ahn-SooHyun/kbo-insight-ai/issues/20)의 원격 v1.1.0 구현 및 사용자 실데이터 개발 평가·62개 M5/348개 전체 테스트·독립 JSON 재현 검증이 확인됐다. M5는 [PR #25](https://github.com/Ahn-SooHyun/kbo-insight-ai/pull/25) 병합(`f97fc73`) 및 Issue #20 종료를 확인했다. M3은 [Issue #21](https://github.com/Ahn-SooHyun/kbo-insight-ai/issues/21)의 원격 v1.1.0 구현, 사용자 68개 M3/416개 전체 테스트, 두 역할의 개발 평가 및 독립 JSON 재현, [PR #26](https://github.com/Ahn-SooHyun/kbo-insight-ai/pull/26) 병합(`9d38fa2`) 및 Issue 종료를 확인했다. [Issue #27](https://github.com/Ahn-SooHyun/kbo-insight-ai/issues/27)의 정규시즌 전망 v1.0.0 구현은 원격 `16398f8`에서 확인했으며, 사용자 전용 39개·전체 455개 테스트 및 실제 자료 실행 5건 통과를 확인했다. 정규시즌의 하위 수용·PR·병합·Issue 종료, 원본 평가 파일의 독립 검토 및 모든 모델의 2026년 최종 Test 성능은 선확정하지 않는다. [공통 문서 작성 규격](../planning/development_workflow.md#documentation-standard)을 따른다.

### 1.2 표현의 의미

| 표현               | 뜻                                                               |
| ------------------ | ---------------------------------------------------------------- |
| 확정 원칙          | 구현과 평가가 지켜야 할 경계                                     |
| 기본안 / 검증 대상 | 먼저 검토할 설계이며 데이터·성능으로 타당성을 확인해야 함        |
| 미확정             | 원본·조건·근거를 더 확인해야 함. 담당·시점·방법·사용 제한을 기록 |
| 정답               | 평가 대상 구간이 끝나고 포함·누락·정정 상태를 확인한 실제 값     |
| 예측 / 가정        | 미래 값의 추정 / 직접 확인되지 않은 조건. 실제 확정값과 구분     |
| 평가 불가          | 정답·표본·자료 정의 등 평가 조건이 충족되지 않은 상태            |

## 3. 공통 정보 경계

<a id="input-gate"></a>

### 3.1 입력 채택 조건

| 검사           | 채택 기준                                                   |
| -------------- | ----------------------------------------------------------- |
| 사건 시각      | 예측하려는 사건 이후 정보가 아님                            |
| 이용 가능 시각 | 기준 시점에 사용할 수 있었다는 근거가 있음                  |
| 집계 절단      | 최근·누적·Rolling·Expanding에 기준 시점 이후 기록이 없음    |
| 출처·정정      | 원본 버전과 당시 이용 가능 근거를 설명할 수 있음            |
| 교차 예측      | 다른 예측기의 값도 당시 생성 가능한 학습·입력으로 만든 값임 |

일반적인 과거 기록은 기준 시점 전에 완료·공개된 정보만 사용한다. 바로 그 경계에서 확정된 경기 상태·참가자처럼 입력에 필요한 값은 이벤트 순서로 선후를 입증해야 한다. 같은 시각으로 기록됐다는 이유만으로 미래 결과를 포함하지 않는다.

공개 근거 없는 실제 라인업은 사후 정답·평가에는 사용할 수 있어도 당시 경기 전 입력으로 쓰지 않는다. 과거 일정의 현재 응답은 과거 공개 상태의 증거가 아니다.

<a id="corrections"></a>

### 3.2 정정 자료와 재현 범위

사후 정정·현재 제공되는 과거 자료가 당시 버전과 다를 수 있다. 당시 입력 스냅샷이 없으면 정정된 자료를 실제 과거 실행 상태와 동일하다고 주장하지 않는다. 현재 확인 가능한 자료 기반의 소급 분석과 당시 공개 상태 재현을 구분해 한계를 기록한다.

정정된 자료는 정답의 최신 공식 버전으로 사용할 수 있으나 입력 재현의 시점 조건과 혼합하지 않는다. 정정 영향은 데이터·정답·예측·평가 버전에 연결한다.

### 3.3 결과에 붙일 맥락

대상, 예측 기준 시점, 기간, 정보 절단 기준, 입력 범위/버전, 모델·설정·실행 식별자, 확정/예측/가정/미확정 상태를 연결한다. 이는 의미 계약이며 실제 필드명·파일 형식은 후속 구현에서 정한다.

## 4. M1~M5 예측 계약

### 한눈에 보는 차이

| 모델 | 논리적 표본          | 입력을 끊는 경계       | 정답 종료           |
| ---- | -------------------- | ---------------------- | ------------------- |
| M1   | 경기 예측 1건        | 경기 시작 전 실행 시점 | 해당 경기 공식 종료 |
| M2   | 타석 예측 1건        | 타석 시작 전           | 해당 타석 확정 결과 |
| M3   | 선수·역할·월요일 1건 | 월요일 00:00 KST       | 기간별 관측 완료    |
| M4   | 타석 경계 상태 1건   | 해당 경계까지          | 경기 / 반이닝 종료  |
| M5   | 실제 투구 예측 1건   | 해당 공 투구 전        | 해당 공 결과        |

원본의 투구 행에 타석 결과가 반복돼도 타석 표본을 중복 생성하지 않는다. 모델별로 정보 단위와 정답 귀속을 따로 정의한다.

### 4.1 M1 — 경기 결과·득점

| 계약 항목      | 정의                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 한 행의 의미   | 한 경기의 예측 1건. 공통 득점 예측기의 팀 관점 내부 호출을 경기 수로 중복 세지 않음                                       |
| 입력 의미      | 당시 이용 가능한 팀·상대 과거 기록, 전력·최근 경기력·불펜 사용량·휴식, 시점 근거가 있는 라인업/등록 정보 또는 당시 예상값 |
| 출력           | 승무패 확률, 홈/원정 득점 분포·예상 득점·예상 스코어                                                                      |
| 예측 시점      | 경기 시작 전 기록된 실행 시점                                                                                             |
| 과거 정보 범위 | 기준 시점 전에 완료·공개된 자료. 현재 경기 결과·실제 사용 선수·경기 후 집계 제외                                          |
| 정답           | 공식 종료 경기의 결과와 양 팀 최종 득점                                                                                   |
| 예측 기간      | 해당 경기 공식 종료까지                                                                                                   |
| 미확정         | 실행 시각, 무효/중단/서스펜디드 처리, 분포·양 팀 결합·꼬리·시즌 규칙 연결                                                 |

**기본안:** 공통 팀 관점 득점 예측기 1개를 홈·원정에 재사용한다. **현재 검증된 구현:** 정규시즌 공식 종료 득점의 공용 프로필 분포, 동점 가중치와 결합 확률. 양 팀 득점 의존성의 완전한 검증이나 포스트시즌/최종 Test 일반화를 주장하지 않는다. 현재 선택 입력은 13개(`competition`과 팀별 6개 과거 집계)이며 표의 다른 입력 의미는 향후 데이터·시점 근거 확인 후 채택할 후보이다. [실행 계약과 개발 결과](game_outcome_score.md).

**출력 연결 검증**

1. 확률은 유효 범위에 있고 전체 합이 정의에 맞는다.
2. 득점은 비음수이며 분포·기대득점·스코어 요약 규칙이 일치한다.
3. 최종 점수와 공식 결과가 직접 대응하는 경기에서는 결합 득점 분포의 홈 우세/동점/원정 우세 영역 합으로 승무패를 대조한다.
4. 연장·무승부·시즌 규칙과 분포의 경기 종료 의미가 맞는다. 독립 득점 가정이나 꼬리 절단을 사용하면 그 근거·영향을 기록한다.
5. 예상 스코어가 평균의 반올림인지 최빈 조합인지 명시한다. 요약 점수의 승패를 확률 예측과 동일시하지 않는다.

분류와 득점을 별도 독립 예측기로 학습하면 실제 모델 수에 포함한다. 일관성 실패를 숫자만 맞춰 숨기지 않고 가정·평가를 다시 검토한다.

### 4.2 M2 — 타석 결과

| 계약 항목      | 정의                                                                    |
| -------------- | ----------------------------------------------------------------------- |
| 한 행의 의미   | 타석 시작 전 예측 1건                                                   |
| 입력 의미      | 시작 시점의 타자·투수·주자·아웃·점수·상황과 이전 기록                   |
| 출력           | 정해진 타석 결과 분류에 대한 확률                                       |
| 예측 시점      | 타석 시작 전                                                            |
| 과거 정보 범위 | 시작까지 이용 가능한 상태·기록. 타석 중 교체·실제 투구·종료 결과 제외   |
| 정답           | 해당 타석의 공식 확정 결과                                              |
| 예측 기간      | 해당 타석 종료까지                                                      |
| 미확정         | 결과 분류, 희생타·희귀/기타 결과, 시작/종료 식별, 중단·무투구·교체 귀속 |

**교체 경계:** 시작 참가자와 최종 결과 귀속 참가자를 분리한다. 타석 도중 사후 확정된 타자·투수를 시작 입력에 넣지 않는다. 시작 참가자 식별 불가 표본은 임의로 최종 참가자로 대체하지 않고 제한·제외 근거를 남긴다.

결과 분류는 공식 기록·원본 가용성에 맞춰 고정하고 학습·검증·Test에서 같은 매핑을 쓴다. 단타·장타·볼넷·사구·삼진·기타 아웃 등의 후보를 최종 범주로 확정하기 전에 희귀·중복·특수 결과를 점검한다. **현재 검증된 구현:** `m2-plate-appearance-v2`, 시작 상태·날짜 이전 집계 41개 입력, 15개 표준 결과 클래스, 검증된 유효 타석과 제외 인덱스, 가능 결과의 평활화 및 마스크, 시간순 확률 보정. 2025년을 7월 1일 미만 보정과 해당일 이상 선정으로 분리했다. 이 구분은 2026 Test를 변경하지 않는다. 마스크·클래스 매핑·구체적 변수·선정 결과는 [타석 실행 계약](plate_appearance.md)에서 관리한다.

### 4.3 M3 — 선수 미래 성적

| 계약 항목      | 정의                                                                                                                       |
| -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 한 행의 의미   | 선수·역할·기준 월요일 1건. 기록·기간은 공동 출력 기본안                                                                    |
| 입력 의미      | 이전 출전량·Count·최근/누적 기록, 시점 근거가 있는 등록·일정 정보                                                          |
| 출력           | 7일·28일·잔여 정규시즌 출전량·Count·파생 비율, 시즌 최종 전망                                                              |
| 예측 시점      | 매주 월요일 00:00 KST를 논리적 기준으로 사용                                                                               |
| 과거 정보 범위 | 월요일 당일 기록을 모두 제외한 이전 이용 가능 정보                                                                         |
| 정답           | 관측 완료·전체 포함·누락/정정 확인된 각 미래 구간의 실제 기록                                                              |
| 예측 기간      | [t, t+7일), [t, t+28일), t부터 정규시즌 공식 종료까지                                                                      |
| 현재 구현      | v1.1.0, 타자 `history_balanced_50` 및 투수 `joint_residual_tree_depth_4_shrink_50`, 각 1개; 역할별 공동 Count 및 파생 비율 |
| 남은 검증      | 공식 등록·이적·전 경기 선수 기록과의 완전 대조, 실제 종료일 이용 가능 근거, 장기 정답 희소성·최종 Test 일반화              |

대상 선수를 미래 출전 여부로 고르지 않는다. 예측 시점의 모집단·역할 정의와 실제 정답 대상의 대응을 데이터 구축 단계에서 정한다. 출전하지 않은 선수와 원본에서 누락된 선수를 같은 상태로 취급하지 않는다.

기간·관측 완료·비율 계산의 상세 기준은 [M3 정답 계약](#m3-labels)을 따른다.

**현재 검증된 구현:** `m3-player-performance-v2`는 기준일 이전 관측 PBP에서 생성한 역할별 시즌 및 최근 28일 출전량·Count를 사용한다. 공식 등록 명단, 과거 일정 공개 스냅샷 및 사후 확인된 미래 소속 팀·시즌 종료일을 입력으로 쓰지 않는다. 세 기간의 타자 24개·투수 30개 Count를 각각 한 예측기가 출력하며, 타율/피안타율·삼진율은 동일 기간의 분자·분모에서 계산한다. 타자 예측기는 Train 기준 통계와 과거 기록률을 결합하는 통계 방식이며, 투수는 기준 통계에 공동 잔차 회귀 트리를 결합한다. 타자의 통계 방식 선정은 개발 지표를 근거로 하며 학습형 트리의 우월성을 주장하지 않는다. 시즌 최종 전망은 이용 가능한 관측 PBP 누적과 잔여 Count를 합산한 잠정 전망이다. 실제 시즌 공식 최종 선수 기록과의 동일성을 보장하지 않는다. 상세 입력·출력·설정·후보·실측은 [선수 미래 성적 실행 문서](player_performance.md)를 따른다.

### 4.4 M4 — 경기 상황 가치

| 계약 항목      | 정의                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------- |
| 한 행의 의미   | 타석 경계 상태 1건. 같은 경기·타석의 pre/post 상태 연결                                                               |
| 관점           | 타석의 공격팀을 양 경계에서 동일하게 고정. 후속 반이닝 공격팀으로 바꾸지 않음                                         |
| 입력 의미      | 경계까지의 이닝·초말·점수차·주자·아웃, 시즌 규칙, 날짜 이전 팀 기록                                                   |
| 출력           | 공격팀의 승리 확률(WP), 현재 반이닝 잔여 기대득점(RE), WPA, 잔여 기대득점 변화, 실제 득점 포함 가치, 사전 상황 중요도 |
| 예측 시점      | 타석 직전과 종료 직후 각각; 관측 가치 계산은 후속 상태 확인 후                                                        |
| 과거 정보 범위 | 경계에서 관측된 상태까지. 미래 결과·경기 후 집계 제외                                                                 |
| 정답           | 공격팀 공식 승리 여부(승리 1, 패배·무승부 0), 현재 반이닝 종료까지 실제 잔여 득점                                     |
| 예측 기간      | 승리 확률은 경기 종료, 기대득점은 현재 반이닝 종료까지                                                                |
| 현재 구현      | 버전 1.1.0, `logistic_core` 주 예측기 1개. RE와 상황 전이는 학습 통계표                                               |
| 지원 범위      | 2023~2026 정규시즌 규칙; 학습은 2025-01-01 이전, 개발 검증은 2025년, 2026년 최종 Test 미실행                          |
| 남은 검증      | 예외 종료 가상 전이, 희소 미지원 상태, 시즌별 일반화·확률 보정, 최종 Test, 포스트시즌 및 후속 기능 연결               |

**확률 정의와 관점:** `WP(s)=P(공격팀 승리 | s)`이다. 무승부는 비승리(0)에 포함한다. `1−WP(s)`는 비승리 확률로 상대팀 승리 확률이 아니다. 승리 지분 또는 승무패 3개 확률로 확대 해석하지 않는다. 독립 추론에서는 경기·타석 식별자를 상태 특징과 분리하고 전후 식별자·공격팀 및 공식 종료 증거의 일치를 검사한다. 호출자가 제공하는 기록의 실제 원본 진위까지 인증하는 것은 아니다.

**RE와 관측 가치:** `RE(s)=E[현재 반이닝 종료까지 실제 잔여 득점 | s]`이다. 3아웃 또는 확인된 공식 종료에서 RE는 0이다. 타석 후 반이닝 전환은 이전 반이닝의 종료 상태로 평가한다. 같은 공격팀의 타석 전후 확률 차 `WPA=WP(post)−WP(pre)`를 계산하고, `ΔRE=RE(post)−RE(pre)`와 `run_value=actual_runs+ΔRE`를 별도로 제공한다. 실제 발생 사건의 가치는 사후 계산값이며 사전 입력·독립 실제 정답·인과효과가 아니다.

**관측 종료와 가상 종료:** 2023~2024 정규시즌 최대 12회, 2025~2026 최대 11회 규칙을 적용한다. 실제 관측은 공식 종료 상태·마지막 타석·최종 득점·품질 근거 일치 시 확정 승리값 1 또는 비승리값 0을 사용한다. 경기 계속 3아웃은 WP를 예측기로 계산한다. 종료 증거가 없으면 공식 종료로 확정하지 않는다. 가상 정상 규칙 종료는 현재 시즌의 최대 이닝·공수·득점·아웃 규칙으로 별도 처리한다. 예외 종료의 발생 확률은 학습하지 않는다.

**상황 중요도:** 사전 실제 이닝·초말·점수차·아웃·주자 상태에서 Train의 물리 전이 `(득점, 후속 아웃, 후속 주자 마스크)`를 집계한다. 경험 전이 확률 `q(t|s)`로 `D(s)=Σ q(t|s)×|WP(s_t)−WP(s)|`를 계산한다. 지원되는 Train 사전 상태의 등장 횟수 가중 평균 `D_ref`에 대해 `LI(s)=D(s)/D_ref`로 정의한다. 전이 지원 수 30 미만, 지원 참조 평균 미확정·0 이하 또는 post 상태는 null과 사유를 반환한다. 실제 평가 타석 결과나 과거 전이의 공식 종료 정답을 사용하지 않는다. 현재 시즌 정상 규칙으로 가상 종료를 결정한다. 기존 시즌의 물리 전이 분포를 재사용하는 가정은 별도의 일반화 한계로 유지한다. 표준 MLB LI와 동일한 값 또는 선수의 인과적 공헌으로 주장하지 않는다.

**선정과 평가:** 빈도 기준과 로지스틱 4개 후보를 동일 시간 분할로 비교하고 Validation Log loss, 동률 시 Brier에 따라 `logistic_core`를 선택했다. 34개 허용 열 중 상태 입력 계약은 22개, 선정 후보는 12개 수치 특징을 사용한다. 팀 이력을 추가한 후보 22개 특징은 비교에만 사용했다. RE는 Train 조건부 평균과 지원 후퇴로 계산한다. 별도 보정기를 적합하지 않았고 ECE 악화 및 상황 중요도 지원 한계를 기록한다. M2와의 직접 연결은 현재 범위가 아니다. [실행 계약 및 실측 결과](game_state_value.md), [강의 원리·확장](game_state_value.md#lecture-methods), [경계 및 한계](game_state_value.md#limitations)에서 구체적 입력·설정·지표·실행 식별자를 관리한다.

구종·결과 공동 출력은 주변 확률 합과 일치해야 한다. 희소/미출현 조합의 처리와 분류 매핑은 비교 전에 고정한다. 실제 투구가 없는 자동 판정·무투구 타석을 투구 표본으로 세지 않는다.

검증된 실제 투구의 구종·결과 코드를 공동 범주로 보존한다. 위치 값은 의미·좌표계·단위 미확정이며 이번 주 예측기와 입력/정답에서 제외한다. 희소 또는 학습 자료에서 미출현한 범주의 처리 방침은 학습 자료만으로 결정한다.

**현재 검증된 구현:** `m5-pitch-outcome-v2`는 선택 입력 21개, 공동 사전 70개를 고정한다. Train 442,636구, Validation 216,869구를 사용했다. Train 사전 평활 및 조건부 빈도 기준, 기본 다항 로지스틱 및 규제·온도 후보를 비교했다. 2025년을 7월 1일 미만 보정, 7월 1일 이상 9월 1일 미만 선정, 9월 1일 이상 선정 미사용 추가 평가로 분리했다. 공동 확률을 우선 선정하고 구종·결과 주변 지표도 함께 공개한다. 최종 운영 모델의 계수에 단일 온도 1.15를 반영하므로 독립 모델은 1개다. 미출현 구종·조합에 양의 확률을 주지만 새로운 구종의 일반화를 보장하지 않는다. 전체 2025년은 선행 개발에서 이미 관찰했으므로 최종 독립 Test가 아니다. [실행·학습·실측 계약](pitch_outcome.md), [강의 원리](pitch_outcome.md#lecture-methods), [한계](pitch_outcome.md#limitations)를 따른다.

## 5. M3 기간·관측 완료·기록 일관성

<a id="m3-period"></a>

### 5.1 기간 경계

기준 월요일을 t로 두고 KST 기준으로 해석한다.

| 기간      | 포함 범위                         | 주의점                                         |
| --------- | --------------------------------- | ---------------------------------------------- |
| 7일       | [t, t+7일)                        | 시작 월요일 포함, 다음 월요일 제외             |
| 28일      | [t, t+28일)                       | 시작 포함, 28일 뒤 경계 제외                   |
| 잔여 시즌 | t부터 해당 정규시즌 공식 종료까지 | 포스트시즌 혼합 금지, 종료·전체 포함 근거 필요 |

월요일 당일 기록은 정답에는 들어갈 수 있지만 입력에서는 모두 제외한다. 실제 실행이 늦어도 논리 기준을 늦추지 않는다. 시즌이 고정 기간 안에서 끝나면 정규시즌 기록만 집계하고 남은 날짜가 있다는 이유로 미래 포스트시즌 기록을 넣지 않는다.

기준 시점에 해당 정규시즌이 이미 끝났다면 잔여 시즌 미래 예측 대상으로 취급하지 않는다. 종료된 시즌의 확정 기록과 미래 예측을 분리하고, 대상 밖 상태를 누락·예측 실패·정답 0과 혼동하지 않는다.

연기·서스펜디드·자정 경계 경기의 기록 귀속일과 실제 이용 가능 시각은 별개다. 데이터 구축 단계에서 공식 집계와 원본 순서를 대조해 귀속 규칙을 고정한다.

### 5.2 출전량·Count·파생 비율

| 항목      | 기준                                                                       |
| --------- | -------------------------------------------------------------------------- |
| 출전량    | 타석·타수·상대 타자·아웃 등 가용한 노출량을 정의하고 기록과 함께 예측·평가 |
| Count     | 비음수와 구성/상위 기록 관계를 검사. 원본 확인 전 전체 목록 확정 금지      |
| 이닝      | 단순 소수로 산술하지 않고 아웃 수 등 일관된 표현으로 계산                  |
| 비율      | 같은 기간의 예측 분자·분모로 계산. 분모 0은 null과 사유로 표시             |
| 시즌 전망 | 실제 누적 Count + 잔여 예측 Count를 먼저 계산한 뒤 비율 산출               |

예를 들어 타율은 안타/타수다. 출루율·장타율·OPS 등은 필요한 구성 기록과 공식 계산 정의를 확보한 경우에만 제공한다. 실제 비율과 미래 비율을 단순 평균하지 않는다. 분모가 다른 비율의 비교에서는 분모 규모·평가 가능 범위를 함께 보고한다.

<a id="m3-state"></a>

### 5.3 정답 상태 의사결정

| 상태                                     | 정답 처리                | 학습·평가                   |
| ---------------------------------------- | ------------------------ | --------------------------- |
| 미래 구간 미종료                         | 미관측                   | 확정 정답으로 사용 금지     |
| 구간 종료, 원본 누락·정정 미확인         | 미확정                   | 0 대체 금지, 제한·제외      |
| 구간 전체 확보·집계 완전, 실제 기록 없음 | 실제 Count 0 가능        | 모집단·정의 충족 시 사용    |
| 시즌 종료·전체 포함·정정 확인            | 잔여 시즌 정답 확정 가능 | 관측 완료 시점 검사 후 사용 |

선수 행이 없다는 사실만으로 출전하지 않았다고 단정하지 않는다. 대상 목록·경기 기록·수집 완전성을 대조한다. 불완전한 28일을 관측된 날짜만 합쳐 완전한 28일 정답처럼 만들지 않는다.

<a id="m3-overlap"></a>

### 5.4 학습 시각·겹치는 구간

학습 실행 시점까지 전체 정답 구간이 관측·이용 가능해진 표본만 학습한다. 기준 월요일이 과거라는 것만으로 충분하지 않다.

Backtesting에서의 학습 시점은 실제 재실행한 오늘이 아니라 해당 과거 평가 구간의 **논리적 학습 기준 시각**이다. 정답 관측 완료도 그 시각으로 검사한다. 실제 프로그램 실행 시각은 실행 이력으로 별도 남긴다.

분할 경계에서는 학습 표본의 정답 구간 종료·관측 완료를 검사한다. 검증·Test 미래 구간에 걸치는 학습 표본을 제거한다. 그 뒤의 재학습에서도 실행 당시 관측 완료된 정답만 추가한다.

공동 출력 일부가 미관측이면 임의 0을 넣지 않는다. 부분 정답 마스크를 알고리즘이 안전하게 지원하는지 검증하고, 지원하지 않으면 요구 정답이 모두 관측된 표본만 학습한다. 어떤 기간·기록이 학습·평가됐는지 기록한다.

평가 내부의 겹치는 미래 구간은 서로 독립이라고 과장하지 않는다. 기준 주·기간·시즌별 결과, 중첩 관계와 해석 한계를 보고한다.

### 5.5 일관성 검사

- 비음수, 하위 Count ≤ 관련 상위 Count·출전량
- 동일 모집단·정의에서 7일 Count ≤ 28일 Count
- 잔여 시즌과 고정 기간의 포함 관계는 실제 시즌 경계에 따라 검사
- 파생 비율의 분자·분모·구성 기록 간 대응
- 누적 실제 기록과 잔여 예측의 중복·누락 방지

Count의 기대값은 소수일 수 있으며 무조건 정수로 반올림하지 않는다. Count 단조 관계를 타율 등 비율에 그대로 강제하지 않는다. 제약·후처리를 사용하면 규칙·버전·평가 영향을 남긴다.

현재 구현은 `7d ≤ 28d ≤ remaining` 및 Count 구성 관계를 검사한다. 기준 시점에 확인 가능한 시즌 종료 경계를 제공한 별도 시나리오에서는 포함 관계가 같은 창의 Count를 일치시킨다. 실제 과거 종료일을 사후 입력하여 평가 성능이나 일관성을 인위적으로 개선하지 않는다. 종료 경계를 알 수 없는 일반 예측에서 실제 종료일을 기준으로 같은 기간이 된 정답 쌍의 예측 차이는 진단값으로 보고한다.

<a id="evaluation"></a>

## 6. 평가 원칙

### 6.1 무엇을 비교하는가

같은 문제 안에서 같은 시점·기간·표본·분할·지표로 기준 모델과 후보를 비교한다. 다른 모델군의 점수를 직접 우열로 해석하지 않는다. 표본이 달라지면 공통 표본 비교와 각 방식의 적용 범위를 함께 제시한다.

기준 모델도 학습 범위에서만 추정하고 동일한 정보 제한을 적용한다. 기준 모델의 선택·집계 창·조건화·희소 후퇴·평활화·수치 처리는 최종 Test 전 고정한다.

주 지표·보조 지표·후보 선택 규칙은 후보 비교 전에 정한다. 세부 지표를 확정할 원본 근거가 부족하면 그 비교를 보류한다. 여러 지표의 결과가 엇갈리면 미리 정한 선택 기준과 장단점을 함께 보고하고 유리한 지표만 남기지 않는다.

<a id="metrics-probability"></a>

### 6.2 분류·확률 출력

| 대상              | 주요 지표·이유                                                                  | 기준 모델                                                       |
| ----------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| M1 승무패         | 다중분류 Log loss: 실제 결과 확률 평가. Brier score·신뢰도 도표: 확률 오차·보정 | 학습 구간 결과 빈도, 근거 있는 홈/원정 조건화                   |
| M2 타석           | Log loss·Brier score: 확률 품질. Macro F1·범주별 결과: 희귀 범주 확인           | 학습 타석 결과 빈도, 필요 시 과거 입력으로만 조건화             |
| M4 승리 확률      | 정답 정의에 맞는 Log loss·Brier score·신뢰도 도표                               | 학습 상황별 결과 빈도와 희소 상황 후퇴 규칙                     |
| M5 구종·결과      | 공동 및 주변 Log loss·Brier score·범주별 결과, top-label 및 macro classwise ECE | 학습 공동/주변 빈도, 현재 공의 정답 구종 사용 금지              |
| 정규시즌 1위·진출 | 이진 Brier 및 Log loss, 유효 분모·공동 분모·미확정 사유 병기                    | 동일 M1 자산의 홈·원정 기준 분포, 동일 일정·규칙·반복 횟수·Seed |

Accuracy는 확률 보정을 설명하지 못하므로 보조로 사용한다. 범주별 표본·지원 범위와 희귀 결과를 함께 보고한다. M4는 공식 공격팀 승리=1, 패배·무승부=0인 이진 사건에 대한 Log loss 및 이진 Brier score `(p−y)^2`의 평균을 사용한다. 10개 신뢰도 구간 및 ECE를 진단 지표로 기록하고, 다중분류 Brier와 이진 Brier의 정규화 차이를 혼동하지 않는다.

**계산 정의:** Log loss는 실제 범주에 부여한 확률의 음의 로그를 평균한다. 다중분류 Brier score는 예측 확률과 정답 원핫 값의 제곱 오차를 범주에 대해 합한 뒤 표본 평균하는 정의를 사용하고, 다른 정규화가 있으면 명시한다. 공동 확률과 주변 확률은 각각 다른 평가 대상이다. M5의 top-label ECE와 macro classwise ECE는 각각 최상위 예측의 신뢰도와 전체 클래스별 one-vs-rest ECE의 동일 가중 평균으로 구분한다. 각 평가 축의 bin 분모와 실제 지원을 보존한다. [M5 지표 산식](pitch_outcome.md#evaluation)을 따른다.

확률 0·미출현 범주·공동 조합·수치 절단·평활화는 사전 규칙을 고정한다. Test 결과를 보고 점수 계산 방식을 유리하게 바꾸지 않는다. 정규시즌 사건은 팀별 유효 반복에서 계산한 조건부 확률과 실제 완료 시즌의 이진 결과를 비교한다. 팀별 유효 분모가 서로 다를 수 있으므로 결과를 무조건 확정 확률 또는 모든 후보가 동일한 유효 반복에서 계산한 성능으로 확대 해석하지 않는다. [정규시즌 지표](regular_season_standings.md#evaluation)를 참조한다.

### 6.3 수치·Count·분포 출력

| 대상                    | 주요 지표·이유                                | 기준 모델                                              |
| ----------------------- | --------------------------------------------- | ------------------------------------------------------ |
| M1 득점 점 예측         | MAE: 일반 오차, RMSE: 큰 오차 민감도          | 학습 득점 평균/중앙값 등 지표에 맞는 고정 기준         |
| M1 득점 분포            | Log score 또는 이산 CRPS: 분포 품질           | 학습 경험 분포, 결합 평가는 결합 출력 정의 후 사용     |
| M3 출전량·Count         | 기록·기간별 MAE·RMSE: 서로 다른 규모를 분리   | 과거 노출량 추세와 단위 노출량당 기록의 지속/평균 기준 |
| M3 파생 비율            | 유효 분모 표본 MAE와 분모 규모·평가 범위      | 기준 Count에서 동일 분자/분모 계산                     |
| M4 기대득점             | 반이닝 잔여 실제 득점 대비 MAE·RMSE           | 학습 상황별 평균과 전체 평균                           |
| 정규시즌 최종 승수·순위 | 실제 완료 시즌 팀별 승수·순위 대비 기대값 MAE | 동일 규칙과 일정 아래 홈·원정 기준 계산                |

MAE는 절대 오차 평균, RMSE는 제곱 오차 평균의 제곱근이다. 기록 단위·기간·표본 수와 함께 보고한다. 규모가 큰 Count의 오차가 다른 기록을 가리지 않도록 임의 합산 점수만 제시하지 않는다.

M1의 주 분포 지표는 출력이 확률질량함수인지 누적분포인지, 꼬리 처리와 결합 정의가 무엇인지 확인한 뒤 모델 비교 전에 고정한다. 지표를 모두 계산하더라도 사후에 유리한 것만 골라 승자를 정하지 않는다.

M3 기준 모델은 미래 실제 출전량을 입력으로 쓰지 않는다. 미래 출전량을 가정하거나 예측하면 그 방식·범위를 명시한다. 예측 구간을 제공할 경우 관측 포함률과 폭을 함께 평가하며 지원되지 않는 구간을 발명하지 않는다.

M3 v1.1.0은 역할별 11개 후보를 동일한 시간 분할과 기록별 마스크에서 비교한다. Train에서 정한 척도로 정규화한 macro MAE의 개선(1e-12 초과)과 macro RMSE 비악화(1e-12 허용 오차)를 채택 조건으로 하며, MAE·RMSE·고정 후보 순서로 선정한다. 해당 후보가 없으면 기준 모델을 유지한다. 비율은 모든 후보 공통 유효 분모 및 후보별 쌍 비교를 구별한다. 시간순 학습 외 잔차에서 적합한 Count 구간의 목표 포함률 90%는 보장값이 아니다. 실제 포함률·폭·지원 수 및 미지원 사유를 기록하고 2025년 평가 재사용과 2026년 최종 Test 미사용을 구분한다.

### 6.4 위치 출력 (현재 제외)

좌표 기반 위치 예측은 현재 주 예측기 및 데이터 정답에 포함하지 않는다. 원본의 좌표 후보는 보존하되 단위·축·원점·방향·유도 근거가 확정되지 않았으므로 원점 대체, 임의 변환, 위치 성능 계산을 하지 않는다. 향후 범위를 변경하더라도 범위 변경 검토와 별도의 좌표 계약·검증을 먼저 요구한다.

### 6.5 보조 기능

라인업은 명단 적중, 타순·수비 위치 일치, 선발투수 식별 등 출력별로 평가한다. 후보 목록은 후보집합·제공 개수·순위 지표·정답 시점을 고정한다. 과거 사용 빈도·최근 패턴을 기준으로 비교한다.

선수의 실제 내부 가용성이나 교체 이유를 정답으로 만들지 않는다. 조건부 항목은 허용된 관측 이벤트·범위에서만 평가한다. 정답 정의가 확보되지 않은 부분은 평가 불가로 표시한다.

### 6.6 시간 분할과 Backtesting

1. **자료 근거 확인:** 수집 범위·시즌 완료·정답 포함·누락·정정을 확인한다.
2. **분할 고정:** 학습 → 검증 → 최종 Test 날짜와 경기 목록을 데이터 구축 단계에서 확정한다.
3. **경기 묶음:** 같은 경기의 타석·투구를 학습·평가 양쪽에 나누지 않는다.
4. **정답 완료:** M3는 정답 구간 관측 완료가 학습 시점 이전인지 검사한다.
5. **학습 처리 분리:** 결측 대체·Encoder·스케일링·변수 선택은 각 학습 구간에서만 맞춘다.
6. **과거 시점 반복:** 당시 입력·완료 정답만 사용해 학습·예측한다. 창·재학습·갱신 규칙을 보존한다.
7. **보정 분리:** 시간 순서상 분리된 검증 또는 과거 시점별 예측을 사용한다.
8. **Test 잠금:** 모델·변수·설정·보정 선택에 최종 Test를 사용하지 않는다.

모델 자료 생성은 Validation 시작 2025-01-01, 최종 Test 시작 2026-01-01, 관측 종료 배타 경계 2026-11-26 KST를 기본 검증 실행의 명시 인자로 사용한다. M1은 2001년부터, 사건·선수 자료는 2023년부터의 가용 범위를 활용한다. 실제 표본 수·기간·제외는 실행 명세에 기록한다. 시간 경계를 성능에 맞춰 이동하지 않는다. 최종 Test를 재조정에 사용했다면 그 자료는 독립 최종 평가로 남길 수 없으며 한계·새 평가 계획을 분리한다.

시즌의 경우 실제 경기 결과 입력의 날짜 절단만 충족한다고 당시 정보 기반 Backtesting이 되지 않는다. 일정 공개 판본과 당시 이용 가능했던 모델 학습·선정의 논리적 시점을 함께 입증해야 한다. 현재 정규시즌의 `formal_backtest_supported=false`, `final_test_used=false`는 이러한 조건을 충족하지 않은 2025년 개발 진단임을 명시한다.

### 6.7 다른 예측기의 출력·설명·오류 분석

예상 라인업 등 다른 모델의 값을 입력으로 쓰면 각 과거 시점에서 학습·생성 가능한 예측만 사용한다. 전체 자료를 학습한 모델의 과거 적합값은 금지한다. 상위 예측기의 학습 범위·입력·생성 시점·버전을 연결한다.

보정·설명·오류 분석은 모델 개발 중 반복한다. 전체 설명과 개별 설명을 구분한다. SHAP은 모델의 예측 기여도이며 인과관계·실제 몸 상태·감독 의도의 증거가 아니다. 최종 Test의 실패 사례를 설명하되 그 결과로 선택을 다시 하면 평가 지위가 달라진다.

### 6.9 실제 모델 자료 인수 계약

`model_data.sqlite3`의 각 모델별 `<model>_inputs`, `<model>_targets`, `<model>_index`를 `sample_id`로 연결한다. `index`는 날짜·분할·키·후보 상태의 명세이며 ML 입력 열이 아니다. 선수 정답은 `(sample_id, horizon)`을 키로 사용하며 역할별 공동 출력으로 연결한다. `m3_window_games`는 실제 관련 정규 경기 ID를, `m3_window_teams`는 해당 정답의 품질 검증 대상 팀을 보존한다. `player_game_role_quality`와 `player_identity_evidence`는 감사 근거이며 입력 변수가 아니다.

- 팀 과거 집계는 같은 시즌 정규시즌의 엄격히 앞선 날짜만 사용한다. 최근 기록은 28일, 같은 날의 더블헤더 결과는 모두 제외한다. 과거 공개 판본 미확인이므로 실제 당시 발표 상태의 완전 재현을 주장하지 않는다.
- M2는 시작 참가자와 시작 상태만 입력한다. 모든 표준 타석은 `m2_index`에 상태·제외 사유·시작/종료 참가자·귀속 후보·무실제 투구·원본 품질 플래그와 함께 보존하고, 유효 후보만 입력/정답으로 사용한다. M4는 공격팀 고정 관점의 타석 전후 상태를 각각 보존하며 검증된 반이닝 종료 득점에서 각 기준점의 득점을 뺀다. 마지막 홈 우세인 부분 반이닝은 관측 종료 후보로 별도 표시한다. M5는 현재 실제 공 직전 상태 및 같은 타석의 앞선 실제 공만 사용한다.
- M3 모집단은 기준 월요일 00:00 KST 이전 해당 시즌에서 식별된 관측 참가자다. 역할과 마지막 관측 팀을 보존하며 실제 미래 팀 변경을 입력하지 않는다. M2·M3·M5 및 선발 이력은 원본 이름 최초 관측일을 연결하고 충돌이 기준 날짜 전에 관측된 경우만 해당 시즌·팀의 식별 제한을 반영한다. 경기별 기본 품질 판정을 사용하되 미래 이름 충돌을 입력에 소급하지 않는다. 정답은 최종 품질 판정에서 채택된 기록을 합산한다. 개인 격리·관측 누락 및 알려진 과거/실제 관측 팀의 역할별 경기 상태·팀 집계 불일치·식별·역할 행 누락을 검사한다. `valid_observed`는 관측된 참가자·관련 팀 기준의 후보로, 그 외 팀의 미확인 이동이나 공식 등록·출전 전체를 보장하지 않는다. `zero_observed`는 리그 해당 역할에 경기·식별 위험과 격리 기록이 없으며 검증된 관측 범위에 참가 기록이 없는 경우에 한정한다. 불완전·미관측·분모 0은 NULL 마스크로 남긴다. 기존 판본에서는 2023~2025 정규시즌 완료 근거가 없어 잔여 정답을 확정하지 않았다. 보완판에서는 세 시즌 각각 완료 경기 720개와 PBP 집합·공식 종료 근거를 대조하여 잔여 정답을 재생성했다. 유효 Count 정답이 생성된 것이 선수별 공식 등록·전체 기록의 완전성을 뜻하지 않는다. 2026 정답을 학습으로 옮기지 않는다.
- `usable=1`인 선수 기간만 Count 학습 후보로 사용하고 비율은 유효 분모가 있는 열만 사용한다. 실제 관측 종료가 학습/검증 경계를 넘는 창은 제외한다. 겹치는 기간은 독립 표본이 아니다. 자책점·ERA는 관측 PBP 집계만으로 확정하지 않는다.
- `train_eda.json`은 학습 분할만 탐색한다. Validation/Test의 표본 수와 상태 검사는 허용되나 정답 분포 탐색·학습 및 최종 성능 평가는 후속 범위다. `feature_target_contract.json`은 입력 허용 열과 정의를 기록한다. 모든 학습형 전처리는 훈련 자료에서만 fit한다.
- `manifest.json`은 입력 DB/품질판본·원본/중간 해시·실행 설정·표본 집계·논리 해시·재생성 비교 결과를 기록한다. 생성기 판본 1.1.0은 시점별 식별·팀 역할 품질 및 M2 제외 인덱스를 확장했다. 현재 인수 판본 1.2.0은 포스트시즌과 정규시즌 종료 근거를 보완한다. 변경된 판본을 이전 생성 판본과 동일 입력·코드의 재현 비교로 처리하지 않는다. 데이터는 로컬 대학 과제 및 내부 평가용으로 제한하며 자료 공개 재배포를 하지 않는다.

### 7.1 출력별 의미

| ------------------ | ----------------------------------------- |
| 최종 승수·순위     | 완료된 정규시즌의 팀별 공식 승수·순위     |
| 정규시즌 우승      | 정규시즌 최종 1위 팀                      |

### 7.2 일정·규칙·조건부 확률

당시 알려진 일정, 미편성/변경 상태, 홈·원정, 동률·대진·차전·승리 조건·무승부 규칙을 확인한다. 시즌별 공식 근거와 적용 버전을 보존한다.

특정 대진 성립을 전제로 한 확률과 현재 시점의 전체 진출·우승 확률을 구분한다. 미래 일정이 미확정이면 가정을 표시한다. 과거 일정 스냅샷이 없으면 가정 시나리오와 실제 당시 정보 기반 Backtesting을 구분한다.

<a id="season-valid-denominators"></a>

### 7.5 유효 분모와 순위 미확정 계약

반복 횟수를 $N$, 팀 $i$의 특정 지표에 대한 유효 반복 수를 $n_i$, 사건 성공 수를 $k_i$로 놓으면 보고 확률은 $\widehat{p}_i=k_i/n_i$이다. $n_i=0$이면 확률과 기대값을 `null`로 유지한다. $N-n_i$는 결과 미확정 반복이며 실제 실패나 0으로 간주하지 않는다. $n_i>0$에서 $k_i=0$인 경우의 0과 `null`은 다른 값이다. 미확정 반복이 있는 사건의 무조건 확률은 이 구현에서 직접 확정하지 않는다. 모의 경로 내부에서 미확정 사건이 모두 실패/성공한다고 가정한 범위는 $[k_i/N,(k_i+N-n_i)/N]$이다. 이는 해석용 보수적 경계이지 구현이 별도로 저장하는 확률 구간 또는 신뢰구간은 아니다.

| 집계 범위       | 유효 반복의 조건                        | 불변 조건                                          |
| --------------- | --------------------------------------- | -------------------------------------------------- |
| 팀별 최종 승수  | 팀의 전체 정규시즌 경기 수 완료         | 0~144 정수 범주의 조건부 분포 합 1                 |
| 팀별 순위       | 해당 팀 순위 확정                       | 1~10 범주 합 1; 동률·불완전 일정 시 미확정 가능    |
| 팀별 1위·진출   | 해당 사건이 확정                        | 이진 분포 합 1; 순위 미확정이어도 진출은 확정 가능 |
| 리그 공동 1위   | 모든 팀의 1위 상태가 동시에 확정        | 팀별 공동 확률의 합 1                              |
| 리그 공동 진출  | 모든 팀의 진출 상태가 동시에 확정       | 팀별 공동 확률의 합 5                              |
| 포스트시즌 시드 | 정확히 5개 진출 팀의 상위 순서 1~5 확정 | 같은 반복의 팀 집합·순위 일치; 미확정 시 null      |

개별 팀별 확률은 서로 다른 유효 분모를 가질 수 있으므로 리그 합계가 반드시 1 또는 5가 되지는 않는다. 리그 전체 합을 확인할 때에는 공동 분모의 확률을 사용한다. 동률이 해소되지 않았어도 상위 5팀 집합에 포함된다는 사실은 확정될 수 있다. 예를 들어 1·2위 결정전이 필요한 두 구단 모두 진출은 확정이지만 1위 및 상위 순서는 미확정이다. 해당 반복을 임의 시드로 보완하지 않는다.

### 7.6 현재 개발 평가 및 해석

대표 실행 `e24254420aee4d52acf2b1fb144c3d58`은 2025-09-01 KST 자정, 사후 일정 가정, 완료 622경기·잔여 98경기·누락 0, 1,000회 반복·Seed 42의 개발 진단이다. 사용자 로그에서 1위 공동 유효 984·미확정 16회, 진출 공동 유효 922·미확정 78회, 시드 확정 906회를 확인했다. 실제 완료 시즌의 10팀에 대해 홈·원정 기준 계산과 동적 M1 결과를 비교했다.

| 승수 MAE(승)  |    2.323900 |    2.133400 | 기대 최종 승수의 절대 오차      |
| 순위 MAE(위)  |    0.869456 |    0.743546 | 기대 순위의 절대 오차           |

### 7.7 포스트시즌 인계 계약

후속 [Issue #28](https://github.com/Ahn-SooHyun/kbo-insight-ai/issues/28)에서 구현할 한국시리즈·시리즈 전망은 현재 정규시즌 기능의 완료 범위에 포함하지 않는다. 인계는 주변 확률이 아니라 부모 `iterations.jsonl`의 `iteration_id`, `teams`, `qualifiers`, `postseason_seeds`, `rank_resolved`, `qualification_resolved`와 매니페스트를 기준으로 한다. 부모 실행 ID·스키마 `regular-season-iteration-v1`·SHA-256·일정 및 규칙 버전·기준 시각을 검증한다. `qualifiers`는 순위순이 아니라 정렬된 팀 ID 집합이며 `postseason_seeds`만 1~5위 순서다. 미확정 시드를 다시 뽑거나 팀별 진출 확률을 독립 표본 추출하여 대진을 조합하지 않는다. 시드 유효 분모와 이후 시리즈 평가 분모를 각각 기록한다. 후속 시리즈 규칙·홈구장·무승부·확정 결과·예측기 포스트시즌 지원 여부를 독립 검증한다. [정규시즌 후속 연결](regular_season_standings.md#limitations)을 따른다.

## 8. 모델 수와 검증되지 않은 설계

### 8.1 기본 구성

| 기능군   | 최종 주 예측기 목표 | 기본 구조                                                |
| -------- | ------------------- | -------------------------------------------------------- |
| M1       | 1                   | 공통 팀 관점 득점 예측기, 분포에서 경기 출력 계산        |
| M2       | 1                   | 공통 타석 결과 분류기                                    |
| M3       | 2                   | 타자·투수 각 1개, 기록·기간 공동 출력                    |
| M4       | 1                   | 승리 확률 예측기, 기대득점은 통계·WPA/상황 중요도는 계산 |
| M5       | 1                   | 구종/결과 공동 예측기; 위치 예측 제외                    |
| **합계** | **6개**             | 현재 확정 구성; 실제 학습·성능은 모델별 검증             |

현재 M1·M2·M4·M5 각 1개와 M3 타자·투수 각 1개로 개발 검증 근거가 있는 주 예측기는 총 6개다. M5와 M3 병합·Issue 종료를 확인했다. M3 역할별 11개 비교 후보 및 내부 공동 출력·기준 통계·구간 적합 요소, M5 실험 후보 6개 및 온도·통계표는 별도 운영 주 예측기로 더하지 않는다. 타자 통계 방식과 투수 공동 회귀 트리의 차이는 명시한다. 정규시즌은 저장 M1·규칙·난수를 사용하며 신규 독립 예측기 수는 0개다. 홈·원정 개발 기준 계산, 캐시 및 반복 결과는 학습한 운영 모델을 추가한 것이 아니다.

### 8.2 집계 규칙

- 팀·선수·기간·기록별 개별 예측기를 늘리지 않는다.
- 한 파일에 여러 독립 예측기를 묶어도 실제 독립 개수로 센다.
- 출력별 독립 예측기를 만드는 래퍼도 실제 독립 개수를 센다.
- 실험 후보·기준 모델과 최종 운영용 주 예측기를 구분한다.
- 전처리·보정의 학습 요소와 통계표·제약·시뮬레이션 설정은 별도 기록한다.

### 8.3 반드시 검증할 가정

| 가정               | 확인할 것                                                                       | 실패 시                                                                            |
| ------------------ | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |

| M3 공동 출력       | 기록/기간/노출량 일관성·부분 정답·분모                                          | 제약·제외·대안과 평가 영향 기록                                                    |

## 10. 재현성·저장·설정 계약

### 10.1 자료의 단계

```text
raw ── 변환/수정/제외 이력 ──> interim ── 검증/입력 구성 ──> processed
 │                                  │                          │
 └──────────── 부모 자료·버전·실행 식별자로 연결 ─────────────────┘
```

위 이름은 자료 경계의 의미다. 실제 물리 경로·파일 형식은 개발 기반에서 정한다. 원본은 수정·덮어쓰지 않는다. 재수집·공식 정정은 별도 버전으로 보존한다.

### 10.2 남길 이력

| 이력       | 필수 의미                                                                                                                    |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 수집       | 출처·수집 시각·기간·요청 조건·파일·버전·포함/누락·실패                                                                       |
| 변환       | 부모 원본·처리 단계·변환 설정·수정/제외 이유·영향 범위                                                                       |
| 분할       | 시간 경계·경기 목록·정답 완료 검사·누수 제한                                                                                 |
| 학습       | 데이터·변수·정답·전처리·설정·Seed·모델·보정 자산                                                                             |
| 예측·평가  | 대상·시점·기간·사용 자산·예측/정답·지표·집계·제외                                                                            |
| 시뮬레이션 | 부모 데이터/모델/실행 ID 및 해시, 시즌·기준 시각·규칙·일정 가정·Seed·반복 수·유효 분모·출력 스키마·파일 해시·완료 매니페스트 |

버전은 사용한 자산의 상태를, 실행 식별자는 수행 1건을 식별한다. 같은 설정의 반복 실행도 별도 수행으로 추적할 수 있어야 한다. 실제 명명법·스키마는 후속 구현에서 정한다. 정규시즌의 완료 매니페스트는 모든 결과 파일을 기록한 후에 저장하며, CLI의 `iterations`(정수)와 `iterations_path`(경로)를 구분한다. 매니페스트 내 `files.iterations` 경로/해시 계약은 유지한다. 실제 재현은 [정규시즌 실행 명령](regular_season_standings.md#commands)으로 확인한다.

### 10.3 저장 경계와 책임

| 대상                | 경계·책임                                                  |
| ------------------- | ---------------------------------------------------------- |
| 원본·중간·처리 자료 | 원본 보존, 변환/제외 추적, 품질 확인 상태 분리             |
| 모델·전처리·보정    | 학습 자산·입력 정의·분할·설정 연결                         |
| 예측·평가·보고      | 재생성 가능한 결과와 사용 버전·실행 연결                   |
| 소스·테스트·문서    | 동작·기준·검증의 변경 관리                                 |
| 캐시                | 재생성 가능한 임시 자산. 유일한 원본·재현 근거로 사용 금지 |
| 기준 경로·설정      | 임의 실행 위치로 출력 위치가 달라지지 않게 해석 책임 명시  |
| 로그                | 레벨·실행 맥락·오류를 남기되 비밀값 제외                   |

개발 기반 담당은 실제 경로·설정·저장·로그 경계를 구현한다. 데이터 구축은 수집·변환 이력을, 모델/통합 이후는 학습·예측·평가 연결을 채운다. 이것은 다음 개발 작업의 인수 계약이며 환경 구현을 선행하지 않는다.

### 10.4 Secret과 Git 추적

실제 Secret·환경 파일·대용량 데이터·모델·캐시의 추적 경계를 실제 구조에 맞춰 정한다. 필요한 경우 비밀값 없는 `.env.example`만 추적하고 `.env`·`.env.production`은 추적하지 않는다. 다른 `.env` 변형을 늘리지 않는다.

요청 조건을 남길 때도 Token·Key·Password 등 비밀값은 제거한다. 코드·Notebook·문서·설정·테스트·로그에 비밀값을 넣지 않는다. 데이터·코드의 사용/재배포 조건은 출처별 확인 근거와 함께 관리한다.

<a id="data-use-scope"></a>

### 10.5 자료 이용 범위와 결정 근거

2026-11-25에 기록된 프로젝트 내부 사용 범위는 비영리 대학 과제용 로컬 표준화·학습 및 내부 모델 평가로 한정한다. 실제 병합된 [전체 자료 수집 및 원본 버전 관리 PR #12](https://github.com/Ahn-SooHyun/kbo-insight-ai/pull/12)의 기타 항목에 이 범위, 기존 원본·명세의 허용 용도 기록 보존, 공개 재배포·외부 서비스 제외가 명시되어 있다. 관련 작업은 [Issue #7](https://github.com/Ahn-SooHyun/kbo-insight-ai/issues/7)이다. 이 기록은 권리자의 별도 이용 허락을 대체하지 않으며 원천 자료의 법적 권리를 확정하지 않는다. 원래 결정 기록과 이전 실행의 승인 참조·허용 용도·해시는 변경하지 않고 별도로 보존한다.

## 12. 결과 해석과 판단 사례

이 절은 상세 기준을 적용하는 보충 설명이다. 실제 선수·경기 결과·성능 수치나 물리 스키마를 정의하지 않는다. 필수 규칙은 앞의 계약 절에서 확인하고, 필요한 설명만 펼쳐 읽는다.

<a id="outputs"></a>

### 12.1 결과를 열면 먼저 볼 것

1. **대상과 시점:** 어느 경기·선수·타석·투구를 언제 예측했는가
2. **기간과 범위:** 한 경기인지, 향후 기간인지, 정규시즌/포스트시즌 중 무엇인가
3. **정보 상태:** 실제 확정값·예측·가정·미확정이 구분되는가
4. **근거와 버전:** 어떤 데이터·모델·설정·실행으로 생성됐는가
5. **평가 가능 범위:** 정답 완료·제외·누락·분모·좌표 조건이 충족됐는가

#### 종류별 확인 지점

| 결과      | 먼저 확인                      | 함께 읽어야 할 것                                                           |
| --------- | ------------------------------ | --------------------------------------------------------------------------- |
| 경기 예측 | 경기 전 기준 시점·승무패 확률  | 득점 분포·예상 득점·스코어 요약 규칙                                        |
| 타석 예측 | 시작 참가자·상태·결과 분류     | 타석 중 교체·중단·무투구 처리                                               |
| 선수 전망 | 기준 월요일·7일/28일/잔여 기간 | 출전량·Count·비율 분모·정답 관측 상태                                       |
| 상황 가치 | 타석 경계·팀 관점              | 승리 확률·기대득점과 사후 WPA 계산의 차이                                   |
| 투구 예측 | 공 직전 정보·실제 투구 여부    | 구종/결과 공동·주변 확률, 유효 표본·제외                                    |
| 시즌 전망 | 기준 시점·해당 시즌 규칙       | 두 우승·확정 상태·일정 가정·조건부 대진, 팀별 및 리그 공동 분모·시드 미확정 |
| 평가 보고 | 문제·기간·분할·기준 모델       | 지표 단위·표본/제외·보정·실패·재현 식별                                     |

#### 상태 표시

| 상태      | 뜻                                              |
| --------- | ----------------------------------------------- |
| 확정      | 그 시점에 근거가 확인된 실제 기록·상태          |
| 예측      | 모델·규칙·통계의 미래 추정. 실제 결과 보장 아님 |
| 가정      | 미발표 일정 등 직접 확인되지 않은 조건          |
| 미확정    | 자료·공개 시점·관측 완료 근거가 부족한 상태     |
| 평가 불가 | 정답·표본·분모·좌표 등 평가 조건 미충족         |

미확정이나 평가 불가는 실제 0·작은 오차·좋은 성능과 다르다. 산출물의 추적 항목은 [재현성 계약](#reproducibility), 평가 보고 구성은 [평가 기록](#evaluation-record)을 따른다.

### 12.2 해석·처리 사례

<details>
<summary><strong>결과 해석 4개 — 스코어·선수 기록·WPA·두 우승</strong></summary>

#### 승리 확률의 우세 팀과 예상 스코어가 다르게 보이는 경우

예상 스코어는 분포의 요약이다. 평균의 반올림과 가장 가능성 높은 점수 조합은 다를 수 있다. 요약 규칙을 확인하고, 분포에서 계산한 승무패와 제공 확률이 일치하는지 [M1 계약](#m1)으로 대조한다. 단순히 화면 숫자만 맞추지 않는다.

#### 선수가 출전하지 않은 것처럼 보이는데 기록이 비어 있는 경우

완전한 자료에서 실제 출전이 없는지, 아직 미래인지, 수집 누락인지 먼저 구분한다. 0으로 채우기 전에 [M3 정답 상태](#m3-state)를 확인한다. 비율의 분모가 0이면 비율 0으로 읽지 않는다.

#### 타석 뒤 WPA가 큰 경우

실제 사건 이후 승리 확률 변화의 계산값이다. 사건 전부터 같은 WPA를 알고 있었다는 뜻이 아니며, 선수의 인과적 공헌을 확정한 값으로 단정하지 않는다. [M4 정의](#m4)를 확인한다.

#### 정규시즌 우승과 한국시리즈 우승 전망이 다른 경우

정규시즌 순위와 포스트시즌 최종 우승은 다른 사건이다. 대진·시리즈 규칙·조건부 진출을 확인한다. 반복 계산의 안정성과 정답 대비 정확도도 [별도로 평가](#season-evaluation)한다.

</details>

<details>
<summary><strong>판단 절차 8개 — 부분 정답·과거 라인업·교체·좌표·Test·시뮬레이션·분모·시드</strong></summary>

#### 사례 A — 월요일에 일부 정답만 준비된 선수

**상황:** 기준 주의 7일 정답은 완료됐지만 28일·잔여 시즌 정답은 아직 관측되지 않았다.

1. 월요일 당일 기록이 과거 입력에 없는지 [기간 경계](#m3-period)를 확인한다.
2. 기간마다 [정답 상태](#m3-state)를 분리한다. 7일 완료가 다른 기간의 완료를 뜻하지 않는다.
3. [부분 정답 처리](#m3-overlap)에 따라 마스크 지원을 검증하거나 요구 정답이 모두 완료된 표본만 학습한다.
4. 누락·제외·학습에 사용한 기간을 평가 기록에 남긴다.

**잘못된 처리:** 미관측 기간을 0으로 채우거나 관측된 날짜만 합쳐 완전한 기간처럼 표시하는 것.

#### 사례 B — 지금 조회한 과거 선발 명단

**상황:** 과거 경기의 실제 선발 명단은 조회되지만 발표 시각 기록은 없다.

1. [입력 채택 조건](#input-gate)에서 사건 날짜와 이용 가능 시각을 구분한다.
2. [라인업·일정 공개 시점](#lineup-schedule-publication)의 공개 근거가 없으면 당시 경기 전 입력으로 채택하지 않는다.
3. 사후 라인업 정답·평가와 경기 전 입력 사용을 분리하고 재현 한계를 표시한다.

**잘못된 처리:** 현재 응답에 있으므로 당시에도 알 수 있었다고 주장하는 것.

#### 사례 C — 타석 중 투수가 바뀐 경기

**상황:** 최종 결과 행에는 교체 후 투수가 기록돼 있다.

1. [M2 계약](#m2)에 따라 타석 시작 상태와 결과 귀속을 별도로 확인한다.
2. [M2 경계·범주](#plate-appearance-boundary)의 시작 참가자 식별·분류 매핑을 확인한다.
3. 시작 상태를 복원할 근거가 부족하면 제한·제외를 기록한다.

**잘못된 처리:** 최종 투수를 시작 입력에 그대로 넣는 것.

#### 사례 D — 제외 범위인 위치 예측의 오류 (향후 설계 참고)

**상황:** 위치 평가에는 좌표가 있는 공만 포함됐고 실제 현재 구종으로 조건화했다.

1. [M5 계약](#m5)에서 투구 전 정보 범위를 대조한다.
2. 실제 현재 구종을 사용한 분석은 별도 조건부 문제로 구분한다.
3. [현재 위치 출력 제외](#metrics-location)를 적용한다. 범위 변경 전에는 위치 평가를 수행하지 않는다.

**잘못된 처리:** 조건부 위치 성능을 원래 투구 전 전체 성능으로 보고하거나 좌표 누락을 원점으로 채우는 것.

#### 사례 E — 최종 Test를 본 뒤 설정 수정

**상황:** Test 결과가 나빠 모델이나 보정 설정을 바꾸고 싶다.

1. [분할·선택 경계](#split)에 따라 해당 자료가 선택에 노출됐음을 기록한다.
2. 기존 평가의 독립성을 그대로 주장하지 않는다.
3. 변경·영향 범위·새 평가 계획을 구분하고 결과의 상태를 갱신한다.

**잘못된 처리:** 같은 자료로 재선정한 결과를 독립 최종 성능으로 유지하는 것.

#### 사례 F — 반복 계산이 안정적인 우승 전망

**상황:** 반복 시뮬레이션의 결과 변동은 작지만 실제 완료 시즌 평가가 없다.

1. [시즌 입력](#season-inputs)의 규칙·일정·확정 상태·가정을 확인한다.
2. [시즌 평가](#season-evaluation)에 따라 계산 안정성과 실제 예측 정확도를 분리한다.
3. 완료된 시즌/시리즈·기준 시점·기준 모델이 확보되기 전 정확도 통과를 주장하지 않는다.

**잘못된 처리:** 반복 변동이 작다는 이유만으로 실제 우승을 잘 예측한다고 결론 내리는 것.

#### 사례 G — 팀의 1위 확률과 미확정 분모

**상황:** 100회 중 90회에서 팀의 1위 여부를 결정했고 그중 72회가 1위다.

1. 팀별 유효 조건부 확률은 72/90=0.8이다.
2. 미확정 10회를 실패로 처리하지 않는다. 가능한 무조건 사건 비율은 해석용 경계 72/100~82/100이다.
3. 리그 전체 1위 확률의 합은 동일 공동 분모에서 확인한다. [유효 분모 계약](#season-valid-denominators)을 따른다.

**잘못된 처리:** 80%를 미확정 상태를 무시한 무조건 1위 확률로 보거나, 72%를 임의 확정값으로 보고하는 것.

#### 사례 H — 진출은 확정됐으나 1·2위 결정전이 남은 반복

**상황:** 상위 2팀은 둘 다 포스트시즌 진출했지만 1위 순서는 결정되지 않았다.

1. `qualifiers`와 `postseason_seeds`를 구분한다. 진출 팀 집합 확정과 시드 확정은 별도 조건이다.
2. `postseason_seeds=null`을 유지하고 후속 계산의 유효 분모와 미확정 사유를 보고한다.
3. 동일 반복의 순위·진출 정보를 보존하고, 팀별 진출 확률을 독립적으로 다시 뽑지 않는다. [포스트시즌 인계 계약](#postseason-handoff)을 따른다.

**잘못된 처리:** 승률이 같다는 이유로 팀 ID 순서를 공식 순위로 지정하거나 미확정 시드를 버리고 전체 확률처럼 발표하는 것.

</details>

### 12.3 미확정 항목의 처리

1. [확정 대기 목록](#decisions)에서 관련 항목·책임·시점을 찾는다.
2. 원본·공개 시점·완료·규칙 등 필요한 증거를 확인한다.
3. 확인 전 사용 제한을 적용한다. 비슷해 보이는 값을 임의로 채우지 않는다.
4. 결정 이유·검증 범위·변경 버전과 영향을 기록한다.
5. 정답·분할·모델·평가가 영향을 받으면 [재현성 계약](#reproducibility)에 따라 연결 자산을 갱신한다.

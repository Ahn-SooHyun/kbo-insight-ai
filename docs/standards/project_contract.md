## 1. 문서 읽는 법·공통 용어

### 1.1 무엇을 정하는가

이 문서는 모든 기능에 공통인 의미·데이터·시간·모델 수·평가·재현성의 불변 조건을 정의한다. 실제 구현의 세부 변수·알고리즘·선정·수치·CLI와 지원 범위는 기능별 기술 문서와 저장 명세가 정본이다. 공통 규범의 후보 정의를 이미 구현하거나 평가한 기능으로 표시하지 않는다. 규범은 더 좁은 실제 지원 범위를 임의 확대하지 않는다.

## 2. 기능 범위

### 2.1 구현 및 출력

5개 모델군 M1 경기, M2 타석, M3 선수 미래 성적, M4 상황 가치, M5 다음 투구를 지원한다. M3 타자·투수 각각 1개로 총 주 예측기 6개다. 정규시즌 1위·진출과 한국시리즈 우승을 각각 제공하고, 예상 선발·팀 전력·일정 난이도는 규칙·통계·기존 M1을 사용한다. 최종 평가 및 설명은 운영 예측기를 변경하지 않는다.

<a id="conditional"></a>

### 2.2 조건부 항목

예상 라인업·타순·수비 위치·선수 교체 후보·불펜/벤치·상대 분석은 실제 이용 가능한 원천, 시점, 정답 및 지원 분모를 검증한 세부 범위에만 적용한다. 대타·대주자·수비 교체, 도루·도루실패·견제사, 관측 번트는 각각 자동 식별·전체 품질 검증이 필요하다. 관측 성공 이벤트만으로 시도 확률이나 선수 가용성을 추론하지 않는다.

### 2.3 제외

실제 건강·비공개 부상·숨은 감독 의도·내부 교체 사유, 분모 없는 견제 확률, M5 위치, 타구 위치·투구 궤적, 수상 예측, 군집화, LLM 결합, 예측 웹/앱/API 배포는 현 범위 밖이다. 원본 누락을 건별 수동 입력이나 미래 정답으로 메우지 않는다. 새로운 기능은 원천·정답·평가·실행 비용·모델 수·기존 작업 의존성의 검토와 별도 승인 이후에만 포함한다.

## 3. 공통 정보 경계

<a id="input-gate"></a>

### 3.1 입력 채택 조건

각 입력은 출처, 생성/공개 시각, 관측 종료, 키, 타입, 단위 및 결측 사유가 예측 계약에 부합해야 한다. 시각을 입증하지 못한 과거 라인업·일정을 실제 당시 이용 가능 자료로 취급하지 않는다. 기존 원천의 사후 판본을 사용하는 경우 가정·재구성의 지위를 별도로 표기한다. 경기·타석·공·월요일별 논리 기준 이후의 실제 결과와 사후 집계를 입력에 넣지 않는다.

Rolling/Expanding의 날짜 절단은 포함/제외 경계를 명시한다. 같은 날 여러 경기를 모의하는 경우 이전 날짜까지의 상태를 사용하고 당일 전체 계산 뒤 반영한다. 정답 열과 감사 열을 변수로 쓰지 않는다. Train에만 결측 대체·인코더·스케일러·특성 선택·학습 모델을 적합한다. 보정은 시간순으로 분리된 개발 자료 또는 적격 Train 외 예측을 사용하며 최종 Test에는 적용만 한다.

<a id="corrections"></a>

### 3.2 정정 자료 및 판본

불변 raw 객체는 덮어쓰지 않는다. 원천 정정·누락·충돌은 출처, 공개/수집 시각, 수정/제외 이유와 새로운 판본의 연결을 남긴다. 과거 시점 재현에는 당시 이용 가능 판본을 사용한다. 현재 판본이 공식 사실의 완전성을 보장하지 않는다. 기존 고정 평가·모델·결과의 지문을 현재 파일에 맞게 변경하지 않는다.

### 3.3 결과에 필요한 맥락

모델/규칙 버전, 기준시각과 입력 판본, 표본 단위·기간·지원 분모, 실제로 계산한 출력과 정답/관측의 상태, 제외·가정·오류·미지원 사유를 함께 기록한다. 값이 실제 0인 경우, 미관측·미결정으로 null인 경우, 대상이 아닌 경우, 검사 실패를 구별한다.

<a id="m1"></a>

### 4.1 M1 — 경기 결과·득점

공통 팀 관점 득점 예측기를 홈·원정에 사용한다. 현재 운영 `profile_histogram`은 13개 선택 입력(competition, 팀별 과거 집계 6개)을 활용한다. 입력은 해당 경기 전의 팀·상대 이력이며 공식 실제 사용 선수·경기 최종 득점·사후 집계를 포함하지 않는다. 기타 전력·라인업·휴식 변수는 이용 가능 시점 및 품질이 확보된 후보에 한한다.

득점 질량함수 p(r)는 비음수, 합 1이다. 기대득점은 `sum(r*p(r))`; 실제 저장 동점/비동점 가중과 정규화로 양 팀 결합 P(h,a)를 구성한다. 홈 승·무·패는 각각 h>a, h=a, h<a 영역의 합이다. 대표 스코어의 산출 방법(기댓값 요약 또는 최빈 조합 등)을 실제 모델 계약으로 확인한다. 평균 스코어의 승패와 확률이 가장 큰 사건은 같지 않을 수 있다. 독립 득점 가정, 꼬리·희소 후퇴, 시즌 규칙 및 점수/결과 일관성을 검증한다. [실행·선정·개발 결과](game_outcome_score.md).

<a id="m2"></a>

### 4.2 M2 — 타석 결과

타석 시작 전의 타자·투수·점수·주자·아웃·과거 이력을 사용한다. 타석 중 교체된 실제 참가자·투구 결과·타석 확정 결과를 사전 입력에 쓰지 않는다. 시작 참가자와 결과 귀속 참가자를 분리하며 식별 불가·중단·무투구 등은 실제 규칙과 제외 근거로 판단한다.

현재 `m2-plate-appearance-v2`, 41개 입력, 15개 표준 결과 범주. 가능 범주에 규칙 마스크, Train 사전 확률 평활, 저장 로지스틱 및 개발 보정을 적용한다. 2025년은 7월 1일 미만 보정과 이상 선정 구간으로 구분한다. 2026년 Test에서는 고정 매핑 및 보정만 사용한다. 희소·미출현, 규칙과 실제 정답 충돌은 별도 집계한다. [타석 실행 계약](plate_appearance.md).

<a id="m3"></a>

### 4.3 M3 — 선수 미래 성적

역할별 기준 월요일 이전의 관측 PBP 출전량과 시즌·최근 28일 Count 이력을 사용한다. 미래 출전 여부, 미래 소속, 사후 확인된 실제 종료일로 예측 모집단이나 변수를 정하지 않는다. `m3-player-performance-v2`, v1.1.0의 타자 `history_balanced_50`, 투수 `joint_residual_tree_depth_4_shrink_50`를 인수한다. 타자는 Train 사전 및 과거 기록률을 결합한 통계 예측기, 투수는 공동 잔차 회귀 트리를 추가한다. 기간별 기록을 별도 독립 모델로 증식시키지 않는다. 7일·28일·잔여의 타자 24개·투수 30개 Count와 파생 비율을 공동 산출하며 시즌 최종 전망은 관측 누적+잠정 잔여다. 공식 최종 선수 기록과의 완전 일치를 보장하지 않는다. [M3 기간·정답](#m3-labels), [선수 실행 계약](player_performance.md).

<a id="m4"></a>

### 4.4 M4 — 경기 상황 가치

공격팀을 타석 pre/post 모두 동일하게 유지한다. WP(s)=P(공격팀 공식 승리 | s), 무승부는 비승리 0이며 `1-WP`를 상대팀의 승리 확률로 해석하지 않는다. v1.1.0 `logistic_core`를 운영 예측기 하나로 사용한다. 34개 허용 열 중 상태 입력 계약 22개, 선정 후보는 12개 수치 특징이며 이력 후보의 22개 특징은 비교에 사용했다. Train의 조건부 반이닝 잔여 득점 통계표 및 지원 후퇴를 사용한다.

- RE(s)=E[현재 반이닝 종료까지 실제 잔여 득점 | s]. 3아웃 또는 확인된 공식 종료에서 RE=0.
- WPA=WP(post)−WP(pre); ΔRE=RE(post)−RE(pre); 득점 가치=actual_runs+ΔRE. 실제 타석 결과의 가치이며 사전 입력·인과효과가 아니다.
- LI는 Train 물리 전이의 기대 절대 WPA와 지원되는 Train 참조 평균의 비다. `D(s)=sum_t q(t|s)*abs(WP(s_t)-WP(s))`, `LI=D(s)/D_ref`. 전이 지원 30 미만, 참조 평균 부재/0 이하, post 상태는 null 및 사유를 유지한다.

2023~2024 정규시즌 최대 12회, 2025~2026 최대 11회 규칙을 적용한다. 공식 종료 증거가 일치한 관측 상태는 승리 1/비승리 0을 사용하고, 계속되는 경기의 3아웃은 일반 WP를 추론한다. 가상 정상 규칙 종료와 실제 예외 종료를 혼동하지 않는다. 현재 운영 모델의 2026 고정 Test는 평가 완료 이력이 있으며 ECE·일부 3아웃 지표의 악화가 남는다. M2와 직접 연결하는 기능은 이 구현 범위가 아니다. [경기 상황 실행 계약](game_state_value.md).

### 4.5 M5 — 다음 투구

## 5. M3 기간·관측 완료·기록 일관성

<a id="m3-period"></a>

### 5.1 기간 경계

| 기간 | KST 논리 구간                     | 정답 조건                  |
| ---- | --------------------------------- | -------------------------- |
| 7일  | [t,t+7일)                         | 구간의 정규시즌 관측 완료  |
| 28일 | [t,t+28일)                        | 구간의 정규시즌 관측 완료  |
| 잔여 | t부터 해당 정규시즌 공식 종료까지 | 종료 근거와 전체 기록 포함 |

`t`는 월요일 00:00 KST다. 실제 실행이 늦어도 같은 월요일의 기록은 입력에 포함하지 않는다. 시즌 중간에 7일/28일 구간이 끝나거나 시즌 자체가 끝나면 관측 구간과 정규시즌 포함 범위를 분리한다. 포스트시즌을 혼입하지 않는다.

### 5.2 Count·비율

출전량·안타·타수·삼진 등 비음수 누적 Count 및 그 분자·분모에서 계산한 비율을 구별한다. Count 예측은 기대값이므로 임의 정수 반올림을 강제하지 않는다. 비율 분모가 0이면 null이다. 비율 자체에 7일≤28일≤잔여의 단조성을 적용하지 않는다. 관측된 Count가 실제 0인 것과 원천 자료가 없어서 0으로 보이는 것은 다르다.

<a id="m3-state"></a>

### 5.3 정답 상태

| 상태                                       | 처리                                     |
| ------------------------------------------ | ---------------------------------------- |
| 정답 기간 완료 및 유효 관측                | 학습/평가 가능 여부를 시간 조건으로 확인 |
| 완료·관측·선수 식별 근거 부족              | 미관측/미완료 상태, 정답 마스크          |
| 실제 출전 또는 해당 기록 0, 전체 포함 입증 | 유효 0으로 유지                          |
| 파생 비율 분모 0                           | 비율 null 및 사유; Count와 구별          |
| 잔여 시즌 종료 근거 부족                   | 잔여 정답 미확정, 임의 종료일 사용 금지  |

<a id="m3-overlap"></a>

### 5.4 학습 시각·겹치는 기간

학습 시점까지 실제 관측 완료된 정답만 사용한다. 기준 월요일이 Train 안에 있더라도 미래 정답 구간이 평가 경계를 넘으면 학습 적격 여부를 별도 검사한다. 동일 선수의 7일/28일/잔여와 겹치는 월요일 표본은 독립이라고 가정하지 않는다. 후보와 기준을 동일한 기록별 유효 마스크에서 비교한다.

### 5.5 출력 일관성과 구간

현재 구현의 7d≤28d≤remaining Count 및 기록 구성 제약은 실제 모델 투영을 따른다. 당시 확인 가능한 합성 시즌 종료 시나리오에서 같은 구간의 Count가 일치하도록 검사한다. 실제 종료일을 미래 입력으로 넣어 예측을 맞추지 않는다. 기간별 Count 정규화 척도는 Train에서 고정하고 비율은 같은 기간의 분자/분모로 계산한다. 90% 목표 구간은 실제 포함률 및 동시 포함 보증이 아니다. 유효 정답·지원 구간·포함률·평균 폭을 보고한다.

## 6. 평가 원칙

### 6.1 비교·선정

같은 문제 안에서 기준 및 후보의 표본·시간·입력·정답·지표를 고정한다. 주/보조 지표 및 선택 규칙을 결과 전에 정한다. 다른 문제의 단위·범주 수·분모가 다른 수치를 직접 우열로 비교하지 않는다. 후보별 유효 표본이 다르면 공통 표본 및 각 후보 지원 범위를 함께 공개한다. 기준 모델도 Train에만 적합한다. 선정과 독립 최종 평가를 섞지 않는다.

<a id="metrics-probability"></a>

### 6.2 분류·확률

| 지표                | 정의와 사용                                                        |
| ------------------- | ------------------------------------------------------------------ |
| Log loss            | `-mean(log(p_true))`; 실제 범주에 부여한 확률, 사전 고정 절단 규칙 |
| 다중분류 Brier      | `mean(sum_c (p_c-y_c)^2)`; 클래스 정규화 차이를 명시               |
| 이진 Brier          | `mean((p-y)^2)`; M4 공격팀 승리 등                                 |
| Macro F1            | 클래스별 F1의 동일 가중 평균, 희소 클래스와 0 분모 정책 기록       |
| Reliability/ECE     | 확률 구간의 평균 예측·실제 관측 차이의 가중 평균; bin·지원·축 구분 |
| Top-label ECE       | 최상위 예측의 신뢰도와 실제 적중률 비교                            |
| Macro classwise ECE | 클래스별 one-vs-rest ECE의 동일 가중 평균                          |

Accuracy·F1이 높아도 보정 개선을 보장하지 않는다. M5 공동·구종·결과는 다른 사건이므로 각각 평가한다. 확률의 구조적 0, 미출현 조합, 평활 및 수치 처리 정책을 평가 전에 고정한다.

<a id="metrics-numeric"></a>

### 6.3 수치·분포·구간

MAE=`mean(abs(y-yhat))`, RMSE=`sqrt(mean((y-yhat)^2))`. 이산 CRPS는 정의한 지지집합에서 예측 CDF와 실제 관측 CDF의 제곱 오차를 합하는 분포 점수다. M1 점수·분포·승무패, M3 기록별 Count 및 파생 비율, M4 RE, 시즌 기대 승수·순위는 단위와 분모를 명시한다. M3 역할별 11개 후보의 선정은 Train 정규화 macro MAE 개선(1e-12 초과) 및 RMSE 비악화(1e-12 허용), MAE·RMSE·고정 후보 순서를 사용했다. 해당 후보가 없으면 기준을 유지한다. 비율은 유효 공통 분모에서만 비교한다. 구간은 포함률·폭·지원을 함께 보고한다.

<a id="metrics-location"></a>

### 6.4 위치 출력 (제외)

좌표의 원점·축·단위·방향·유도 근거가 확정되지 않았으므로 M5 위치는 현재 모델과 정답에서 제외한다. 원점을 임의 보정하거나 위치 평가를 만들어내지 않는다.

### 6.5 보조 기능

예상 선발의 단위는 경기×팀 측. 후보 제공률과 실제 선발 식별률의 분모는 전체 측, 유효 Top-k의 분모는 후보와 식별 정답을 모두 가진 측이다. 전체 식별 정답 기준의 적중률도 별도로 표시한다. 공통 평가 측에서 두 규칙을 비교하며 선발 순위를 확률이나 공식 발표로 해석하지 않는다. 팀 기록의 0 분모·부분 일정 및 관측 누락을 유지한다.

<a id="split"></a>

### 6.6 시간 분할과 Backtesting

Train 2025-01-01 이전, Validation 2025년, 고정 최종 Test 2026-01-01 이상 2026-11-26 미만(KST). 모델 자료의 실제 관측 기간과 정답 완료 경계를 함께 검사한다. 같은 경기 묶음·동일 표본·시간 순서를 지키며, 전처리 및 Encoder를 평가 자료로 fit하지 않는다. M3 기간별 정답 관측 완료를 별도로 검사한다. 시간순 Backtesting은 매 시점에서 실제 사용할 수 있는 자료와 모델에 근거한다. 과거 일정 공개 시점 및 당시 운영 모델 가능성이 입증되지 않은 2025 가정은 정식 Backtesting이 아니다. 무작위 K-fold·Stratified K-fold·OOB는 이 평가를 대체할 수 없다.

<a id="stacking"></a>

### 6.7 다른 예측기와 설명

하위 모델 출력을 상위 모델의 학습 입력으로 사용하려면 해당 시점 이전 자료만으로 생성된 하위 예측을 사용한다. 최종 Test의 실제 정답이나 같은 표본을 학습한 하위 모델의 결과를 섞지 않는다. Stacking 등 독립 예측기 추가는 모델 수·지원·성능·비용을 별도 검토한다. 현재 시즌은 저장 M1의 직접 재사용이며 신규 상위 학습이 아니다.

설명은 실제 저장 모델의 출력 구조를 따르고 전역/개별 설명을 분리한다. SHAP은 정의한 Train 배경과 출력 척도에 대한 기여로 보고하며 실제 원인이나 확률 가산량을 단정하지 않는다. 자세한 방식은 [설명 계약](prediction_explanation.md)을 따른다. 최종 Test를 보고 온도·Threshold·변수·모델을 바꾸지 않는다.

<a id="evaluation-record"></a>

### 6.8 결과의 필수 맥락

소스/자료/모델/설정·실행 ID, 학습·검증·Test 기간, 정답 관측 조건, 공통·유효 분모, 제외·미지원, 기준·운영 지표와 악화, 계산·학습 비용의 실제 측정, 검증 근거를 기록한다. 실제 미측정 비용을 추정해서 실행 결과로 표기하지 않는다.

### 6.9 인수판 및 최종 Test 결과

표준 실행 `e020dafedc8b4fd9ac6696d0e4a92e`, 검증 `37b56c39caf5435e8fb2a17f993ec4df`, 모델 자료 `259b38decaac4ed68dd5a596cfbe4849` 및 6개 운영 자산을 사용한다. 상세 경로와 지문은 [실행 인수](execution_handover.md#data)를 따른다. 2026 고정 평가 #34, 시즌 종합 검산 #35, 예측 설명 #36의 기술 수용·PR 병합·Issue 종료를 확인했다. 신규 전체 추론 없이 기존 평가 지표 6개 재계산 및 설명 Train 배경 3개 대조가 #40에서 이루어졌다.

## 7. 시즌·포스트시즌 전망 계약

### 7.1 출력의 차이

정규시즌 우승은 정규시즌 최종 1위, 한국시리즈 우승은 포스트시즌 규칙을 거친 최종 우승이다. 승수·순위·진출·시리즈 참가·대진·시리즈 승리·우승은 별개 사건이며 서로 다른 유효 분모를 가진다.

<a id="season-inputs"></a>

### 7.2 일정·규칙·조건부 확률

현재 2025 정규시즌 `kbo-2025-ranking-v1`, 10팀·팀 쌍 16경기·팀당 144경기·총 720경기·5팀 진출. 2025-03-22~12-31 범위의 KST 자정 기준을 지원한다. 실제 기준일 이전 완료 경기·잔여 일정 가정, 외부 스냅샷의 구조 및 공개 주장 시각을 구분한다. 제공 스냅샷이 실제 당시 공개된 것이라는 독립 인증은 아니다. 2026 시즌 전망·보조 분석은 지원하지 않는다.

<a id="season-evaluation"></a>

### 7.3 계산 검증과 성능 평가

규칙·수식·시드 연결·확정 기록·분모·동일 Seed 재현을 확인하는 기술 검증과 실제 시즌 결과에 대한 성능 평가를 분리한다. 공식 당시 정보와 정답, 모델의 당시 이용 가능성이 입증된 평가에서만 승수/순위 MAE, 사건 Brier·Log loss를 독립 성능으로 해석한다. 같은 시즌의 반복을 여러 실제 독립 시즌으로 세지 않는다.

<a id="regular-season-implementation"></a>

### 7.4 정규시즌 시뮬레이션

동일 저장 M1 결합 분포의 승무패 영역 및 조건부 득점 셀을 표본 추출한다. 양 팀 결과를 동시에 반영하고 리그 승패의 합을 대조한다. 시즌 누적·최근 28일은 기준일 전의 실제 이력 및 모의 날짜별 상태로 갱신한다. 같은 날 경기의 결과는 해당일 모든 경기 예측이 끝난 뒤 반영한다. 무승부는 W/(W+L)의 분모에서 제외하며 승률은 정확한 유리수 비교를 사용한다. 1위·5위 경계 결정전 미확정과 불완전 일정은 보수적 가능 순위와 확정 사건만 유지한다. 기존 결과 `scenario.json`, `summary.json`, `iterations.jsonl`, `manifest.json` 및 선택 진단을 연결한다. [정규시즌 계약](regular_season_standings.md).

<a id="season-valid-denominators"></a>

### 7.5 유효 분모와 미확정

전체 N회, 특정 사건 유효 V회, 성공 H회, 미결정 U=N−V회라면 `H/V`(V>0) 및 `U/N`를 각각 기록한다. V=0인 경우 확률은 null. H=0, V>0의 0과 구분한다. 미결정 사건이 전부 실패/성공하는 논리적 범위는 `[H/N,(H+U)/N]`이며 신뢰구간이 아니다.

| 범위        | 유효 조건                      | 검사                                 |
| ----------- | ------------------------------ | ------------------------------------ |
| 팀 승수     | 해당 팀 경기 수 완료           | 0~144 범주의 조건부 분포 합 1        |
| 팀 순위     | 해당 팀 순위 확정              | 1~10 범주 조건부 분포 합 1           |
| 팀 1위·진출 | 해당 사건 확정                 | 순위가 미확정이어도 진출은 확정 가능 |
| 공동 1위    | 모든 팀 1위 상태 확정          | 공동 분모 확률 합 1                  |
| 공동 진출   | 모든 팀 진출 상태 확정         | 공동 분모 확률 합 5                  |
| 부모 시드   | 정확히 다섯 팀의 순서 1~5 확정 | 같은 반복 ID·팀 집합 및 순위 일치    |

### 7.6 대표 개발 결과

`e24254420aee4d52acf2b1fb144c3d58`, 2025-09-01 KST 자정, 완료 622·잔여 98·누락 0경기, Seed 42·1,000회. 1위 공동 984, 진출 공동 922, 확정 시드 906회. 동일 조건에서 승수 MAE 2.323900→2.133400, 순위 MAE 0.869456→0.743546의 개발 진단이다. 2025년 가정 및 이미 사용된 M1의 개발 비교이며 공식 Backtesting 성능이 아니다. [시즌 검산](season_forecast_validation.md).

<a id="postseason-handoff"></a>

### 7.7 포스트시즌 인계

정규시즌 동일 반복 ID의 확정 시드를 인수하며 팀별 주변 진출 확률을 독립적으로 다시 표본 추출하지 않는다. 같은 부모의 확정 여부·팀 집합·순위·진출 상태를 확인한다. 와일드카드·준플레이오프·플레이오프·한국시리즈의 규칙에 맞는 참가·대진·홈 배정·완료 경기·차전 수 및 종료 상태를 연결한다. 대진 조건부 확률과 참가/승리 사건의 공동/팀별 분모를 보존한다. 1,000회 대표 사례에서 한국시리즈 대진 성립 902, 우승 확정 899, 미결정 101회. 2025-11-01 종료 재생의 5차전 원천 기록 충돌로 1,000회 우승 미결정이었다. 공식 2025년 우승팀 LG와 이 결과의 미결정은 서로 모순되는 주장으로 해석하지 않는다. [포스트시즌 계약](postseason_forecast.md).

### 7.8 검증과 원천 사실

작업·규칙·계산·Seed·결과의 재현은 원천 전수 정확성 및 당시 정보 기반 일반화 성능을 입증하지 않는다. 2025년 한국시리즈 5차전 충돌을 원본 수동 수정으로 처리하지 않고 별도 정정 승인과 자동 품질 검증이 필요한 항목으로 남긴다.

<a id="support-analysis-contract"></a>

### 7.9 예상 선발·팀 전력·일정 난이도

2025년 기준일 이전 28일 이력, 해당 팀 최신 관측 소속 및 이름 일치로 후보를 만들고 운영 baseline 사전식 순위를 적용한다. 다음 관측 팀 경기일이면서 기준일부터 7일 이내만 제공한다. 더블헤더의 두 선발을 확정 배정하지 않는다. 실제 선발 및 공식 발표를 확정하지 않는다. 최근 투구 부담은 관측 행의 합이며 관측 누락과 공식 총량을 구분한다.

팀 기록은 시즌/최근 28일/홈·원정/상대별 W/(W+L), RF/G, RA/G, (RF−RA)/G 등 기술통계다. M1 팀 관점 난이도는 P(loss)+0.5P(tie), 유효 경기 평균이다. 기준일 이후 예정 경기의 실제·모의 결과를 상태에 반영하지 않으므로 동적 시즌 반복과 다른 계산이다. 2025년 공통 1,429측의 기준 순위 선택은 개발 비교이며 2026년 보조 분석 지원이나 공식 발표의 적중률이 아니다. [보조 분석 계약](support_analysis.md).

## 10. 재현성·저장·설정 계약

### 10.1 자료·모델·결과의 계보

불변 raw, 중간 자료, 표준 검증판, 모델 자료, 모델·대표 입력/기준 출력, 평가·시즌·설명 결과를 실행 ID와 지문으로 연결한다. 과거 고정 명세의 절대 경로·환경·코드·문서·입력 지문은 그 판본으로 확인한다. 문서 수정만으로도 기존 지문이 달라질 수 있으므로 새 명세·결과는 기존 경로 외에 생성한다. 기존 지문을 현재 바이트로 치환하거나 검사 우회하지 않는다.

### 10.2 보존 기록

원천·수집 시각/범위/판본·객체 지문, 자료 변환/제외/정정, 코드·설정·환경·Seed, Feature/Target·분할, 모델/평가/예측·정답 지문, 결과 상태·실패와 비교 대상을 남긴다. 지문은 바이트/계약 일치의 증거이며 자료의 사실 정확성, 일반화·인과성의 증명이 아니다. M3 과거 직렬화 재구성과 M5 과거 기록 차이의 실제 근거는 [인수 안내](execution_handover.md#inputs)에 유지한다.

### 10.3 저장 책임·설정

경로는 `kbo.toml`에서 고정하며 명시 절대 루트, 프로세스 `KBO_PROJECT_ROOT`, 편집 가능 소스 위치의 순서로 해석한다. 경로 겹침·설정 누락·타입·권한/I/O 및 스키마 오류는 명확히 구분한다. 생성 결과는 기존 원본·명세·결과를 덮어쓰지 않는다. 읽기 전용 검사는 불필요한 파일 생성·수정·삭제를 수행하지 않는다. CLI 입력 오류·실행 실패와 정상 상태를 구분한다. 설정의 실제 값과 설치 명령은 [README](../../README.md#running)를 따른다.

### 10.4 Secret과 Git

비밀값은 소스·설정·테스트·Notebook·문서·로그에 포함하지 않는다. 필요한 예시 환경 파일에는 실제 비밀값을 적지 않으며 `.env`, `.env.production` 등은 Git 추적에서 제외한다. 원본·모델·로컬 결과를 승인 범위 밖에 공개하지 않는다. 데이터 저장 위치와 Git 변경은 사용자 관리 범위다.

<a id="data-use-scope"></a>

### 10.5 자료 이용 범위

현재 자료는 승인된 비영리 대학 과제용 로컬 처리 및 내부 평가 범위를 기준으로 한다. 소스 공개가 DB·원본·모델의 재배포 권한을 자동 부여하지 않는다. 실제 원천 이용 조건 및 추가 제공 범위를 확인한다.

### 12.3 미확정 처리

근거가 부족하면 null·미지원·미확정과 사유를 기록한다. 수치·원본·지문을 조정해서 성공으로 바꾸지 않는다. 새 기능의 지원과 새 모델·재평가는 별도 작업으로 관리한다.

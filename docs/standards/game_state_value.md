## 1. 목적·지원 범위

### 1.1 문제 정의

타석 직전과 직후의 같은 공격팀 관점에서 무조건부 승리 확률과 현재 반이닝 잔여 기대득점을 계산한다. 관측한 전후 상태를 연결해 WPA와 득점 가치를 계산하고, 사전 상태의 경험적 전이 분포로 상황 중요도를 계산한다. 운영 승리 예측기는 하나다. RE와 전이 분포는 학습 통계표로 구성한다. 포스트시즌, 실시간 서비스 배포, 독립 최종 Test 평가는 이 개발 범위에서 제외한다.

### 1.2 운영 상태와 해석 범위

| 구성                              | 제공 결과                                                  | 범위 제한                                                                                         |
| --------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 승리 확률(Win Probability, WP)    | 타석 경계에서 공격팀이 공식 경기에서 승리할 조건부 확률    | 패배와 무승부는 하나의 비승리 사건이다. 별도 무승부 확률, 승리 지분, 전력 지수는 제공하지 않는다. |
| 잔여 기대득점(Run Expectancy, RE) | 해당 반이닝의 앞으로 관측될 득점 평균                      | 다음 반이닝이나 경기 종료까지의 총 득점이 아니다.                                                 |
| 관측 WPA·득점 가치                | 같은 공격팀의 실제 관측 전후 예측 변화                     | 반사실적 인과효과 또는 타자 단독 기여도로 해석하지 않는다.                                        |
| 상황 중요도(Leverage-like Index)  | 사전 상태의 가능한 전이들에 따른 기대 절대 WPA의 상대 크기 | 실제 타석 결과와 별개다. 지원 부족은 null이며, MLB LI와 수치의 직접 비교는 불가하다.              |

일반적 분류기의 정답을 맞히는 문제가 아니라, 상태별 확률 및 조건부 평균을 예측해 해석 가능한 야구 상황 가치를 산출하는 문제다. 1개 운영 분류기의 확률을 전후 두 상태에 공통으로 적용한다. RE 표와 전이 표는 독립 학습 분류기가 아니다. M2의 타석 결과 분류만으로 득점·주자·아웃의 모든 물리 전이를 확정할 수 없으므로 이 버전에는 M2와의 직접 결합을 추가하지 않았다.

DB를 읽기 전용으로 연결하고 입력 계약, Train EDA, 원본 경계와 자료 키를 확인한다.

### 2.3 EDA와 개발 자료 한계

`train_eda.json`의 인수 지문을 확인하되, 이 문서 작성 시 원본 EDA JSON을 별도로 열어 변수별 분포·결측 비율을 다시 계산하지 않았다. Train·Validation의 표본 수, 공식 종료 유형, 상태 지원률은 실행 로그로 확인한 실측치만 기록한다. 상태별 빈도와 조건부 RE의 희소성이 존재하기 때문에 빈도 후퇴와 중요도 미지원 조건을 구분한다. 2025년 연장 이닝 규칙 변화는 과거 분포의 단순 재사용을 제한하는 자료 분포 이동 요인이다.

## 3. 입력·전처리

### 3.1 원본 허용 열과 선택 상태

34개 허용 열 가운데 기존 22개 상태 입력을 유지한다. 경기·타석 ID는 감사 계약에만 사용하며 모델 특징에서 제외한다. 시즌은 최대 이닝 계산에 사용한다. 정규시즌 여부, 팀 식별자와 phase는 계약 검사에 사용한다. 실제 수치 특징은 이닝·공격팀 홈 여부·점수차·아웃·주자 및 점수차 상호작용이다. 선택 후보는 양 팀의 시즌 이전 경기수·득실점·승수를 추가한다. 과거 기록 누락 표시, 고정 평활화, Train 평균·표준편차를 사용한다. 3아웃의 잔존 주자는 특징에서 정규화한다.

| 구분                 | 선택 열                                                                     | 사용                                  |
| -------------------- | --------------------------------------------------------------------------- | ------------------------------------- |
| 시즌·대회            | `season`, `competition`                                                     | 최대 이닝 규칙과 지원 정규시즌 검사   |
| 팀 관점              | `home_team_id`, `away_team_id`, `perspective_team_id`                       | 대진·공격팀 동일성 검사, 홈/원정 정렬 |
| 경기 경계            | `inning`, `half`, `phase`                                                   | 현재 진행 시점, 공격 방향, 전후 계약  |
| 점수                 | `home_score`, `away_score`                                                  | 공격팀 점수와 상대 점수의 차이        |
| 아웃·주자            | `outs`, `on_first`, `on_second`, `on_third`                                 | 관측 아웃, 주자 점유 상태             |
| 팀 이전 기록(각 4개) | `home_` / `away_` + `season_games`, `season_rf`, `season_ra`, `season_wins` | History 비교 후보의 특징, NULL 유지   |

총 22개 상태 열이다. 기존 자료 허용 열 34개 중 양 팀 `season_ties`, `recent_games`, `recent_rf`, `recent_ra`, `recent_wins`, `days_since_game`(12개)은 현재 선택 상태에 넣지 않는다. 정답, 타석 이후에만 알 수 있는 변수, 감사 플래그 및 식별자 자체는 수치 특징에 포함하지 않는다.

### 3.2 상태 검사와 시즌 규칙

| 시즌      | 최대 이닝 |
| --------- | --------: |
| 2023~2024 |        12 |
| 2025~2026 |        11 |

근거: [KBO 2025년 규정 개정 공지](https://www.koreabaseball.com/MediaNews/Notice/View.aspx?bdSe=11353), [2025 주요 규정](https://www.koreabaseball.com/Kbo/League/GameManage2025.aspx), [2026 주요 규정](https://www.koreabaseball.com/Kbo/League/GameManage2026.aspx). 2025년 정규시즌 최대 이닝 축소가 명시되어 있고 2026 주요 변경 공지에는 추가 최대 이닝 변경이 명시되지 않는다. 위 범위 밖 시즌은 임의로 추정하지 않는다.

최대 후속 반이닝 수 `H = 2 × (최대 이닝 - 현재 이닝) + I(초 공격)`는 규칙상 상한이다. 로지스틱 회귀에서 `점수차 / sqrt(H + 1)`을 사용한다. 빈도 기준은 9회 이후 `현재 이닝 + 12 - 최대 이닝`의 참조 이닝을 사용하여 최대 잔여 이닝이 같은 Train 상태와 연결한다. 9회 이전에는 실제 이닝을 유지한다. Train에 11회 제한 시즌이 없으므로 규칙 효과를 별도로 학습한 것이 아니며, 참조 상태 연결은 검증 대상 가정이다.

### 3.3 실제 특징 벡터와 변환

공격팀 점수차를 `d = 공격팀 점수 - 수비팀 점수`, 홈 공격 여부를 `h`, 현재 이닝을 `i`, 7회 이후 지표를 `late`, 주자 마스크를 `m = b1 + 2*b2 + 4*b3`로 둔다. 3아웃 이후에는 마스크를 0으로 정규화한다. 실제 기본 로지스틱 특징은 다음 12개다.

| 순서 | 특징                         | 의미                                       |
| ---: | ---------------------------- | ------------------------------------------ |
|    1 | `i`                          | 실제 이닝                                  |
|    2 | `h`                          | 홈 공격 여부                               |
|    3 | `d`                          | 공격팀 점수차                              |
|    4 | `outs`                       | 아웃 수                                    |
|  5–7 | `I(m&1)`, `I(m&2)`, `I(m&4)` | 1·2·3루 점유 여부                          |
|    8 | `d*i`                        | 진행 시점과 점수차 상호작용                |
|    9 | `d*h`                        | 홈 공격 여부와 점수차 상호작용             |
|   10 | `abs(d)`                     | 점수차 절대값                              |
|   11 | `I(i>=7)`                    | 후반 진입 여부                             |
|   12 | `d/sqrt(H+1)`                | 최대 후속 반이닝을 고려한 점수차 규모 변환 |

History 후보는 공격팀과 수비팀 각각 다음 5개 특징을 같은 순서로 추가해 22차원을 구성한다. `n`은 과거 경기 수, `RF`, `RA`, `W`는 과거 득점, 실점, 승수다. 미관측은 수치 계산에 제한적으로 0을 대입하고 별도 누락 플래그로 구분한다. 빈 기록에 임의의 실제 경기 결과를 추가 저장하지 않는다.

| 특징        | 산식                            | 목적                                |
| ----------- | ------------------------------- | ----------------------------------- |
| 기록 규모   | `n/(n+20)`                      | 이력량의 비선형 안정화              |
| 경기당 득점 | `(RF+20)/(n+5)`                 | 5경기·4득점 사전값으로 수축         |
| 경기당 실점 | `(RA+20)/(n+5)`                 | 5경기·4실점 사전값으로 수축         |
| 승리 비율   | `(W+2.5)/(n+5)`                 | 5경기·0.5 승리 비율 사전값으로 수축 |
| 결측 여부   | `I(n,RF,RA,W 중 하나라도 NULL)` | 관측 0과 미관측 구분                |

로지스틱 후보의 스케일링은 Train 비종료 상태의 가중 평균 `mu_j`와 모집단 표준편차 `sigma_j`로 `z_j=(x_j-mu_j)/sigma_j`를 계산한다. 거의 상수인 특징의 스케일은 1로 처리한다. Validation과 독립 추론에 학습 당시 변환을 재사용한다. 이력 특징은 비교 후보에 구현되었으나 최종 `logistic_core`에는 포함되지 않는다.

## 4. 정답·출력 계약

### 4.1 정답과 단위

승리=1, 무승부·패배=0이다. `win_probability`는 무승부 제외 승률이나 승리 지분이 아니다. RE는 현재 반이닝 종료까지 남은 실제 득점의 조건부 평균이다.

- WPA = 타석 후 승리 확률 - 타석 전 승리 확률.
- 잔여 기대득점 변화 = 타석 후 RE - 타석 전 RE.
- 득점 포함 타석 가치 = 실제 공격팀 득점 + 잔여 기대득점 변화.

확률은 [0, 1], WPA는 [-1, 1]의 확률 차이다. 0.05 WPA는 5%p 변화이지 5% 상대 개선율이 아니다. RE와 득점 가치는 점(run) 단위이며, 상황 중요도는 무차원 상대값이다. 같은 공격팀의 승리 사건은 무승부를 포함한 전체 결과 분모로 정의한다. `1 - WP`는 패배 또는 무승부의 합이며 상대팀 승리 확률로 바로 해석하지 않는다.

### 4.2 관측 경기 종료와 가상 종료의 분리

관측 3아웃은 RE=0이지만 그 자체로 경기 종료가 아니다. 공식 Final, 최종 점수, 원본 마지막 타석, 순서·경계·득점 일치 및 종료 형태를 확인한 경우만 실제 승리 확정값을 사용한다. 부분 반이닝 종료는 관측 근거를 우선하며 강우 등 예외 원인을 추측하지 않는다. 끝내기 패턴은 공식 종료 및 9회말 이후 동점·열세에서 홈 우세로 바뀐 상태를 구분한 것이다.

| 관측 또는 가상 경계                  | WP 처리                       | RE 처리                                          |
| ------------------------------------ | ----------------------------- | ------------------------------------------------ |
| 일반 관측 상태                       | 운영 예측기                   | 조건부 평균                                      |
| 경기 계속 3아웃                      | 운영 예측기                   | 0                                                |
| 관측 공식 승리 종료                  | 1                             | 0                                                |
| 관측 공식 패배·무승부 종료           | 0                             | 0                                                |
| 공식 종료 근거 없이 관측된 부분 상태 | 확정 종료값 적용 안 함        | 3아웃 여부에 따라 통계 또는 0                    |
| 가상 정상 규칙 종료                  | 상황 중요도 내부에서 1 또는 0 | 가상 전이 WP 계산용이며 실제 공식 종료 인증 아님 |

### 4.3 독립 추론 입력 계약

독립 추론의 `pre`, `post`는 각각 `{game_id, pa_number, state}` 구조이다. 단일 상태 요청은 `{state: {game_id, pa_number, state}, final}` 구조이다. `final`은 null 또는 공식 종료 감사 객체다. 전후 경기와 타석 식별자가 서로 일치해야 하고, 종료 근거의 경기 및 마지막 타석도 같아야 한다. 식별자나 정답은 내부 상태 특징에 넣지 않는다. 호출자가 제공한 정보의 원본 진위는 원본 DB 없이 인증할 수 없다.

## 5. 모델·학습·선정

### 5.1 비교 후보 및 학습 설정

상태별 빈도 기준(Laplace 평활화, 최소 지원 30), 기본 로지스틱, 팀 과거 기록 로지스틱, L2 0.001, L2 0.01의 5개 후보를 비교한다. 가중 미니배치 512, 12 epoch, 초기 학습률 0.15, 제곱근 감소, Seed 42를 사용한다. 동일한 Train에서 전처리와 계수를 적합하고, 동일 Validation 전체 상태 Log loss와 Brier 순으로 하나의 운영 승리 예측기를 선택한다. 동률이면 먼저 비교한 단순 후보를 유지한다. 확률 보정은 신뢰도 구간과 ECE를 진단하며 별도의 보정기는 적합하지 않는다. 설정은 사전 정의값이며 실측 최적값을 의미하지 않는다.

| 후보                         | 실제 학습·계산                                 | 운영 여부 |
| ---------------------------- | ---------------------------------------------- | --------- |
| `frequency`                  | 상태별 경험적 Bernoulli 승리 빈도, 가산 평활화 | 비교 기준 |
| `logistic_core`              | 12개 기본 특징, L2=0                           | **선정**  |
| `logistic_history`           | 기본 12개와 팀 이력 10개, L2=0                 | 비교      |
| `logistic_history_l2`        | 22개 특징, L2=0.001                            | 비교      |
| `logistic_history_l2_strong` | 22개 특징, L2=0.01                             | 비교      |

### 5.2 빈도 기준과 희소 후퇴

비종료 Train 상태에 대해 지원 수 `n`, 승리 수 `w`를 집계하고 `p=(w+1)/(n+2)`를 반환한다. 이 가산 평활화(Laplace smoothing)는 0/1 확률에 과도하게 확신하는 것을 완화한다. 세부 상태부터 다음 순서로 후퇴하며 처음 지원 수 30 이상인 집계를 사용한다. 마지막 전체 집계는 양의 지원 수만 요구한다.

| 순서 | 키                                     |
| ---: | -------------------------------------- |
|    1 | 참조 이닝·초말·점수차·아웃·주자 마스크 |
|    2 | 이닝 그룹·초말·점수차·아웃·주자 마스크 |
|    3 | 이닝 그룹·초말·점수차·아웃             |
|    4 | 이닝 그룹·초말·점수차                  |
|    5 | 초말·점수차                            |
|    6 | 점수차                                 |
|    7 | 전체                                   |

이닝 그룹은 1~3, 4~6, 7~9, 10 이상으로 구분한다. 가상 전이 키는 이 참조 이닝이 아니라 실제 이닝을 사용한다. 빈도 표의 조건을 완화하는 후퇴와 LI 지원 부족의 미지원 처리는 서로 다른 정책이다.

### 5.3 로지스틱 회귀와 학습 목적

표준화한 특징 `z`와 절편 `b`, 계수 `w`에 대해 `a=b+w·z`, `p=1/(1+exp(-a))`를 사용한다. 공식 확정 종료는 학습 분류기와 분리하여 규칙값으로 처리한다. 동일 특징 벡터와 이진 정답 조합을 `Counter`로 집계하고 개수만큼 가중치를 둔다. 이 집계는 부트스트랩이나 무작위 복원추출이 아니다.

이론적 목적은 가중 이진 교차 엔트로피 및 선택 L2 벌점의 최소화다. 한 미니배치에서 가중치 합 `N_B`, 레코드 반복 수 `n_k`, 정답 `y_k`에 대해 기울기는 `sum(n_k*(p_k-y_k)*z_k)/N_B + lambda*w`이며 절편에는 L2를 적용하지 않는다. 이는 Bernoulli 음의 로그우도에 대한 경사하강 원리를 사용한 것이다. 안정적인 시그모이드와 `epsilon=1e-15` 절단을 사용한다.

| 설정        | 값                                                | 근거 및 제한                                                      |
| ----------- | ------------------------------------------------- | ----------------------------------------------------------------- |
| Seed        | 42                                                | 동일 환경과 입력 순서의 실험 재현을 위한 고정값                   |
| Epoch       | 12                                                | 사전 고정 횟수. 조기 종료·최적 수렴 판정은 없음                   |
| Batch       | 512개 집계 레코드                                 | 원래 타석 상태 512개와 동일하다고 해석하지 않는다.                |
| 초기 학습률 | 0.15                                              | epoch e(0부터)에 `0.15/sqrt(e+1)` 적용                            |
| L2          | 0, 0.001, 0.01                                    | 고정 비교 후보. 전체 탐색이나 최적값의 증명 아님                  |
| 실행 환경   | CPU, Python 3.12 가상환경                         | 외부 학습 라이브러리나 GPU를 추가하지 않았다.                     |
| 선정 규칙   | Validation 전체 Log loss 최소, 동률 시 Brier 최소 | 완전 동률은 후보 순서상 먼저 비교한 단순 모델. ECE는 진단 지표다. |

가중 집계 미니배치 경사하강은 전체 데이터의 단일 배치 경사하강과 갱신 경로가 같지 않다. 각 배치를 고정 Seed로 섞고 배치 가중치 합으로 정규화한다. 학습 목표, 경사하강 업데이트, 최종 Validation 선정 기준을 구분한다. 확률 보정기는 이번 버전에 추가하지 않았다.

### 5.4 잔여 기대득점 통계

RE는 반이닝 방향·아웃·주자 평균에서 아웃·주자, 아웃, 전체 평균으로 후퇴한다. 공식 종료 또는 3아웃은 비교 후보 모두 0이다.

비종료 상태의 정답 잔여 득점 `R_i`를 사용해 각 키에서 `RE = sum(R_i)/n`을 계산한다. 아웃 0~2와 8가지 주자 마스크의 기본 조합을 초말 방향으로 더 세분한다. 비교 후보인 전체 평균은 같은 종료 규칙과 같은 Validation 상태를 사용한다. 최소 지원 30과 전체 평균 후퇴를 유지한다. 조건부 평균은 제곱오차 최소화 관점에서 자연스럽지만 절대오차 최소값(조건부 중앙값)과는 일반적으로 다르다. 두 오차 지표의 실제 결과를 모두 검증한다.

### 5.5 상태 전이와 상황 중요도

상황 중요도는 타석 직전 실제 이닝·초말·점수차·아웃·주자 키에서 Train의 물리 전이 `득점|후속 아웃|후속 주자 마스크`를 집계한다. 과거의 실제 종료 결과는 전이 코드에 저장하지 않는다. 각 전이를 현재 상태에 적용한 후 현재 시즌 정상 종료 규칙을 적용한다. 9회초 이후 홈팀 우세로 초가 끝나면 원정 공격팀 패배, 9회말 이후 홈팀이 앞서게 되면 승리, 말 공격의 3아웃 후 점수차가 있으면 승패, 최대 이닝 말 3아웃 동점은 무승부다. 그 외는 운영 예측기로 평가한다. 예외적 공식 종료의 발생 확률은 추정하지 않는다.

상황 중요도 = 가능한 전이의 확률 가중 절대 WPA 합 / 지원되는 Train 사전 상태의 가중 평균. 최소 지원 30, 지원 부족 또는 분모 0은 null이다. 실제 평가 타석의 결과를 중요도 계산에 쓰지 않는다. 2024년 11회말 동점 3아웃은 계속, 2025년 동일 상태는 무승부 종료로 재현한다. 두 시즌의 물리 전이 분포 자체가 동일하다는 보장은 없으며, 현재 방법은 이전 시즌의 경험적 분포를 제한적으로 재사용하는 가정이다.

전이 `t=(runs,post_outs,post_mask)`의 경험 확률을 `q(t|s)=n(s,t)/sum_t n(s,t)`로 두고, `D(s)=sum_t q(t|s)*abs(WP(s_t)-WP(s))`를 계산한다. 가능한 전이의 확률 합은 1이다. 지원 Train 타석의 등장 횟수로 가중한 참조 평균 `D_ref`로 `LI(s)=D(s)/D_ref`를 정의한다. 이때 공식 경기 종료 정답을 과거 전이 코드에 저장하지 않고 현재 시즌 규칙을 다시 적용한다. 사전 상태에서만 계산하며 실제 관측 후속 결과를 조건으로 삼지 않는다.

| 예외                             | 처리                                                                    |
| -------------------------------- | ----------------------------------------------------------------------- |
| 지원 수 30 미만                  | `value=null`, `reason=insufficient_transition_support`                  |
| 지원 참조 평균 미확정·0 이하     | `value=null`, `reason=unsupported_reference_mean`                       |
| post 상태                        | `value=null`, `reason=pre_state_required`                               |
| 정상 규칙으로 결정되는 가상 종료 | 가상 WP=0 또는 1, 실제 종료 인증은 하지 않음                            |
| 강우 등 관측 예외 종료           | 가상 발생 확률 모델 없음. 실제 관측 공식 종료는 별도 감사 계약으로 처리 |

| 로그 오즈와 시그모이드                                   | 직접 적용                | 선형 점수 `a=b+w·z`를 0~1 범위의 승리 사건 확률로 바꾼다. 점수차·이닝·주자 정보를 선형 점수의 특징으로 사용한다.                                                                                                 |
| 최대우도(MLE)·음의 로그우도(NLL)·이진 교차 엔트로피(BCE) | 직접 적용                | 강의의 이진 로지스틱 회귀 손실 원리를 적용한다. 비종료 Train 상태의 `(p-y)` 기울기로 가중치를 갱신하며 Validation은 동일 표본 Log loss로 평가한다.                                                               |
| 경사하강법과 학습률                                      | 직접 적용 및 구현 변형   | 가중 미니배치 512개 집계 레코드, 12 epoch, 고정 Seed, 학습률 제곱근 감소를 사용한다. 강의의 기울기 반대 방향 갱신 원리를 적용하되 집계·가중·스케줄은 프로젝트 구현이다.                                          |
| 학습·검증·최종 Test 분리                                 | 직접 적용 및 시간순 변형 | 과거 Train, 2025 Validation, 2026 잠금 Test로 분리한다. 같은 경기의 전후 상태를 분할하지 않는다.                                                                                                                 |
| 교차검증의 평가 독립성 및 일반화 원리                    | 문제에 맞게 변형         | 무작위/층화 K-fold를 실행한 것은 아니다. 서로 의존하는 경기 경계를 미래와 과거로 섞지 않고 시간 절단을 지킨다. 다중 시즌 Backtesting은 M4에서 아직 미실행이다.                                                   |
| Feature Engineering 및 스케일링 개선                     | 과제 안내의 원리 적용    | 점수차와 이닝/홈 여부의 상호작용, 주자 마스크, 최대 잔여 반이닝, 팀 이력 파생과 Train 표준화. 구체 수식은 프로젝트 자체 설계이며 강의 전사에서 동일 특징을 확인한 것은 아니다.                                   |
| 기준 모델과 비교·하이퍼파라미터 설정·과적합 고려         | 과제 안내의 원리 적용    | 동일 Validation에서 5개 승리 후보와 2개 RE 방법을 비교한다. 이력 특징 유무와 고정 L2 후보로 복잡도·규제 효과를 비교한다. Bias–Variance의 정량 분해, 전체 Grid/Random Search 및 독립 학습 곡선은 실행하지 않았다. |

### 6.2 강의 외 프로젝트 확장 원리

## 7. 평가 지표·실제 결과

### 7.1 평가 단위와 산식

| 지표            | 산식                                          | 방향·해석                                                                                                       |
| --------------- | --------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Binary Log loss | `-mean(y*ln(p)+(1-y)*ln(1-p))`                | 낮을수록 좋음. 확신한 오답에 큰 벌점. 수치 계산에 epsilon 절단을 사용하며 정확한 공식 종료 예측의 손실은 0.     |
| Brier score     | `mean((p-y)^2)`                               | 낮을수록 좋음. 이진 확률의 제곱오차.                                                                            |
| ECE             | `sum_b (n_b/N)*abs(mean_p_b-observed_rate_b)` | 낮을수록 좋음. 10개 동일 폭 구간, 최종 구간에 1 포함. 표본·구간에 의존하며 proper scoring rule과 다른 목적이다. |
| RE MAE          | `mean(abs(RE_hat-R))`                         | 낮을수록 좋음. 점 단위 평균 절대 오차.                                                                          |
| RE RMSE         | `sqrt(mean((RE_hat-R)^2))`                    | 낮을수록 좋음. 큰 오차에 민감한 점 단위 오차.                                                                   |
| LI coverage     | `지원 타석 수 / 전체 유효 타석 쌍 수`         | 중요도 적용 가능 범위. 확률 정확도와 별도다.                                                                    |

하위 구간(0.1~0.4)에서 승리 확률을 상대적으로 높게, 0.6 이상 구간에서 낮게 추정하는 경향이 있다. 0.3~0.4 구간 차이는 약 +5.29%p다. 높은 Log loss/Brier 성능과 별개로 확률의 신뢰도 개선 여지가 있다. 위 표는 선택에 사용된 Validation의 집계이며 신뢰구간이나 미래 시즌 보정 성능을 보장하지 않는다.

설정의 `models_dir/m4/<training_run_id>/model.json`과 `results_dir/m4/<training_run_id>/evaluation.json`, `example_input.json`, `example_prediction.json`에 저장한다. 버전 1.0.0의 기존 자산은 덮어쓰지 않으며 새로운 실행을 학습한다. 모델과 평가의 정규화 지문, 자료·코드 SHA-256, 후보·규칙·Seed를 기록한다. 자산을 복원하여 실제 예시 8개 유형과 시즌별 합성 예시 2개를 재현한다. 합성 규칙 예시는 실제 경기의 성능 지표에 포함하지 않는다. 원본 자료 및 산출물은 승인된 비영리 대학 과제용 로컬 처리 및 내부 평가에 한정한다.

### 8.2 인수 실행과 지문

| 항목              | 값                                                                 |
| ----------------- | ------------------------------------------------------------------ |
| 학습 실행 ID      | `52df3aae7b45406790165d4c871614b7`                                 |

지문은 사용자 로그의 학습·검증 출력에서 일치함을 확인한 값이다. 정규화 JSON 지문과 파일 바이트 해시는 서로 다른 검증 항목이다. 해당 파일 원본을 이 문서 작성 환경에 가져와 독립 해시를 계산하지는 않았다. `verify` 로그의 `source_hashes_match`, `evaluation_fingerprint_match`, `example_prediction_match`, `season_rule_examples_match`는 모두 True다. 학습 당시 소스별 해시와 원격 Commit의 바이트 직접 대조는 별도 증거가 필요하다.

### 8.3 호환성과 저장 정책

1.0.0의 이전 자산은 1.1.0에 직접 입력하지 않는다. 새로운 `m4-game-state-value-v2` 스키마와 경계 객체를 요구한다. 이전 자산과 입력을 거부하는 테스트가 통과했다. 새 학습마다 UUID 실행 ID를 만들고 기존 자산을 덮어쓰지 않는다. 검증된 모델 파일은 `model.pending.json`의 저장·복원 검사 이후 확정된다. 소스 변경 또는 입력 자료 변경 시 기존 지문으로 검증을 통과했다고 가정하지 않는다. 모델·자료·평가 결과는 로컬에 보존하고 Git에 원본 및 실행 자산을 추가하지 않는다.

## 10. 실행 명령

### 10.1 신규 학습·검증·추론

프로젝트 루트에서 Python 3.12 가상환경을 사용한다. 기존 자산을 재사용하지 말고 신규 실행 ID를 사용한다.

```powershell
Set-Location -LiteralPath 'D:/Programming/kbo-insight-ai'
$py = 'D:/Programming/kbo-insight-ai/.venv/Scripts/python.exe'
& $py -X utf8 -B -m unittest discover -s tests/models -p test_game_state_value.py -v
if ($LASTEXITCODE -ne 0) { throw 'M4 tests failed' }
& $py -X utf8 -B -m unittest discover -s tests
if ($LASTEXITCODE -ne 0) { throw 'Regression tests failed' }
$raw = & $py -X utf8 -B -m src.models.game_state_value train --run-id 259b38decaac4ed68dd5a596cfbe4849
if ($LASTEXITCODE -ne 0) { throw 'M4 train failed' }
$run = $raw | Out-String | ConvertFrom-Json
& $py -X utf8 -B -m src.models.game_state_value verify --asset $run.paths.model --evaluation $run.paths.evaluation
if ($LASTEXITCODE -ne 0) { throw 'M4 verify failed' }
& $py -X utf8 -B -m src.models.game_state_value predict --asset $run.paths.model --input $run.paths.input
if ($LASTEXITCODE -ne 0) { throw 'M4 predict failed' }
```

각 단계 종료 코드, 학습 ID, 평가 JSON 및 모델·평가 지문을 확인한다. 새 UUID가 생성되므로 다른 실행의 경로를 혼용하지 않는다. 예측 결과에는 감사 식별자와 기존 입력 계약이 포함되어야 한다.

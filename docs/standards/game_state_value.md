## 1. 목적·지원 범위

타석 경계까지 관측된 상태에서 고정 공격팀의 무조건부 승리 확률과 같은 반이닝의 잔여 기대득점을 추정한다. 타석 이후에는 관측 전후 차이와 실제 득점을 계산한다. 타석 이전 상황 중요도는 가능한 전이의 경험적 확률을 사용한다. 운영 승리 예측기는 하나이며 기대득점과 전이 분포는 학습 통계표다. 별도 배포 서비스, 포스트시즌 및 최종 Test 평가는 포함하지 않는다.

## 3. 입력·전처리

34개 허용 열 중 22개를 사전 입력 계약으로 사용한다. 시즌, 정규시즌 여부, 홈·원정·공격팀 식별자와 phase는 계약 검사에 사용한다. 실제 수치 특징은 이닝, 공격팀 홈 여부, 공격팀 점수차, 아웃, 주자, 점수차 상호작용, 선택적으로 양 팀의 시즌 이전 경기수·득실점·승수에 기반한 특징이다. 과거 기록 누락을 표시하며 고정 평활화 및 Train 특징 평균·표준편차를 사용한다. 경기/타석 ID, 감사 정보, 정답, 미래 상태는 모델 특징으로 쓰지 않는다. 3아웃의 주자는 특징에서 정규화한다.

<a id="outputs"></a>

## 4. 정답·출력 계약

승리=1, 무승부·패배=0이다. `win_probability`는 무승부 제외 확률이나 승리 지분이 아니다. 기대득점은 현재 반이닝 종료까지 실제 남은 득점의 조건부 평균이다.

- WPA = 타석 후 승리 확률 - 타석 전 승리 확률.
- 잔여 기대득점 변화 = 타석 후 RE - 타석 전 RE.
- 득점 포함 타석 가치 = 실제 공격팀 득점 + 잔여 기대득점 변화.

3아웃은 RE=0이지만 그 자체로 경기 종료가 아니다. 공식 Final, 최종 점수, 원본 마지막 타석, 순서·경계·득점 일치와 종료 형태를 확인한 경우만 승리 사건의 확정값을 사용한다. 부분 반이닝 종료는 공식 종료 근거를 확인하되 감독 의도나 종료 원인을 확정하지 않는다. 독립 추론의 `final` 객체는 호출자가 제공한 종료 근거이며 원본 DB 없이 출처의 진위를 재검증할 수 없다. 근거가 없으면 경기 종료 확정값을 적용하지 않는다.

<a id="training"></a>

## 5. 모델·학습·선정

기준은 상태별 승리 빈도이며 최소 지원 30, Laplace 평활화, 상태 축소 후퇴 규칙을 사용한다. 비교 후보는 기본 로지스틱 회귀, 팀 과거 특징을 추가한 로지스틱 회귀 및 L2 규제 후보 2개(0.001, 0.01)이다. 빈도 기준을 포함하여 5개 후보를 비교한다. 가중 미니배치 512개, 12 epoch, 초기 학습률 0.15와 epoch별 제곱근 감소를 사용한다. 팀 과거 특징은 고정 5경기 평활화(경기당 4득점·4실점, 승률 0.5) 및 누락 표시를 사용한다. 이 값들은 최적값이라는 실측 근거가 없는 사전 고정값이다. Train에서만 전처리와 계수를 적합한다. Seed와 학습 설정은 고정한다. 2025 Validation의 동일 상태에 대한 Log loss, Brier 순으로 후보를 선택한다. 확률 보정은 신뢰도 구간과 ECE로 진단하며 별도 보정기 적합을 기본안에 포함하지 않는다. 최종 Test는 사용하지 않는다.

RE는 종료 전 Train 상태의 반이닝별 아웃·주자 평균에서 시작해 아웃·주자, 아웃, 전체 평균으로 후퇴한다. 종료 상태에는 모든 비교 방법에서 0을 적용한다.

상황 중요도는 정확한 타석 전 이닝·초말·점수차·아웃·주자 상태를 기준으로 Train의 전이(득점, 후속 아웃·주자, 관측 종료 여부)를 집계한다. 각 전이 확률에 운영 승리 확률의 절대 변화량을 가중해 합산하고, 지원되는 Train 타석의 기대 절대 변화량 평균으로 나눈다. 최소 지원 30, 분모 0·미지원은 null이다. 실제 평가 타석의 후속 결과는 해당 타석의 상황 중요도 계산에 쓰지 않는다. M2 확률만으로 전이 상태를 결정하지 않는다.

## 6. 강의 원리 및 프로젝트 확장

| 방법                            | 적용                                   |
| ------------------------------- | -------------------------------------- |
| 지도학습·이진분류·로지스틱 회귀 | 비교 후보의 직접 사용                  |
| 특징 변환·스케일링              | Train 평균·표준편차 및 점수차 상호작용 |
| 규제·Bias–Variance              | 고정 L2 후보의 검증 비교               |
| 베이스라인과 동일 표본 비교     | 상태별 빈도와 로지스틱 후보            |

프로젝트 확장은 반이닝 종료 통계, WPA, 득점 가치, 전이 기반 상황 중요도, 시간순 분할과 데이터·자산 지문이다. 위 기법의 강의 전사 원문과 정확한 일치 여부는 이번 응답에서 직접 확인하지 못했다. 랜덤포레스트·부트스트랩·투표 앙상블은 추가하지 않는다.

<a id="metrics"></a>

## 7. 평가 지표·실제 결과

이진 Log loss는 실제 승리 여부의 음의 로그우도 평균이며 Brier는 `(p-y)^2`의 평균이다. 확률 0/1의 로그 계산에는 수치 안정화 절단을 적용한다. 보정은 10개 동일 폭 확률 구간의 표본 수·평균 예측·관측 빈도 및 ECE로 확인한다. 전체·비종료·pre/post 상태를 구분한다. 기대득점 MAE와 RMSE는 조건부 통계와 전체 평균 기준을 동일 표본에서 비교한다. 상황 중요도는 지원률과 미지원 사유, 지원 상태의 평균값을 보고한다.

새 모델의 실제 성능, 후보 선정, 적용률은 사용자 실행 전에는 미확인이다. Validation은 선택에 사용되므로 독립 Test가 아니다.

## 8. 구현·산출물·재현성

- `src/models/game_state_value/data.py`: 인수·원본 대조
- `src/models/game_state_value/model.py`: 상태 계약·승리 분류
- `src/models/game_state_value/value.py`: RE·상황 중요도·타석 가치
- `src/evaluation/game_state_value.py`: 평가
- `src/models/game_state_value/__main__.py`: CLI 및 자산 저장·검증

설정의 `models_dir/m4/<training_run_id>/model.json` 및 `results_dir/m4/<training_run_id>/evaluation.json`, `example_input.json`, `example_prediction.json`에 저장한다. 자산의 정규화 지문, 평가 지문, 코드 SHA-256, 입력 계약·자료·시드·후보를 기록한다. 저장 전후 예시 값과 독립 프로세스 추론의 일치를 검사한다. 정답 DB 없이 계약에 맞는 상태/타석 입력과 저장 자산으로 추론할 수 있다. 자료와 산출물은 승인된 비영리 로컬 평가 범위에서만 사용한다.

<a id="limits"></a>

## 9. 검증·한계·후속 연결

확률, 관점, 입력 오류, 쌍 연결, 3아웃·공식 종료·무승부·부분 종료·희소 상태를 검사한다. 관측 상태의 선택 편향 및 희소 전이, 2025년 제외 반이닝, 과거 자료의 공개 시점 완전 복원 불가, 호출자 종료 근거의 진위 확인 제한을 명시한다. 전이 기반 중요도는 표준화된 MLB LI와 동일한 값이 아니며 숨은 감독 의도나 인과효과를 나타내지 않는다. 신규 모델의 실제 테스트·재현 및 2026년 독립 일반화 성능은 확인 전이다.

## 10. 실행 명령

프로젝트 루트에서 Python 3.12 가상환경을 사용한다.

```powershell
Set-Location -LiteralPath 'D:/Programming/kbo-insight-ai'
$py = 'D:/Programming/kbo-insight-ai/.venv/Scripts/python.exe'
& $py -X utf8 -B -m unittest discover -s tests/models -p test_game_state_value.py -v
& $py -X utf8 -B -m unittest discover -s tests
$run = & $py -X utf8 -B -m src.models.game_state_value train --run-id 259b38decaac4ed68dd5a596cfbe4849 | ConvertFrom-Json
& $py -X utf8 -B -m src.models.game_state_value verify --asset $run.paths.model --evaluation $run.paths.evaluation
& $py -X utf8 -B -m src.models.game_state_value predict --asset $run.paths.model --input $run.paths.input
```

각 실행 종료 코드와 평가 JSON을 확인한다. 실제 결과를 확보한 뒤 기술 문서의 수치 및 프로젝트 안내의 완료 상태를 갱신한다.

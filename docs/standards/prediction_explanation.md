## 1. 목적·지원 범위

<a id="목적과-범위"></a>

이 기능의 목적은 새로운 예측기의 개발이 아니라 이미 선정된 6개 운영 예측기의 계산 근거와 오류 양상을 검증 가능한 형태로 제공하는 것이다. 설명은 모델의 수치 계산을 검산하고, 고정 최종 평가의 신뢰도·지원 범위·실패 사례를 분석한다. 모델의 정확도와 설명의 충실성, 자료의 사실 정확성, 독립 재현성은 서로 다른 판정 대상이다.

| 기능                | 설명 대상                                                | 해석 경계                                             |
| ------------------- | -------------------------------------------------------- | ----------------------------------------------------- |
| M1 경기 결과·득점   | 홈·원정 기준 PMF, 프로파일, 결합 및 승무패 확률          | 기대득점과 실제 확정 득점 구분; 단계 변화는 SHAP 아님 |
| M2 타석 결과        | 클래스별 로짓 SHAP, 마스크·평활·저장 보정                | 로짓 기여와 최종 확률 변화 구분                       |
| M3 타자             | 과거 기록률, 사전 통계, 기간별 Count와 공동 투영         | 실제 0·미관측·기간 미완료 분리                        |
| M3 투수             | 이력 기준, 단일 공동 잔차 트리의 경로, 축소·투영         | 경로 차분을 TreeSHAP으로 부르지 않음                  |
| M4 경기 상황 가치   | 비종료 승리 로짓, RE 조회 근거, WPA·RV·LI 및 공식 종료   | 사후 확인된 종료 사실은 당시 입력이 아님              |
| M5 다음 투구        | 공동 로짓·SHAP, 구종·결과 주변화, 희소 지원              | 위치·궤적 제외; 미출현 구종의 일반화 미보증           |
| 정규시즌·포스트시즌 | 동일 반복의 진출·정규시즌 1위·한국시리즈 우승, 공동 분모 | 2025년 사후 일정 가정 시나리오                        |
| 예상 선발·팀·일정   | 후보 및 정답 식별, 적중률, 관측 기록과 기대 손실         | 후보 순위는 선발 확률·공식 발표 아님                  |

`prepare` → `run` → `verify`의 책임을 분리한다. 신규 학습·보정·모델 선정·LLM 결합·GPU 학습·API 배포·새 SHAP 라이브러리를 추가하지 않는다. 설명 기능의 기술 수용 및 [PR #39](https://github.com/Ahn-SooHyun/kbo-insight-ai/pull/39) 병합(`ea4ef45`), [Issue #36](https://github.com/Ahn-SooHyun/kbo-insight-ai/issues/36) 완료 종료를 확인했다. 개정 문서에 대한 신규 실행은 별도이며 기존 실행을 소급 변경하지 않는다.

### 2.2 시간 경계와 정답 감사

| 분할           | KST 날짜                        | 역할                     |
| -------------- | ------------------------------- | ------------------------ |
| Train          | 2025-01-01 미만                 | 학습 및 배경 통계        |
| Validation     | 2025-01-01 이상 2026-01-01 미만 | 개발 비교·선정·보정      |
| 고정 최종 Test | 2026-01-01 이상 2026-11-26 미만 | 고정 성능 평가·사후 설명 |

최종 Test의 입력·정답 분리, 사전 예측 저장, 원천 재생성, 표본 식별 및 누수 감사 계약을 유지한다. 설명 시점에 이미 고정된 정답을 읽어 오류를 설명하는 것과 예측기 학습·선정·보정에 이용하는 것은 다르다. 이후 Test를 이용해 설정을 선택하면 기존 독립 평가의 지위를 훼손한다. 동일 경기·동일 선수의 중첩 기간은 독립 관측으로 간주하지 않는다. M3의 월요일 이전 입력 및 실제 완료 기간 마스크를 보존한다.

`evaluation/<model>/predictions.jsonl`, `targets.jsonl`, `metrics.json` 및 `result.json`의 참조가 정본이다. 전체 모집단과 지표별 유효 분모, 설명 가능 표본, 실패 선정 표본을 구분한다. 설명 작업이 새 원천 EDA나 새 피처 설계를 완료한 것은 아니다.

## 3. 입력·전처리

<a id="표본-및-진단"></a>

### 3.1 저장 모델에 대응하는 설명 입력

| 모델 | 실제 특징 표현                      | 설명 기준                                         |
| ---- | ----------------------------------- | ------------------------------------------------- |
| M1   | 홈·원정 및 경기 전 시즌·최근 이력   | Train 장소별 분포 및 조건 프로파일                |
| M2   | 실제 타석 전 상태·ID 인코딩·수치    | 적격 Train의 계수 키별 평균, 절편 `bias` 제외     |
| M3   | 월요일 이전 선수 이력·기간·Count    | Train 일수당 사전율 및 투수 트리 루트             |
| M4   | 실제 Core의 표준화된 12개 특징      | 저장 Train 평균·표준편차, 표준화 평균 0           |
| M5   | 투구 전 상태·이력·실제 활성 계수 키 | Train 평균, `fallback_key` 적용 후 활성 횟수 누적 |

`train_background`는 적격 Train 입력만 조회하고 입력 열을 제한하는 읽기 전용 SQLite `prediction_authorizer`를 사용한다. 각 행의 기간·분할을 확인하고 적격 수와 저장 모델 학습 빈도를 대조한다. M4 표준화 통계를 Test에 다시 맞추지 않는다. 설명에 필요한 배경의 계산은 새 모델 학습이 아니다.

M4의 Core 특징 순서는 `features(state, False)`의 실제 순서를 유지한다.

| 순번 | 특징                                      | 계산                                  |
| ---- | ----------------------------------------- | ------------------------------------- |
| 1    | `inning`                                  | 현재 이닝                             |
| 2    | `attacking_home`                          | 공격팀 홈 여부                        |
| 3    | `score_difference`                        | 공격팀 관점 점수차                    |
| 4    | `outs`                                    | 아웃 수                               |
| 5–7  | `on_first`, `on_second`, `on_third`       | 각 루 점유 표시                       |
| 8    | `score_difference_x_inning`               | 점수차 × 이닝                         |
| 9    | `score_difference_x_home`                 | 점수차 × 홈 공격 표시                 |
| 10   | `absolute_score_difference`               | 점수차 절댓값                         |
| 11   | `late_inning`                             | 7회 이상                              |
| 12   | `score_difference_per_future_opportunity` | 점수차 / √(남은 최대 반이닝 기회 + 1) |

### 3.2 전량 진단과 설명 표본의 차이

전역 설명 표본은 각 모델의 적격 `sample_id`에서 `SHA256(str(42) + ':' + sample_id)`의 작은 순서로 최대 2,000개, 동률이면 ID 오름차순으로 정한다. 2,000개 미만이면 전량을 사용한다. 정답·예측 오차로 전역 표본을 선택하지 않는다. 해시 순위는 재현 가능한 선택 기준이지 확률 표집 또는 모집단 대표성의 보증이 아니다.

실패·희소·미지원 사유별 대표 사례는 정의된 비음수 점수 내림차순 및 ID 오름차순으로 최대 5개씩 선택한다. 동일 사례가 여러 사유에 포함될 수 있다. 전역 표본과 실패 표본의 합집합을 개별 설명 대상으로 저장하되 실패 사례로만 추가된 행은 전역 중요도 집계에서 제외한다. 전역과 실패에 모두 포함된 행은 원래 전역 가중을 유지한다.

M2는 `M2StreamingScore`로 혼동행렬·Log loss·Brier·신뢰도 구간을 순차 누적한다. 나머지 고정 지표는 기존 평가기를 재사용한다. M4 전·후 상태는 같은 타석 키와 ID 접미사를 검증한다. 최대 메모리·처리 시간·전체 기능의 점근적 메모리 복잡도를 별도로 측정하지 않았으므로 O(1) 메모리나 GPU 대비 성능을 주장하지 않는다.

## 4. 정답·출력 계약

### 4.1 출력의 단위와 정합성

| 기능 | 정답·관측                                 | 설명 척도                                   |
| ---- | ----------------------------------------- | ------------------------------------------- |
| M1   | 최종 홈·원정 득점 및 승무패               | 득점 PMF, 기대득점 및 결합 확률             |
| M2   | 타석의 고정 15개 결과 범주                | 보정 전 로짓 기여, 확률 단계 변화           |
| M3   | 역할·기간·기록별 완료 Count 및 유효 비율  | Count, 비율, 예측 구간 및 투영 변화         |
| M4   | 동일 공격팀의 승리 여부, 남은 반이닝 득점 | 로짓, WP, RE, WPA, RV, LI                   |
| M5   | 구종·결과 공동 정답 및 각 주변 정답       | 공동 70개 로짓 및 확률, 구종 10개, 결과 7개 |
| 시즌 | 반복 사건·실제 확인 가능한 공식 결과      | 유효·공동·전체 분모 및 논리적 사건 범위     |
| 보조 | 실제 선발 식별과 관측 팀 기록             | 후보 적중·제공률, 확률 기반 기대 손실       |

로짓 설명의 합은 로짓에 대해 검산한다. 비선형 확률 변환 뒤의 특징 기여를 원래 로짓 기여와 동일하게 합산하지 않는다. M3의 투영 전후 값은 같은 Count 단위에서 비교하고, 비율은 유효 분모로 계산한다. M4 종료 확정 규칙은 일반 모델 추론과 구분한다. M5의 공동 확률에서 두 주변 분포를 얻으며 별도 모델을 호출한 것으로 집계하지 않는다.

### 4.2 실패 사례와 지원 상태

| 모델      | 실패·제한 사유의 예                                      | 해석                                                           |
| --------- | -------------------------------------------------------- | -------------------------------------------------------------- |
| M1        | 실제 무승부, argmax 오류, 홈 득점 과대·과소              | 실제 무승부와 분류 오류는 다른 집합; 절대오차를 방향별로 본다. |
| M2        | 오분류, 희소·미출현, 클래스별 오류, 마스크 충돌          | 클래스와 지원 분모를 분리한다.                                 |
| M3        | 정답·구간 미관측, 실제 0, 구간 밖, 기준 대비 악화        | 구간 초과 거리는 `max(L-y,y-U,0)`; 누락은 0이 아니다.          |
| M4        | 공식 종료, 비종료 확률·RE 오차, Brier 악화, 3아웃 비종료 | 종료 결정 규칙을 일반 확률 예측과 혼합하지 않는다.             |
| M5        | 공동·구종·결과 각 축의 오류, 미출현·희소                 | 세 축별 오류와 유효 분모를 유지한다.                           |
| 시즌·보조 | 원천 충돌, 미결정, 정답 미식별, 후보 미제공              | 확률 0·지원 없음·미확정·오류를 분리한다.                       |

`eligible_samples`, `count`, `fraction`, `cases`는 사유별로 해석한다. 사유는 상호 배타적이지 않으므로 사유별 건수 합을 고유 실패 건수로 해석하지 않는다. 대표 사례는 전량 오류 집계의 대체가 아니다. 공개 문서는 원본 행·모델 전체 계수·DB·비밀을 포함하지 않는다.

## 5. 설명 방법·계산 척도

<a id="설명-방법과-척도"></a>

### 5.1 선형 로짓의 독립 개입 SHAP

클래스 c의 선형 로짓을 다음과 같이 둔다. x는 실제 저장 모델에 입력된 특징 공간, μ는 적격 Train 배경 평균이다.

$$z_c(x)=b_c+\sum_j w_{cj}x_j.$$

독립 개입 가치 함수 $v(S)=b_c+\sum_{j\in S}w_{cj}x_j+\sum_{j\notin S}w_{cj}\mu_j$에서 특징 j를 추가한 한계 기여는 부분집합과 무관하게 $w_{cj}(x_j-\mu_j)$다. 따라서 Shapley 가중치 합이 1이라는 성질에 의해 다음 닫힌식을 얻는다.

$$\phi_{0,c}=b_c+\sum_jw_{cj}\mu_j,\qquad \phi_{j,c}=w_{cj}(x_j-\mu_j),\qquad z_c=\phi_{0,c}+\sum_j\phi_{j,c}.$$

비활성 특징은 x=0이므로 기여는 $-w_{cj}\mu_j$다. `active_shap_values`, `inactive_shap_sum`, `base_values`를 통해 누락 없이 합을 검산한다. 독립 개입 설명은 상관을 조건으로 둔 conditional SHAP 또는 확률 척도의 SHAP이 아니며 인과 효과도 아니다. 전역 중요도는 선정된 적격 행에서의 평균 절대 기여 $N^{-1}\sum_i|\phi_{ij,c}|$를 사용한다. 다중 클래스 요약은 클래스 동일 가중 평균이지 발생 빈도 가중이 아니다. M4는 비종료의 유효 로짓만 집계한다.

### 5.2 M1: 득점 분포 및 단계 변화

장소별 Train 기준 PMF → 실제 프로파일 PMF → 결합 조정의 순서로 기대득점을 비교한다. PMF의 기대득점은 $\sum_r r p(r)$이며 다음 단계 변화는 실제 계산의 망원합이다.

$$m_{final}=m_{site}+(m_{profile}-m_{site})+(m_{final}-m_{profile}).$$

결합은 기존 운영 모델의 홈·원정 분포 및 동점 가중을 사용한다.

$$P(h,a)=\frac{p_H(h)p_A(a)w(h,a)}{Z},\qquad Z=\sum_{h,a}p_H(h)p_A(a)w(h,a).$$

홈승·무승부·원정승은 각각 h>a, h=a, h<a 영역의 합이다. 꼬리 처리와 정규화 상수·지원 수·실제 저장 동점/비동점 가중을 `explain_m1`의 계산과 연결한다. 단계별 기대득점 차이는 특징별 SHAP이나 인과 기여가 아니다.

### 5.3 M2: 규칙 제한 다항 로지스틱 및 보정

실제 저장 계수의 클래스별 로짓을 구하고 비제한 Softmax에서 허용 집합 A의 제한 Softmax를 얻는다. 허용 집합 밖 확률은 0이다. 허용 Train 사전 분포 $\pi_A$와 저장 혼합 비율 λ로 $q_{mix}=(1-\lambda)q_{mask}+\lambda\pi_A$를 계산한다. 마지막으로 저장 온도 T와 클래스별 절편 δ를 사용하여 허용 집합에서 $p_c\propto\exp(\log(q_{mix,c})/T+\delta_c)$를 구한다. `masked_probabilities`, `calibrate_vector`, `explain_m2`를 실제 저장 출력과 비교한다. 보정 전 로짓 SHAP과 마스킹·평활·보정의 확률 변화를 분리한다. 이 작업에서 온도를 새로 학습하지 않는다.

### 5.4 M3: 기록률·잔차·제약 투영

Train 사전율, 시즌 장기율, 최근 28일 단기율과 기존 후퇴 규칙을 실제 `player_history`에서 얻는다. 혼합식은 $r=\alpha r_{short}+(1-\alpha)r_{long}$이며 타자 `history_balanced_50`은 α=0.5다. 기간 d의 원시 Count는 dr이며 실제 기간·종료 가정은 저장 계약을 따른다. `m3.project`는 비음수 Count 및 기간 간 누적·기록 관계를 보존한다. 실제 미래 종료일을 입력하지 않는다.

투수의 깊이 4 단일 공동 잔차 트리는 특징값과 임계값의 비교로 경로를 결정한다. 루트에서 잎까지의 차분을 합하면 실제 잎 벡터가 된다.

$$u_{leaf}=u_0+\sum_{k=1}^{K}(u_k-u_{k-1}).$$

출력별 잔차 보정은 `leaf residual × train_scale × strength × scenario_factor_period`이며 저장 축소 계수는 0.50이다. 이력 기준에 더한 뒤 공동 투영한다. `tree_path`, `explain_m3`에서 분기, 잎 지원, 최종 Count 및 구간을 대조한다. 단일 경로 차분은 모든 부분집합의 기여를 평균하는 TreeSHAP이 아니다. 실제 구간 포함률과 폭을 보고하며 미래 관측의 교환가능성이나 엄밀한 보장을 주장하지 않는다.

### 5.5 M4: 승리 로짓, 기대득점, 경기 상황 가치

비종료 승리 확률은 저장 표준화 특징 $z_j=(x_j-\mu_j)/s_j$, 로짓 $\eta=b+\sum_jw_jz_j$, $WP=1/(1+e^{-\eta})$로 계산한다. 무승부는 공격팀 비승리 사건이다. 공식 종료 근거가 일치할 때 WP는 실제 승리 여부에 따른 0 또는 1, RE는 0이다. 3아웃은 반이닝 종료이나 항상 경기 종료는 아니다.

| RE 조회 순서 | 실제 저장 키                   | 최소 지원 |
| ------------ | ------------------------------ | --------- |
| 1            | `exact:<half>\|<outs>\|<mask>` | 30        |
| 2            | `base_out:<outs>\|<mask>`      | 30        |
| 3            | `outs:<outs>`                  | 30        |
| 4            | `global`                       | 1         |

표의 이스케이프된 세로줄은 키의 구분 문자다. 선택 통계 `[n,total]`의 `RE=total/n`을 직접 검산한다. `re_evidence`에서 선택 키와 조회 경로, `missing`·`insufficient_support`·`selected`, 지원 수 및 오차를 보존한다. `raw_re_evidence`와 `evaluated_re_evidence`를 나누고 종료 결정 시 `selected_key=null`은 정상이다.

동일 공격팀 관점의 전후 상태에서 다음을 구한다.

$$WPA=WP_{after}-WP_{before},\qquad \Delta RE=RE_{after}-RE_{before},\qquad RV=R_{actual}+\Delta RE.$$

$$LI=\frac{E_{Train}(|WPA|\mid state)}{E_{Train,ref}(|WPA|)}.$$

LI의 Train 전이 지원·참조 평균과 미지원 사유를 보존한다. LI는 해당 타석의 실제 WPA가 아니다. 공식 종료 사후 정보를 경기 전 입력으로 되돌리지 않는다.

### 5.6 M5: 공동 로짓·주변 확률

실제 저장 70개 공동 범주의 로짓과 Softmax를 검산한다. Temperature 1.15가 이미 저장 운영 계수에 반영되었으므로 다시 나누지 않는다. 구종 t 및 결과 r의 주변 확률은 $P(t)=\sum_rP(t,r)$, $P(r)=\sum_tP(t,r)$다. 세 축의 실제 정답과 지표를 분리하며 공동 로짓 SHAP을 주변 확률의 SHAP으로 바꾸지 않는다. 미출현 ID 후퇴와 희소 범주 지원을 기록하고 구종·결과의 양의 확률을 충분한 일반화의 증거로 확대하지 않는다.

### 5.7 시즌·보조 분석의 설명

[시즌 검증](season_forecast_validation.md#method) 및 [보조 분석](support_analysis.md#method)의 기존 계산을 연결한다. 반복 경로·규칙·분모, 후보 순위의 사전식 비교, 관측 기록 및 기존 M1 기대 손실을 설명한다. 새 시즌 모델·선발 분류기나 SHAP 모델은 생성하지 않는다.

### 6.3 미실행·비교 후 미채택

무작위 K-fold·Stratified K-fold, 신규 선형/로지스틱 회귀·KNN·SVM·트리 적합, Bootstrap·OOB·Random Forest·Bagging·Boosting·Voting·Stacking, 외부 SHAP 패키지·TreeSHAP·KernelSHAP, Test 기반 Temperature/Threshold 적합, Grid/Random Search는 이번 설명 기능에서 미실행 또는 금지 범위다. 앞선 모델 개발의 후보 실험은 각 모델 문서에서 관리한다. 이번 작업의 신규 성능 개선으로 중복 계상하지 않는다.

## 7. 평가 지표·실제 결과

### 7.1 지표 정의 및 비교 원칙

MAE는 절대오차 평균, RMSE는 제곱오차 평균의 제곱근이다. Log loss는 실제 정답에 부여한 확률의 음의 로그 평균이다. 다중 분류 Brier는 클래스별 제곱오차 합의 표본 평균이며 이진 Brier는 $(p-y)^2$의 평균이다. CRPS는 분포의 누적 확률과 실제 관측의 누적 지시값의 제곱 차이를 이용한다. ECE는 구간별 예측 확률과 실제 빈도의 차이의 표본 가중 평균이다. Top-label ECE와 macro classwise ECE는 다른 진단이며 직접 비교하지 않는다. 실제 계산의 경계·빈 구간·절단 정책·정규화는 기존 평가 명세와 소스가 정본이다.

### 7.7 시즌·선발·보조 분석의 진단

2025-09-01 KST, Seed 42, N=1,000회 시나리오의 공동 유효 분모는 정규시즌 1위 984회, 진출 922회, 순위·시드 906회, 한국시리즈 우승 899회다. 사건 유효 V회, 발생 H회일 때 H/V는 조건부 추정량이다. 미결정 비율은 (N−V)/N, 가능한 무조건 사건 비율의 논리적 범위는 [H/N,(H+N−V)/N]이며 통계적 신뢰구간이 아니다. V=0이면 확률은 `null`이다. 2025년 한국시리즈 5차전 원천 기록 충돌에 따른 종료 재생의 우승 1,000회 전부 미결정과 실제 공식 우승팀을 혼동하지 않는다. 시즌 종합 검증의 작업 성공 15건, 독립 검산 35건, 실패 0·안정성 경고 0은 사용한 조건 내 계산 검증이다. 2026 시즌·보조 분석은 미지원이다.

선발은 2025 개발 비교의 전체 1,440팀 측, 정답 식별 1,439측, 후보 제공 1,430측, 공통 1,429측이다. 기준 Top-1 269/1,429(18.82%), Top-3 1,056/1,429(73.90%), 제안 규칙 Top-1 258/1,429(18.05%), Top-3 962/1,429(67.32%)를 보존한다. 기준 규칙 채택은 동일 개발 자료 비교 결과이며 실제 당시 공식 공개 시각의 입증이나 독립 2026 평가가 아니다. 자세한 계산과 결과는 [보조 분석](support_analysis.md#evaluation)과 [시즌 검증](season_forecast_validation.md#evaluation)을 따른다.

소스 인벤토리는 기술 문서와 개발 흐름 문서, 코드·테스트·설정을 포함한다. 문서 변경만으로도 기존 명세와 불일치할 수 있다. 과거 명세는 일치하는 역사 판본과 원래 참조 경로를 준비해 검증한다. 현재 판본에서 신규 계산이 필요하면 새 `prepare`와 독립 실행 두 건을 생성한다. 원래 명세·결과·지문을 수정하지 않는다. `--reuse-result`는 동일 계획의 검증된 성공 부분만 재사용할 수 있으며 독립 재현 두 건으로 집계하지 않는다.

합계는 독립 표본 수나 경기 수가 아니다. 전역 중요도는 전체 진단 행 수나 개별 설명 행 수와 별개의 분모를 사용한다. 선행 실행의 기술 검증·수용·병합 및 종료와 이번 문서의 적용·검증을 구별한다.

### 9.2 제한과 변경 통제

- 최종 Test 지표 개선과 악화가 공존한다. 기존 Test에 맞춘 새 최적화를 하지 않는다.
- SHAP의 가산성은 정의한 로짓과 Train 배경의 계산 성질이다. 인과 효과나 상관 구조의 완전 설명이 아니다.
- M3 관측·구간·지원, M5 희소·미출현, 경기·선수 내 의존성은 유지한다. 통계적 유의성·독립 신뢰구간을 새로 검증하지 않았다.
- 2025년 가정 시나리오, 한국시리즈 기록 충돌, 2026 시즌 미지원을 보존한다.
- #40에서 과거 판본의 전체 CLI 재실행, 현 판본의 신규 명세와 전체 CLI, 최종 Test 전량 재추론은 미실행이다. 지문 검증과 저장 지표·배경 재계산은 그 제한 내 검증이다.
- 새 기능·모델·새 시즌 지원은 별도 승인 범위다. 기존 공개 자료 이용 범위를 확대하지 않는다.

## 10. 실행 명령

다음은 기존 실행 계약의 현재 판본 신규 설명 실행 예시다. 기존 성공 실행을 덮어쓰지 않는다. 명령은 사용자가 실제 저장소 및 승인된 자산이 있는 Windows PowerShell에서 실행하며, 이 문서 개정 과정에서 실행한 결과가 아니다. 고정 참조 또는 환경 지문이 다르면 임의로 값을 바꾸지 않고 원인을 확인한다.

```powershell
Set-Location 'D:/Programming/kbo-insight-ai'
$python = (Resolve-Path '.venv/Scripts/python.exe').Path
& $python -X utf8 -B -m unittest discover -s tests/explainability -p 'test_*.py' -v
if ($LASTEXITCODE -ne 0) { throw '설명 전용 테스트 실패' }

$prepareOutput = & $python -X utf8 -B -m src.explainability prepare
if ($LASTEXITCODE -ne 0) { throw '설명 계획 준비 실패' }
$prepare = ($prepareOutput -join "`n") | ConvertFrom-Json
if ($prepare.status -ne 'prepared') { throw '계획 상태 오류' }

$firstOutput = & $python -X utf8 -B -m src.explainability run --plan $prepare.plan --sha256 $prepare.sha256
if ($LASTEXITCODE -ne 0) { throw '첫 설명 실행 실패' }
$first = ($firstOutput -join "`n") | ConvertFrom-Json
if ($first.status -ne 'completed' -or $first.completed_models -ne 6 -or $first.season_status -ne 'completed') { throw '첫 설명 결과 불완전' }

$secondOutput = & $python -X utf8 -B -m src.explainability run --plan $prepare.plan --sha256 $prepare.sha256
if ($LASTEXITCODE -ne 0) { throw '두 번째 설명 실행 실패' }
$second = ($secondOutput -join "`n") | ConvertFrom-Json
if ($second.status -ne 'completed' -or $second.completed_models -ne 6 -or $second.season_status -ne 'completed') { throw '두 번째 설명 결과 불완전' }

$verifyOutput = & $python -X utf8 -B -m src.explainability verify --plan $prepare.plan --sha256 $prepare.sha256 --first $first.result --second $second.result
if ($LASTEXITCODE -ne 0) { throw '독립 검증 실패' }
$verification = ($verifyOutput -join "`n") | ConvertFrom-Json
if ($verification.status -ne 'completed' -or $verification.matched_models -ne 6 -or $verification.backgrounds_matched -ne 3 -or -not $verification.season_matched -or $verification.reproduction_failure_count -ne 0) { throw '검증 결과 불일치' }

& $python -X utf8 -B -m unittest discover -s tests -p 'test_*.py' -v
if ($LASTEXITCODE -ne 0) { throw '전체 회귀 실패' }
Get-FileHash -LiteralPath $prepare.plan -Algorithm SHA256
Get-FileHash -LiteralPath $first.result -Algorithm SHA256
Get-FileHash -LiteralPath $second.result -Algorithm SHA256
Get-FileHash -LiteralPath $verification.verification -Algorithm SHA256
git diff --check
if ($LASTEXITCODE -ne 0) { throw 'Git 공백 검사 실패' }
git status --short --branch
```

종료 코드 0은 정상 준비/완료, 2는 잘못된 CLI 인자, 3은 사용자 중단, 4는 파일 I/O, 5는 검증 계약 실패 또는 부분 완료다. JSON 파일 존재만으로 성공을 판단하지 않는다. 현재 계획의 코드·환경·참조가 바뀌지 않고 완료 부분을 검증한 경우에만 `run --plan <plan> --sha256 <sha256> --reuse-result <이전 result.json>`을 사용할 수 있다. 독립 재현에는 재사용하지 않는다.

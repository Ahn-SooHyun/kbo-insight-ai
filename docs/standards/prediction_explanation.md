## 1. 목적·지원 범위

### 1.1 문제 정의

예측값이 생성되었다는 사실과 그 예측이 타당하고 해석 가능하다는 사실은 다르다. 이 기능은 새 예측기를 학습하여 성능을 올리는 대신, 이미 선택·저장된 운영 모델의 실제 계산을 설명하고, 고정 최종 평가에서 예측과 실제 정답의 차이 및 신뢰도·지원 범위를 분석한다. 설명과 평가를 통해 모델의 한계를 드러내되 이미 공개한 최종 Test를 다시 최적화 자료로 사용하지 않는다.

설명은 다음 질문을 분리해서 답한다. (1) 특정 예측이 어떤 입력·학습 통계·계수·규칙을 통해 생성되었는가? (2) 선택한 모집단에서 어떤 특징 또는 계산 단계가 큰 변화를 만드는가? (3) 같은 확률을 부여한 사례에서 실제 발생률은 어떠한가? (4) 어느 사례에 큰 오차가 있거나 입력·정답·구간·규칙의 지원이 부족한가? (5) 동일 고정 자료와 코드에서 핵심 산출물을 다시 생성할 수 있는가?

### 1.2 지원 기능과 경계

| 기능              | 출력·분석                                                                     | 해석 경계                                                               |
| ----------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| M1 경기 결과·득점 | 홈·원정 기대득점, PMF와 결합 분포, 승무패 신뢰도, 무승부·득점 오차            | 기대득점은 실제 득점 확정값이 아니다.                                   |
| M2 타석 결과      | 보정 전 클래스별 선형 SHAP, 마스크·평활·보정, 혼동과 확률 신뢰도              | 클래스 로짓 기여와 최종 확률의 변화는 별개다.                           |
| M3 타자           | 이력 기반 Count 계산·일관성 투영·기록별 구간과 실패                           | 관측하지 못한 선수 활동을 실제 0으로 해석하지 않는다.                   |
| M3 투수           | 이력 기준 및 공동 잔차 트리 경로·축소·투영, 구간                              | 트리 경로 기여를 TreeSHAP으로 표기하지 않는다.                          |
| M4 경기 상황 가치 | 비종료 승리 로짓 SHAP, RE 통계 근거, 공식 종료, WPA·RV·LI의 실제 타석 쌍 계산 | 사후 종료 증거는 평가·관측 설명용이며 경기 중 입력으로 누출하지 않는다. |
| M5 다음 투구      | 저장 공동 로짓 SHAP, 공동·구종·결과 확률, 희소·미출현 지원                    | 투구 위치·궤적·새 구종의 성능 보장은 제외한다.                          |
| 시즌·포스트시즌   | 정규시즌 1위·진출·한국시리즈 우승, 유효·공동·조건부 분모, 계산 변동           | 2025년 사후 가정 시나리오다. 공식 당시 정보 기반 일반화 평가가 아니다.  |
| 예상 선발·팀·일정 | 후보·정답 식별, Top-k, 팀 기록, 일정 기대 손실                                | 후보 순위를 선발 확률이나 공식 발표로 바꾸지 않는다.                    |

운영 예측기는 6개이며 새 운영 예측기는 0개다. M3의 역할별 예측기를 각각 세고 M5는 공동 확률의 두 주변화를 독립 모델로 세지 않는다. 기존 M4의 RE·LI 통계 및 시즌 시뮬레이션도 추가 독립 주 예측기가 아니다. Python 표준 라이브러리 및 기존 모듈만 재사용한다. 별도 SHAP 라이브러리·재학습·재선정·재보정·GPU 학습·서비스 배포·LLM 결합을 추가하지 않는다. 신뢰도 진단은 보정기를 새로 적합한다는 뜻이 아니다.

### 2.3 시간 분할 및 정보 시점

| 분할            | 포함 조건(KST 날짜 기준)          | 사용 범위                                    |
| --------------- | --------------------------------- | -------------------------------------------- |
| Train           | `date < 2025-01-01`               | 선행 학습·통계·설명 기준 배경                |
| Validation/개발 | `2025-01-01 <= date < 2026-01-01` | 선행 비교·선정·보정, 2025 사후 가정 시나리오 |
| 최종 Test       | `2026-01-01 <= date < 2026-11-26` | 고정 예측 평가·사후 설명·실패 분석만         |

모델별 최초 관측연도와 적격 표본은 서로 다르다. 전체 데이터 중 비율을 맞추기 위해 무작위로 재분할하지 않는다. 같은 경기의 여러 상태·타석·투구는 독립적인 경기 수로 세지 않고 날짜·경기 식별자 계약을 유지한다. M3의 기준일은 월요일이며 해당 월요일 이전 자료만 입력한다. 7일·28일·잔여 정규시즌의 정답 완료 시점, 품질 마스크 및 실제 0과 미관측의 구분은 별도 검증한다.

선행 최종 평가의 정답 접근과 추론 입력 분리, 원천 재생성 대조 및 Test 격리 결과를 인수한다. 설명은 고정 평가가 완료된 뒤에 수행하므로 Test 정답을 열람하는 것 자체가 누수는 아니다. 그러나 그 정답을 통해 운영 계수·변수·배경·보정값·분할·모델 선택을 수정하면 최종 평가의 독립 지위가 훼손된다. 특히 M4 공식 종료 근거와 시즌 종료 자료의 사후 사실은 과거 예측 입력에 소급 적용하지 않는다.

### 2.4 품질·EDA와 검증 분모

최종 평가의 `evaluation/<model>/predictions.jsonl`, `targets.jsonl`, `metrics.json` 및 실행 명세가 입력·정답·평가의 정본이다. 실제 파일명과 경로는 `result.json`의 참조를 우선한다. `sample_id`의 일치·중복·자료 지문·시간 경계와 정답 마스크를 확인한다. 모형별 `population`은 선행 적격 모집단이며 제외 수나 비율은 원래 평가의 정의를 유지한다. 모든 표본이 모든 출력에 유효하다는 의미가 아니다.

본 작업에서 수행하는 탐색·진단의 단위는 분포·클래스별 지지도·예측 확률 구간·지원 상태·실패 사유·계산 경로다. 새로운 전체 원천 EDA, 새로운 변수 생성 실험 및 후보 모델 재선정은 수행하지 않는다. 범주 또는 기간별 지원 분모와 제외 사유가 0건인지, 관측 자체가 불가능한지 구분한다.

### 3.1 설명 입력과 기준 자료

| M4 Core 순번 | 설명 특징                                 | 실제 계산                             |

|            1 | `inning`                                  | 현재 이닝                             |

M2·M5의 배경은 `train_background`가 기존 입력 조회문을 Train으로 제한하여 순차 계산한다. DB는 읽기 전용이며 `prediction_authorizer`가 허용 입력 열만 조회하도록 제한한다. 각 행의 분할과 날짜를 검증하고 적격 입력 수를 저장 모델 학습 빈도 합계와 대조한다. M4는 Train 가중 표준화의 저장 평균 및 척도를 사용하므로 Test를 다시 표준화하지 않는다. 이 단계는 모델 학습이 아닌 고정 모델의 설명 기준 계산이다.

### 3.2 전체 중요도 모집단과 개별 설명의 구분

전체 중요도는 고정 Test의 모든 적격 `sample_id`에 대해 `SHA256(str(42) + ':' + sample_id)`를 계산하여 작은 지문 순서로 최대 2,000개를 선택한다. 동률이면 ID 오름차순이다. 모델별 모집단이 2,000개 미만이면 전량을 사용한다. 선택에는 예측 오차·정답·분류 결과를 쓰지 않는다. 선택된 표본은 동일 가중으로 집계한다. 이 결정론적 해시 순위 표본은 통계적 모집단의 완전한 대표성, 층화, 독립·동일분포 또는 신뢰구간을 보장하지 않는다.

실패·희소·미지원 대표 사례는 사유별로 전체 적격 표본을 확인하고, 사유에 정의된 비음수 점수 내림차순·ID 오름차순으로 최대 5개를 선택한다. 동점 및 동일 사례의 다중 사유를 보존한다. 여러 사유에 속한 표본은 개별 설명 파일에서 한 번만 설명한다. 전체 표본과 실패 표본의 합집합만 개별 설명 대상으로 저장한다. 실패에만 선정된 표본은 전역 중요도 집계에서 제외하며, 이미 전역 표본이었던 실패 사례는 원래 가중을 유지한다.

### 3.3 순차 처리 및 예외

M2는 `M2StreamingScore`로 혼동행렬·Log loss·Brier·신뢰도 구간을 누적하여 전체 타석 예측을 메모리에 올리지 않는다. M4·M5·M3의 고정 평가 재계산은 기존 평가기를 활용하며, 실패·설명 표본은 제한된 사유별 목록을 유지한다. M4의 타석 전·후 쌍은 고정 키 순서 및 ID 접미사의 쌍을 검증한다. 시즌 진단은 기존 검증기의 반복·팀·경기별 재검산을 인수하므로 시즌 반복 자료의 메모리 특성은 기존 구현을 따른다. 전체 프로세스의 최대 RSS·처리 시간·병렬 확장성은 별도 측정하지 않았고 O(1) 메모리 사용을 보장한다고 주장하지 않는다.

### 4.3 결과 해석의 불변 조건

- SHAP은 정의된 기준 분포에서 모델 출력의 가산 분해를 설명한다. 인과 효과·선수의 실제 컨디션·감독 의도의 추정값이 아니다. 서로 다른 출력 척도의 절대 기여도를 직접 비교하지 않는다.
- 확률은 유효 범위와 합계, 마스크의 구조적 0을 유지한다. 빈 신뢰도 구간에서 평균 예측·실제 발생률은 `null`이며 관측률 0과 구분한다. `p=0`의 Log loss 계산용 바닥값은 출력 확률을 바꾸지 않는다.
- M3는 정답 미확정·미관측·품질 제외·실제 0을 구분한다. 비율 분모가 0인 경우 비율이 정의되지 않는다. 구간이 미지원이면 폭·포함률을 임의로 0으로 만들지 않는다.
- 시즌에서 사건 미결정은 사건 실패 또는 확률 0과 다르다. 유효 반복이 0이면 그 비율은 정의되지 않는다.
- `verification_status=matched`는 해당 검산 기준에서 일치했다는 뜻이지 실제 정답을 정확히 맞혔다는 뜻이 아니다.

## 5. 모델·학습·선정

### 5.1 공통 계산 흐름

`prepare`에서 고정 자산·코드·환경·정책·Train 배경을 고정하고, `run`에서 고정 평가 자료를 전량 진단한 뒤 설명 대상 합집합을 선정하여 저장 모델로 실제 추론을 재검산한다. 모델별 설명은 해당 예측기의 구조와 정확히 대응한다. `verify`는 두 독립 실행의 핵심 산출물 지문 및 Train 배경 재계산 결과를 검사한다. 신규 학습, 하이퍼파라미터 탐색, Test 기반 Threshold·Temperature 조정 및 후보 교체는 수행하지 않는다.

### 5.2 선형 로짓에 대한 정확한 독립 개입 SHAP

출력 클래스 c의 선형 로짓을 다음과 같이 정의한다. `x_j`는 실제 인코딩 또는 표준화 특징이고 `w_cj`는 고정 저장 계수, `b_c`는 절편이다. `μ_j`는 적격 Train 배경의 특징 평균이다.

$$
z_c(x)=b_c+\sum_{j=1}^{d}w_{cj}x_j,\qquad
\phi_{0,c}=b_c+\sum_{j=1}^{d}w_{cj}\mu_j.
$$

누락 특징을 Train 배경에서 개입 방식으로 적분하는 선형 게임의 부분집합 가치 함수는 `v_c(S)=b_c+Σ_{j∈S}w_cj x_j+Σ_{j∉S}w_cj μ_j`다. 임의의 특징 j를 추가했을 때 주변 기여는 어떤 부분집합에서도 `w_cj(x_j−μ_j)`로 동일하다. 따라서 Shapley 가중치 합이 1이라는 성질에 의해 모든 조합을 열거하지 않고도 다음을 정확히 계산한다.

$$
\phi_{j,c}=w_{cj}(x_j-\mu_j),\qquad
z_c(x)=\phi_{0,c}+\sum_j\phi_{j,c}.
$$

희소 인코딩에서 비활성 특징은 `x_j=0`이므로 `−w_cj μ_j`다. `active_shap_values`, `inactive_shap_sum`, `base_values` 및 저장 계수·배경을 이용하여 로짓을 복원한다. 활성·비활성 합계를 보존하되 각 행에 전체 희소 계수를 복제하지 않는다. 이는 상관된 특징의 조건부 기대값으로 정의한 SHAP과 다르다. 입력의 상관관계 또는 원-핫 범주의 현실 제약을 개입 게임이 그대로 보존한다고 가정하지 않는다.

전체 설명의 특징별 중요도는 전역 선택 표본 수 N에 대해 `mean_i |φ_ijc|`이며 다중 출력 요약은 클래스별 중요도의 동일 가중 평균이다. 동일 가중은 클래스 발생 빈도 가중이 아니다. 중요도는 영향을 준 방향의 평균이 아니라 크기의 평균이고, 분포 이동이나 상관 특징의 인과관계를 증명하지 않는다. M4는 비종료 표본에서만 로짓 SHAP을 집계하므로 전체 선택 수와 선형 SHAP 유효 수가 다를 수 있다. 실패 표본만을 추가로 넣지 않는다. `LinearExplanation.explain/report`가 실제 계산을 담당한다.

### 5.3 M1 — 득점 분포와 동점 가중

M1의 기존 모델은 홈·원정의 장소별 득점 통계와 과거 팀 기록 기반 프로파일로 PMF를 구성한다. 득점이 r일 확률 `p_s(r)`에서 기대득점은 `Σ_r r p_s(r)`이다. 실제 `m1.pmf`의 평활 및 꼬리 처리 계약을 유지한다. 설명은 장소별 Train 기준 PMF, 실제 프로파일·지원 수, 프로파일 PMF 및 결합 후 주변 분포를 비교한다.

기준 기대득점 `m_site`에서 프로파일 기대득점 `m_profile`, 최종 기대득점 `m_final`로 이어지는 변화는 `m_final = m_site + (m_profile−m_site) + (m_final−m_profile)`이다. 이 분해는 기준 분포에 대한 실제 단계 변화이며 개별 입력의 SHAP이 아니다.

독립 홈·원정 PMF의 곱에서 동점 가중 및 비동점 가중을 적용한 결합 분포를 생각하면, 점수 쌍 (h,a)의 질량은 `p_H(h)p_A(a)w(h,a)/Z`다. 여기서 `w`는 실제 저장 동점/비동점 가중이고 `Z`는 정규화 상수다. 승·무·패는 각각 `h>a`, `h=a`, `h<a` 영역의 확률 합이다. 실제 결합 모델은 `joint`의 기준 PMF·가중치·normalizer·독립 동점 확률·공분산 및 `tail`의 꼬리 제한을 제공한다. `explain_m1`은 실제 프로파일 재계산, 기대득점의 단계 분해, 독립 및 조정 결과 확률을 보존하고 저장 운영 예측과 비교한다. 독립 결과와 조정 결과의 차이는 동점 조정 단계 변화이지 모든 입력 영향의 개별 인과 분해가 아니다.

### 5.4 M2 — 규칙 제한 다항 로지스틱 및 저장 보정

1. 실제 `features`와 저장 `base.weights`에서 각 클래스 로짓을 계산한다.
2. 비제한 Softmax `q_c=exp(z_c)/Σ_k exp(z_k)` 및 실제 허용 마스크 A의 제한 Softmax를 연결한다. A 밖의 확률은 0이다.
3. 허용 범주 내 Train 사전 분포 `π_A`와 저장 모델의 혼합 비율 λ를 이용해 `q_mix=(1−λ)q_mask+λπ_A`를 계산한다.
4. 허용 범주에서 저장 온도 T와 클래스 절편 `δ_c`로 `p_c ∝ exp(log(q_mix,c)/T+δ_c)`를 계산한다. 실제 함수의 구조적 0과 정규화 규칙을 유지한다.
5. `explain_m2`는 보정 전 로짓 SHAP, 마스킹·사전 혼합·보정의 확률 차이, 최종 운영 확률을 저장하고 `masked_probabilities`, `calibrate_vector` 및 고정 예측을 대조한다.

클래스 절편과 온도는 선행 2025년 개발에서 확정된 값이다. 로짓의 큰 양의 기여가 최종 확률을 같은 크기로 증가시키는 것은 아니다. Softmax는 여러 클래스 로짓을 함께 사용하고 마스킹 및 보정이 추가되므로, 최종 확률을 SHAP 합으로 표시하지 않는다.

### 5.5 M3 — 선수 이력 및 공동 잔차 트리

타자와 투수의 출력은 각각 고정 기록 사전의 7일·28일·잔여 기간 Count 벡터다. `player_history`는 기준 일수당 사전 평균 `r_prior`, 시즌 경과일을 이용한 장기율 `r_long`, 최근 28일 단기율 `r_short`, 결측 및 위험에 따른 기존 후퇴를 기록한다. 기본적인 혼합식은 `r=α r_short+(1−α)r_long`이며 α는 저장 후보의 `recent_weight`다. 타자는 실제 `history_balanced_50`에서 α=0.5를 사용하고, 투수는 선택 잔차 후보의 설정을 따른다. 각 기간의 일수는 `dev3.durations`의 기존 달력 기준 및 잔여 기간 가정으로 정한다. 실제 미래 시즌 종료일을 과거 입력으로 사용하지 않는다.

기간 d의 원시 예측은 `d r`이다. `m3.project`는 비음수 Count와 기간 누적 순서, 기록 간 일관성을 보존하도록 투영한다. 투영은 단순히 각 기간 독립 회귀값을 잘라내는 것이 아니라 기존 모델의 공동 출력 제약을 적용한다. 설명은 사전율 기준, 이력 변화, 투영 차이를 실제 Count 척도에서 연결한다.

투수는 단일 공동 잔차 트리(깊이 4, 축소 0.50)를 추가 사용한다. 트리 입력은 `m3.features`의 실제 값이고 경로는 `feature_value <= threshold` 여부로 결정한다. 루트 벡터 `u_0`, 경로의 각 자식 벡터 `u_k`에 대해 `u_leaf=u_0+Σ_k(u_k−u_{k−1})`이다. 실제 잎 지원을 보존한다. 출력 j의 잔차 보정은 `u_leaf,j × train_scale_j × strength × scenario_factor_period`이며 기존 이력 기준에 더한 후 최종 투영한다. `tree_path`, `explain_m3`가 실제 잎 및 최종 Count 벡터와 저장 기간별 예측·구간을 대조한다. 이 경로 차분은 TreeSHAP·전체 경로 평균·조건부 Shapley 값이 아니다. 전체 설명은 선택 표본에서 계산 단계별 평균 절대 변화 및 분기 사용 횟수를 집계한다.

### 5.6 M4 — 승리 로짓, RE 통계 및 종료 경계

승리 확률은 공격팀 관점 이진 사건이다. 비종료의 표준화 특징 `z_j=(x_j−μ_j)/s_j` 및 저장 Core 로지스틱을 이용해 `η=b+Σ_j w_j z_j`, `p_win=1/(1+exp(−η))`를 계산한다. SHAP 기준은 저장 Train 표준화 공간의 평균 0이다. M4에서 무승부는 비승리(0)이며 별도 무승부 확률이 아니다. 공식 경기 종료 증거가 일치하면 평가용 확률은 실제 승리 여부에 따라 0 또는 1, RE는 0으로 결정된다. 3아웃은 반이닝 종료지만 항상 경기 종료는 아니므로 일반 승리 추론을 유지할 수 있다.

RE는 해당 반이닝에서 남은 실제 득점 Y의 Train 조건부 평균이다. 기존 통계표 항목은 `[n, total]`이며 `RE=total/n`이다. `value.re_keys`의 순서와 `model.MIN_SUPPORT=30`을 그대로 사용한다.

| 선택 순서 | 실제 키 형태                   | 지원 조건  |
| --------: | ------------------------------ | ---------- |
|         1 | `exact:<half>\|<outs>\|<mask>` | 존재, n≥30 |
|         2 | `base_out:<outs>\|<mask>`      | 존재, n≥30 |
|         3 | `outs:<outs>`                  | 존재, n≥30 |
|         4 | `global`                       | 존재, n>0  |

이 표의 `\|`는 Markdown 표 안에서 구분 문자 자체를 표현하기 위한 이스케이프이며 실제 저장 키는 `exact:top|1|3`과 같은 문자열이다. 마스크는 주자 점유 비트 조합이다. 정상 종료 경계에서는 Train 통계를 선택하지 않고 `half_ended`에 해당하는 0을 반환한다.

`re_evidence`는 선택 키, `[n,total]`, 지원 수와 득점 합, 계산한 평균, 조회 경로의 `missing`·`insufficient_support`·`selected` 및 최대 절대 오차를 기록한다. 저장 일반 추론의 `raw_re_evidence`와 공식 종료 반영 `evaluated_re_evidence`를 각각 검산한다. 종료 상태에서 `selected_key=null`은 정상적인 결정 규칙이며 누락된 근거가 아니다.

실제 타석 쌍의 승리 확률 변화는 `WPA=p_after−p_before`, 잔여 기대득점 변화는 `ΔRE=RE_after−RE_before`, 득점 가치는 `actual_runs+ΔRE`이다. 공격팀 관점을 양 상태에서 유지한다. LI는 사전 상태에서 Train 경험 전이분포의 `E(|WPA| | state)`를 지원되는 Train 참조 평균으로 나눈 무차원 값이다. `value.plate_value`와 `value.importance`를 재사용하고 전이 지원이 부족하면 미지원 사유를 보존한다. WPA와 LI는 동일한 값이 아니며 실제 타석 결과와 미래의 행동 의도를 혼동하지 않는다. 저장 예측과 평가 종료 처리를 분리하고, SHAP·RE·WPA·LI의 서로 다른 단위를 섞지 않는다.

### 5.7 M5 — 공동 로짓과 구종·결과 주변화

공동 범주 `(t,r)`는 구종 t와 투구 결과 r의 고정 조합이다. 로짓은 실제 저장 온도 반영 계수로 계산하고, Softmax와 사전 혼합으로 공동 확률 `p(t,r)`을 얻는다. 저장 계수에 이미 온도 변환이 적용된 구조이므로 설명에서 온도를 다시 나누지 않는다. `Runtime.probabilities` 및 고정 공동 확률을 대조한다.

$$
p(t)=\sum_r p(t,r),\qquad p(r)=\sum_t p(t,r),\qquad \sum_{t,r}p(t,r)=1.
$$

`explain_m5`는 실제 인코딩·미출현 ID 후퇴·활성 횟수, 공동 로짓의 선형 SHAP, Softmax·사전 혼합 단계 및 두 주변 확률을 기록한다. 구종·결과를 서로 독립적으로 학습한 별도 모델이 아니다. 공동 최대 확률의 구종·결과가 각각 주변 분포의 최대 범주와 일치할 필요도 없다. 희소 조합과 구종·결과의 미출현은 서로 다른 집계 축으로 판단한다.

### 5.8 시즌 및 보조 분석 — 새 학습이 없는 계산의 설명

시즌 분석은 기존 정규시즌·포스트시즌·선발 및 보조 검증 결과를 연결한다. 저장된 M1 결합 분포와 시즌 규칙, 확정 경기, 잔여 일정, 동일 반복 ID의 포스트시즌 시드, 대진·라운드 전이 및 미결정 상태를 사용한 선행 계산의 실제 근거를 재집계한다. 설명에서 새로운 시즌 전망 모델을 학습하거나 시뮬레이션을 추가로 적합하지 않는다. `diagnose_season`은 고정 실행들의 지문과 기존 `season_forecast_checks` 검산을 사용한다.

예상 선발은 기준 시점 이전 선발·등판 이력으로 구성한 후보 순위이며 운영 규칙은 선행 2025년 개발 비교로 고정했다. 팀 전력은 실제 누적·최근 기록의 기술통계이고, 일정 난이도는 팀 관점 경기별 기대 손실 `p_loss+0.5 p_tie`를 유효 잔여 경기에서 평균한 값이다. 미편성·미지원·모델 예측 누락은 실제 난이도 0으로 넣지 않는다. 팀 기록·일정과 선발 후보의 시점·실제 사용 가능 여부는 선행 문서의 지원 범위를 따른다.

## 7. 평가 지표·실제 결과

### 7.1 확률 및 수치 지표

표본 i의 범주 정답 표시를 `y_ic=1(Y_i=c)`, 예측 확률을 `p_ic`라고 한다. 최종 평가와 동일한 적격 표본 n에서 다음을 계산한다. Log loss 바닥값은 `1e-15`이고 해당 로그의 수치 계산에만 사용한다. 다중 클래스 Brier는 범주 방향의 합을 표본 방향으로 평균한 값이며, 이진 M4 Brier와 정규화가 다르다.

| 지표                | 정의                                                                  | 해석                                                                                 |
| ------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Log loss            | `−(1/n) Σ_i log(max(ε,p_{i,Y_i}))`                                    | 낮을수록 좋음. 정답에 지나치게 낮은 확률을 주면 큰 손실                              |
| 다중 클래스 Brier   | `(1/n) Σ_i Σ_c (p_ic−y_ic)^2`                                         | 낮을수록 좋음. 클래스 수로 추가 나누지 않음                                          |
| 이진 Brier(M4)      | `(1/n) Σ_i (p_i−y_i)^2`                                               | 낮을수록 좋음. M4 승리=1, 비승리=0                                                   |
| Accuracy            | `정답 범주와 argmax 예측이 일치한 수/n`                               | 높을수록 좋음. 희소 클래스에서 단독 해석 금지                                        |
| Precision/Recall/F1 | 클래스별 `TP/(TP+FP)`, `TP/(TP+FN)`, `2PR/(P+R)`                      | 기존 평가기의 0 분모 처리 및 범주 사전 유지; Macro F1은 클래스별 F1의 동일 가중 평균 |
| MAE                 | `(1/n) Σ_i \|ŷ_i−y_i\|`                                               | 낮을수록 좋음. 원래 기록 단위                                                        |
| RMSE                | `sqrt((1/n) Σ_i (ŷ_i−y_i)^2)`                                         | 낮을수록 좋음. 큰 오차에 더 민감                                                     |
| Bias                | 평균 부호 오차(정확한 부호는 기존 평가 함수 계약 참조)                | 과대·과소의 방향. 절대 오차와 별개                                                   |
| 이산 CRPS           | 지원 범위 CDF와 실제 정답 계단 함수 차이 제곱 합 및 범위 밖 정답 보정 | 낮을수록 좋음. M1 분포 전체에 대한 진단                                              |

M3의 Train 정규화 Macro MAE/RMSE는 기존 Train 척도와 지원 출력 셀 정의에 따른 집계이며 서로 다른 Count 단위를 단순 합한 MAE가 아니다. M3의 기록별 비교·비율·구간 공통 분모는 기존 점수화 계약을 그대로 유지한다.

### 7.2 Reliability 및 ECE

범주 c 또는 이진 사건에 대해 확률 구간 B의 수를 `n_B`, 평균 예측을 `p̄_B`, 실제 발생 비율을 `ȳ_B`로 표시한다. `ECE = Σ_B (n_B/n)|p̄_B−ȳ_B|`이다. 빈 구간은 합에서 제외하되 결과에 빈 구간으로 남긴다. Macro Classwise ECE는 범주별 One-vs-rest ECE를 고정 사전의 범주 수로 동일 가중 평균한다. Top-label ECE는 최대 확률과 그 argmax 정답 여부를 비교하는 다른 지표다. 서로 다른 지표를 같은 척도의 수치로 대체하지 않는다.

| 대상 | 구간·모집단                                                                                                                             |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------- |
| M1   | 13개 비균등 구간, 경계 `0, .01, .02, .05, .1, .2, .3, .4, .5, .6, .7, .8, .9, 1`; 기존 결과의 각 구간에서 추가 Classwise/Macro ECE 계산 |
| M2   | 15개 클래스의 One-vs-rest, 10개 동일 폭 구간, 규칙 마스크와 실제 지원 확인                                                              |
| M4   | 이진 승리 확률, 10개 구간, 전체·pre/post·공식 종료·비종료·3아웃 비종료 등 기존 그룹                                                     |
| M5   | 공동 70·구종 10·결과 7의 각 확률축, 10개 구간, 기존 Classwise 및 Top-label 지표                                                         |

구간은 왼쪽 포함·오른쪽 제외이며 마지막 구간만 1 포함이다. 구간 `count` 또는 `games`가 0이면 `empty`, 1~29면 `sparse`, 30 이상이면 `observed`다. `observed`라는 표시는 충분한 통계적 검정력을 증명하지 않는다. M2의 Train 희소 범주는 1~29건으로 이번 진단에 고정했고, M5는 기존 1~49건 기준이다. Train 0건은 미출현이다. 해당 기준은 합격 성능 임계값, 보정 목표 또는 새로운 모델 선정 규칙이 아니다.

신뢰도는 확률의 경험적 정렬 여부이며 정확도·구별력과 다르다. ECE가 낮아도 모든 표본에 비슷한 사전 확률을 주면 개별 사례의 구별력이 낮을 수 있다. 반대로 더 나은 Log loss가 반드시 더 나은 ECE를 의미하지 않는다. 구간별 평균의 비교는 특정 사건의 실제 확률을 보증하지 않는다.

### 7.3 M3 예측 구간·정답 및 비율 분모

운영 모델의 목표 구간 포함 수준은 `INTERVAL_LEVEL=0.90`이다. 관측된 유효 실제값과 유효 하한 L·상한 U가 모두 있는 n_int개에서 `coverage=Σ 1(L_i≤y_i≤U_i)/n_int`, `mean_width=Σ(U_i−L_i)/n_int`를 계산한다. 구간을 제공하지 못한 건수, 유효 정답 수, 양 모델의 공통 구간 제공 수는 별도 분모다. 구간 포함률이 높더라도 폭이 과도하게 크면 정보량이 적을 수 있으므로 같이 해석한다. 구간별·기록별 측정이며 선수의 모든 기록이 동시에 구간에 포함될 확률이나 모수 신뢰구간을 뜻하지 않는다.

7일·28일·잔여 정규시즌은 월요일 기준일과 정답 준비일, 관측 배타 경계 및 종료 증거에 따라 유효성이 다르다. 정답 마스크는 실제 미관측이나 위험 상태를 제외하되 실제로 관측된 0 Count는 유효하게 남긴다. `hit_rate`, `strikeout_rate`는 기존 역할·노출량 분모를 따르며 분모 0, 정답 미관측, 예측 분모 0, 공통 비교 불가를 구분한다. 미래 정답 미확정은 모델 실패나 0으로 치환하지 않는다. 관측이 유효한 표본에서만 기록별 오차·구간 미포함을 계산한다.

### 7.4 고정 최종 평가의 대표 실제 수치

아래 수치는 선행 [고정 최종 평가](https://github.com/Ahn-SooHyun/kbo-insight-ai/issues/34)의 Work 최종 기술 검증·인계 보고서(2026-11-28 KST)에 보고된 실제 2026년 최종 Test 결과를 인수한 것이다. 이번 설명 작업의 사용자 로그는 해당 지표 재계산 및 독립 재현의 성공을 확인하지만 개별 `summary.json` 전문을 직접 대조하지 않았으므로 아래 값을 새 설명 실행에서 독립 추출한 수치로 표시하지 않는다. 실제 지표의 전량·정밀도·표본별 근거는 고정 평가 `evaluation/<model>/metrics.json` 및 새 실행 `<model>-summary.json`을 사용한다. 낮을수록 좋은 지표의 감소, 높을수록 좋은 F1의 증가를 개선으로 표시한다.

### 7.6 시즌 사건·유효 반복·불확실성

정규시즌 1위와 한국시리즈 우승은 각각 별도 사건이다. 전체 N회에서 특정 팀의 사건이 확정된 유효 반복 수 V, 참 사건 수 H, 미결정 U=N−V이면, 유효 반복 조건부 확률은 `H/V`(V>0), 미결정 비율은 `U/N`이다. 모든 반복을 분모로 삼고 미결정의 결과를 모른다는 조건의 논리적 사건 확률 범위는 `[H/N,(H+U)/N]`이다. 이 범위는 통계 신뢰구간이 아니다. 모든 팀의 사건이 함께 확정된 공동 반복은 팀별 분모와 다르며, 대진 조건부 승리 확률은 대진 형성 및 시리즈 결과의 유효 반복만 사용한다. 팀별 조건부 확률 합이 1이 되지 않는다고 즉시 계산 오류로 판단하지 않는다.

2025-09-01 KST 자정, Seed 42/1,000회가 대표 시즌 개발 시나리오다. 동일 조건 재실행, Seed 42/2,000회, Seed 43/1,000회 및 연결된 포스트시즌을 선행 종합 검증에서 비교했다. 2025-11-01 종료 재생은 Seed 42/1,000회 및 동일 조건 재현이다. 이 비교는 난수에 의한 계산 변동의 진단이며 실제 경기 불확실성이나 표준오차·Confidence Interval의 추정이 아니다. 2025년 일정·선수 기록의 당시 공개 시각을 검증하지 않았으므로 실제 운영 당시 정보 기반 정식 Backtesting 또는 2026 시즌 전망 최종 Test로 부르지 않는다.

2025년 한국시리즈 5차전은 선행 승인 검증에서 원천 홈·원정 및 점수 표기와 공식 결과의 충돌이 확인되었다. 종료 재생의 한국시리즈 우승 결과 1,000회 전부는 이 충돌 때문에 미결정이다. `archive_replay_conflict` 및 기존 보존된 원천 증거를 유지한다. 유효 우승 분모가 0인 경우 우승 확률은 `null`이며 공식 실제 우승팀이 없었다거나 모든 팀의 실제 우승 확률이 0이라는 뜻이 아니다. 원본 정정·재수집·새 규칙 승인 없이 충돌을 임의 수정하지 않는다.

선행 시즌 검증의 사용자·하위 보고에서 작업 성공 15건, 종합 독립 검산 35건, 안정성 경고 0건, 검증 실패 0건이 기록되었다. 이번 설명은 해당 결과·실행 ID를 인수하여 재집계한다. 안정성 경고가 없었다는 사실은 사용한 경고 조건 및 반복 범위 안의 계산 결과이지 경기 모델의 정확성을 인증하는 것이 아니다.

### 8.4 재현·무결성·자원 계약

- 선행 명세·결과·자료·모델 및 연결 파일 지문을 확인하며, 같은 파일에 서로 다른 해시가 요구되면 실패한다. M3의 역사적 표현 차이는 기존 검증 계약을 인수한다. 현재 소스 인벤토리와 선행 검증 당시 소스 인벤토리는 다른 책임을 갖는다.
- `compare`의 수치 허용오차는 절대 1e-9 및 상대 1e-9(실제 `math.isclose` 기준)다. 문자열·불리언·결측·키·정수끼리의 비교는 정확하며, JSON 배열과 Python 튜플의 표현 차이는 허용한다. 유한하지 않은 수를 성공 처리하지 않는다. 상대 허용오차가 적용될 때 최대 절대오차가 항상 1e-9 이하라고 해석하지 않는다.
- 출력은 신규 경로에 배타적으로 생성한다. 실패·부분 산출물을 삭제 또는 덮어쓰지 않는다. `--reuse-result`는 동일 계획의 검증된 성공 결과만 재사용하며 독립 재현 검증에서 같은 산출물 경로를 두 실행으로 인정하지 않는다.
- `load_plan`은 현재 환경·정책·코드 인벤토리 및 입력 지문을 다시 비교한다. `final.code_inventory`에는 `docs/standards/*.md`, `docs/planning/development_workflow.md`와 소스·테스트·설정이 포함된다. 따라서 문서-only 개정이라도 과거 설명 명세의 코드/문서 지문과 달라질 수 있다. 과거 결과를 덮어쓰거나 해시 검사를 우회하지 않고 새 `prepare`와 새 설명 실행·재현을 수행한다(10절).
- Python 3.12.15는 착수 시 사용자 실행 확인값이다. CPU 기반 표준 라이브러리 경로를 사용하며 새 의존성·GPU 실행을 추가하지 않았다. 현재 환경 정보는 명세에 기록한다. 사용자가 전달한 테스트 시간은 해당 사용자 환경에서의 측정값이고, 전체 실자료 수행 시간·메모리 최대값의 정량 비교는 미확인이다.

## 10. 실행 명령

### 10.1 실행 전 조건

Windows PowerShell, 저장소 루트 `D:/Programming/kbo-insight-ai`, 착수 시 확인된 Python 3.12.15 가상환경을 기준으로 한다. 동일 고정 자산이 설정 경로에 존재해야 한다. `--project-root`가 필요한 경우 CLI 전역 인자로 서브커맨드 앞에 지정한다. 기존 고정 평가 및 시즌 검증 명세·결과·모델·DB를 이동·수정·덮어쓰지 않는다. 이 설명 기능은 운영 모델을 새로 학습하지 않는다.

### 10.2 독립 설명 실행과 전체 검증

아래 명령은 사용자가 실제 파일을 반영한 뒤 실행하는 안내다. 기존 성공 실행과 무관한 새 명세와 두 독립 실행을 생성한다. 과거 결과를 재사용한 두 실행은 독립 재현의 증거가 아니다. 모든 단계의 종료 코드 및 출력 상태를 함께 확인한다.

```powershell
Set-Location "D:/Programming/kbo-insight-ai"
$python = "D:/Programming/kbo-insight-ai/.venv/Scripts/python.exe"

& {
    git branch --show-current
    git rev-parse HEAD
    git status --short --branch
    & $python --version
    & $python -m unittest discover -s tests/explainability -p "test_*.py" -v
    if ($LASTEXITCODE -ne 0) { throw "설명 전용 테스트 실패" }

    $prepareOutput = & $python -m src.explainability prepare
    if ($LASTEXITCODE -ne 0) { throw "설명 명세 준비 실패" }
    $prepare = $prepareOutput | ConvertFrom-Json
    if ($prepare.status -ne "prepared") { throw "명세 상태 오류" }
    $prepare | ConvertTo-Json -Depth 20

    $firstOutput = & $python -m src.explainability run --plan $prepare.plan --sha256 $prepare.sha256
    $firstExit = $LASTEXITCODE
    $first = $firstOutput | ConvertFrom-Json
    $first | ConvertTo-Json -Depth 20
    if ($firstExit -ne 0 -or $first.status -ne "completed" -or $first.completed_models -ne 6 -or $first.season_status -ne "completed") { throw "첫 번째 실자료 실행 실패" }

    $secondOutput = & $python -m src.explainability run --plan $prepare.plan --sha256 $prepare.sha256
    $secondExit = $LASTEXITCODE
    $second = $secondOutput | ConvertFrom-Json
    $second | ConvertTo-Json -Depth 20
    if ($secondExit -ne 0 -or $second.status -ne "completed" -or $second.completed_models -ne 6 -or $second.season_status -ne "completed") { throw "두 번째 독립 실자료 실행 실패" }

    $verifyOutput = & $python -m src.explainability verify --plan $prepare.plan --sha256 $prepare.sha256 --first $first.result --second $second.result
    $verifyExit = $LASTEXITCODE
    $verification = $verifyOutput | ConvertFrom-Json
    $verification | ConvertTo-Json -Depth 20
    if ($verifyExit -ne 0 -or $verification.status -ne "completed" -or $verification.matched_models -ne 6 -or $verification.backgrounds_matched -ne 3 -or -not $verification.season_matched -or $verification.reproduction_failure_count -ne 0) { throw "독립 재현 검증 실패" }

    & $python -m unittest discover -s tests -p "test_*.py" -v
    if ($LASTEXITCODE -ne 0) { throw "전체 회귀 테스트 실패" }
    Get-FileHash -LiteralPath $prepare.plan -Algorithm SHA256
    Get-FileHash -LiteralPath $first.result -Algorithm SHA256
    Get-FileHash -LiteralPath $second.result -Algorithm SHA256
    Get-FileHash -LiteralPath $verification.verification -Algorithm SHA256
    git diff --check
    if ($LASTEXITCODE -ne 0) { throw "Git 공백 검사 실패" }
    git status --short --branch
}
```

### 10.3 부분 실패·재사용 및 변경 처리

준비 실패 시 명세를 임의 작성하지 않는다. 실행이 `failed_or_partial`이면 `result.json`과 로그에서 실패 모델·시즌·무결성 원인을 확인한다. 같은 명세의 코드·환경·입력에 변경이 없고 무결성 오류 없는 완료 부분이 있다면 `run --plan <plan> --sha256 <sha256> --reuse-result <이전 result.json>`으로 성공 산출물을 인수할 수 있다. 경로 또는 지문이 달라지면 중단한다. 실패 결과를 삭제하여 성공처럼 표시하지 않는다. 독립 재현을 최종 확인하려면 재사용 없이 별개 실행 경로를 생성한다.

문서만 변경했더라도 현재 명세가 문서 파일의 지문을 포함하므로 개정 반영 이후 이전 `manifest.json`을 사용한 검증이 거부될 수 있다. 기존 기술 검증 결과를 역사적 증거로 보존하고 10.2절로 새 명세와 새 실행을 생성하여 변경 후 인벤토리를 연결한다. 이 과정에서 M1~M5 재학습, 기존 최종 평가의 모델 재선정, 시즌 전망 재적합을 수행하지 않는다.

종료 코드는 `0` 정상 준비/완료, `3` 사용자 중단, `4` 파일 입출력 오류, `5` 실행·검증 계약 실패 또는 부분 완료이며 잘못된 CLI 인자는 `argparse`의 종료 코드 2가 될 수 있다. 성공 여부는 단순 JSON 파일 존재가 아니라 명세·결과의 상태, 종료 코드, 지문 및 재현 검증 결과를 함께 확인한다.
